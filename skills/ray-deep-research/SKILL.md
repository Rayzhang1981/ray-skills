# ray-deep-research — 深度研究 · 溯源对比

对一个对象（产品/公司/技术概念/人物/行业）做深度研究，产出**叙事驱动、可读性强**的深度研究报告。

## 核心方法论：溯源对比法

> 两条轴交叉出判断——纵向溯源（时间轴），横向对比（同期切面），交汇出判断。

```
纵向（时间轴）：它是怎么一步步走到今天的？ → 历史与因果
横向（同期切面）：它今天站在赛道的什么位置？ → 位置与差异
        ↓ 交汇 ↓
综合判断：它当前所处位置 + 未来走向
```

**先判断研究对象类型**（决定纵向/横向的侧重）：

| 类型 | 纵向侧重 | 横向侧重 | 示例 |
|------|---------|---------|------|
| **产品/工具** | 版本迭代、功能演进 | 竞品功能对比 | Cursor、Claude Code |
| **公司/组织** | 融资历程、战略转型 | 商业模式对比 | Anthropic、字节 |
| **技术概念** | 概念提出、演化脉络 | 同类概念辨析 | MCP、RAG、Agent |
| **人物** | 职业轨迹、关键节点 | 同期人物对比 | 关键人物 |
| **行业** | 产业链演进、政策节点 | 竞争格局、博弈关系 | 预制菜、新能源 |

## 六阶段流程

### Phase 0：研究对象确认

- 明确「研究对象」= 具体是什么（一句话定义）
- 判断类型（上表）
- 确认研究深度（快速认知框架 / 深度研究报告 / 深入 · 穷尽——见下方「研究深度分级」）
- **计划先行（v1.3 新增）**：正式报告动工前，给 3 行研究计划（研究对象 / 覆盖范围 / 深度档位）请用户确认，避免方向跑偏后返工

### Phase 1：纵向分析（时间轴，报告主体）

**来源五维评估（v1.3 新增）**：每个关键来源按下表评估，低可信来源标记并降权：

| 维度 | 问什么 |
|------|--------|
| 权威性 | 谁写的？什么资质？（机构官网 > 个人博客 > 匿名帖） |
| 时效性 | 何时发布？现在仍有效吗？（数据类信息尤其看年份） |
| 证据性 | 论断有数据/引用支撑，还是只有观点？ |
| 立场性 | 有无议程或利益冲突？（厂商宣传、券商研报注意立场） |
| 佐证性 | 其他来源印证吗？单方来源标记待核实 |

沿时间轴完整还原发展全貌，**叙事驱动**（不是年表流水账）。详见 `references/vertical-analysis.md`：

1. **起源追溯**：诞生背景、基于什么技术/理念/需求、核心推动者、当时环境
2. **诞生节点**：首次发布/成立/提出时间、最初形态和定位
3. **演进历程**：所有关键节点（版本更新/融资/转型/里程碑/争议），按时间串成故事
4. **决策逻辑**：每个关键节点"为什么选 A 不选 B"，还原约束条件

### Phase 2：横向分析（同期对比）

**停止条件（v1.3 新增）**：研究是迭代的——初始发现引出新问题、顺着线索追、补缺口，但**三条件任一即停**：
- ① 回答已清晰；② 边际收益递减（新增源不再改变结论）；③ 时间/预算耗尽
- 停下时**记录停止决定及原因**（如"搜索 12 源后结论稳定，停止"），不无限深挖

以当前时间点为切面，对比同赛道竞品。详见 `references/horizontal-analysis.md`：

**先判断竞品情况**（三种场景）：
- **A 无直接竞品**：分析为什么没竞品（品类太新/壁垒太高/市场太小）+ 潜在竞争者 + 替代方案
- **B 少量竞品（1-2 个）**：逐一深入对比
- **C 竞品充分（3+ 个）**：选 3-5 个代表深入对比，其余简述

**对比维度**：技术路线 / 产品形态 / 目标用户 / 核心优劣势 / 用户口碑 / 生态位 / 趋势判断。

**融合七步法的补充**（行业类对象必做）：
- **博弈关系**：谁和谁在争什么？经典博弈（规模 vs 差异化等）
- **生命周期判断**：成长期/成熟期？同一个数字在不同周期的含义完全不同

### Phase 3：关键词速览（行话表，可选但强烈推荐）

提炼 10-20 个核心术语，一句话解释 + 优先级（🔴必懂 / 🟡该懂 / 🟢了解）。**用类比，别背定义**：

```
❌ "中央厨房是采用标准化作业和工业化设备，对食材集中采购统一加工配送的场所"
✅ "中央厨房就是餐饮业的富士康——餐厅不再自己洗菜切菜，大工厂统一做好送到门店加热上桌"
```

### Phase 4：横纵交汇总结（报告精华）

纵向脉络 + 横向格局 → 综合判断。**不是前文缩写**，给新的综合性判断：当前所处位置、未来走向、机会与风险。

**风险分级**（v1.2 新增）：机会与风险不能混着列，按概率×影响分级：

| 级别 | 判定 | 应对 |
|------|------|------|
| 🔴 红 | 高概率 + 高影响 | 必须正视，影响核心判断 |
| 🟠 橙 | 中等概率/影响 | 需关注，纳入 caveat |
| 🟡 黄 | 低概率或可控 | 提示即可，不展开 |

### Phase 5：费曼检验（用输出倒逼输入）

用自己的话写 200 字概述研究对象，挑出讲不清的地方 = 没真懂的地方。详见 `references/seven-steps.md`。

### Phase 6：假设 + 行动路径（可选）

- **提出假设**（基于已看到的，带置信度）：🔴高/🟡中/🟢低
- **行动路径**（分目标）：交简报 / 能交流 / 真上手，各自的时间投入和产出

## 研究深度分级（v1.3 新增）

**动工前先确认深度档位**（对应 Phase 0 的研究深度确认）；研究过程中发现档位不符可上调/下调：

| 档位 | 投入 | 来源数量 | 何时用 |
|------|------|---------|--------|
| 快速 | 5-10 分钟 | 3-5 个 | 简单事实型问题（"XX 是什么时候成立的"） |
| 标准 | 30-60 分钟 | 8-15 个 | 大多数研究请求 |
| 深入 | 2-4 小时 | 20-30 个 | 重要决策、深度报告 |
| 穷尽 | 数天 | 50+ 个 | 高利害、关键决策（罕见） |

## 写作风格（叙事驱动，不是罗列驱动）

1. **可读性优先**：像深度报道/非虚构特稿，有节奏感、画面感，让读者被内容吸引
2. **叙事有弧线**：有起承转合——"为什么某时间点突然爆发"要有铺垫和转折，不写"2023年1月发布A，3月发布B"流水账
3. **观点建立在事实上**：先摆事实再给判断；推测明确标注"推测/未经证实"
4. **用人话写**：避免"赋能/抓手/打造闭环"咨询腔，用具体细节代替概括
5. **对比有温度**：不写参数对照表文字版，讲清每个竞品"活成了什么样"、用户选它的真实理由
6. **尽可能量化**（v1.1 新增）：把"被广泛采用"这类模糊论断替换为"被 38% 的受访团队使用"的具体数字——让报告可执行、可验证
7. **结论先行**（v1.2 新增）：每个章节开头先给一句结论，再展开论证——读者看标题和首句就知道这段讲什么，不用读完整段才 get 到点

## 反编造铁律（沿用 ray 系列）

1. **信息标注来源**：所有关键数据/事件标注来源和时间，确保可追溯
2. **无法确认 → 明确标注推测**：不确定的数字不硬写，标"待核实/推测"
3. **不编造数据**：市场规模、增长率、融资额等必须有据可查，宁缺毋滥
4. **区分事实与判断**：事实（发生了什么）和判断（意味着什么）分开写
5. **交叉核对**（v1.1 新增）：关键论断至少 2-3 个来源交叉验证；只出现在单一来源、或与多数证据冲突的论断，显式标记
6. **显式呈现分歧**（v1.1 新增）：当高权威来源互相矛盾时，并列呈现双方 + 各自方法论 + 证据，标记"有争议"，**不静默选一方**——让读者自行判断
7. **引用规范**（v1.3 新增）：报告引用编号 [1][2]… 文末附来源列表（URL + 访问日期）；**不伪造来源或引用——每个 URL 必须真实来自搜索结果**

## 失败模式（研究过程的 fallback）

| 如果… | 兜底动作 |
|---------|---------|
| 搜索不到足够信息 | 明确标注"信息不足"，只写已确认的部分，不硬凑篇幅 |
| 信息互相矛盾 | 并列呈现矛盾 + 标注"待核实"，不武断选一方 |
| 研究对象太新（无历史）| 纵向分析改"现状 + 背景"，不强编不存在的演进史 |
| 竞品信息极少 | 降级为场景 A（无竞品分析），改分析替代方案 |
| 用户只要快速框架 | 切轻量模式（1/3 篇幅），优先关键词速览 + 横纵交汇 |

## 反例黑名单（❌ 不要做）

❌ 编造数据（市场规模/融资额无据可查就硬写）
❌ 把推测当事实（推测不标注）
❌ 罗列年表流水账（"2023年1月发布A，3月发布B"）
❌ 咨询腔套话（"赋能/抓手/打造闭环"）
❌ 参数对照表文字版（对比没有温度）
❌ 背定义式解释（不用类比，写学术定义）

## 篇幅参考

| 部分 | 篇幅 | 说明 |
|------|------|------|
| 纵向分析 | 6000-15000 字 | 主体，历史越长越靠上限 |
| 横向分析 | 3000-10000 字 | 竞品越多越长 |
| 横纵交汇 | 1500-3000 字 | 精华，给新判断 |
| 全文 | 10000-30000 字 | 不怕长，牺牲信息密度才是错 |

**轻量模式**：用户只要"快速认知框架"时，压缩到 1/3 篇幅（纵向 2000 字 + 横向 1000 字 + 交汇 500 字），优先保留关键词速览 + 横纵交汇。

## 实战经验

- 2026-08-30｜[LRN-20260830-001]｜场景：研究对象是家人健康等长周期事务，报告交付后用户持续补充信息（用药史/复查结果/血检）｜经验/教训：①报告采用**「活文档」模式**——用 Edit 增量更新对应章节（治疗档案表/单次报告解读节/行动清单），不重写全文；②医疗报告解读纪律：**「报告未提及 X」≠「X 未做」**（截图可能只是报告的部分页面），未提及项写「需向医生确认」，不写「疑似漏项」——后者带负面判断色彩，会制造家属焦虑（本次推断即被用户纠正：MRI/骨扫描实际已做且阴性）；③行动清单用「已确认✅/待确认☐」状态标记随信息演进，老问题确认后改写为新跟进问题而非删除｜死路：每次用户补充信息就重写全文（丢结构记忆、费 token）；从截图不全推断检查缺失｜来源：母亲肺腺癌深度研究（4 轮增量更新实测）｜计数：1｜状态：resolved
