# 纵向分析详细框架（时间轴）

> Phase 1 纵向分析时读本文件。目标是叙事驱动的完整发展史。

## 四个层次

### 1. 起源追溯

- 诞生背景是什么？解决了什么问题？
- 基于什么技术/理念/需求而来？
- 创始团队/核心推动者是谁？他们之前做什么？
- 当时的行业环境、技术条件、竞争格局？

### 2. 诞生节点

- 明确的首次发布/成立/提出时间
- 最初的形态和定位
- 与最初设想的差异（如果有）

### 3. 演进历程（主体）

按时间顺序梳理所有关键节点，**用故事串起来，不写年表**：

| 节点类型 | 关注什么 |
|---------|---------|
| 重大版本更新 | 解决了什么痛点、改变了什么 |
| 融资/收购事件 | 资本为什么看好、估值逻辑 |
| 团队变动 | 核心人物进出带来什么影响 |
| 战略转型 | 为什么掉头、放弃了什么 |
| 技术架构变化 | 技术债积累、重构契机 |
| 用户规模里程碑 | 什么引爆了增长 |
| 公关危机/争议 | 暴露了什么深层问题 |

### 4. 决策逻辑（最关键，区分深浅）

每个关键节点追问：**为什么选 A 不选 B？当时的约束条件是什么？**

- 这是"浅研究"和"深研究"的分水岭
- 浅研究只列"发生了什么"，深研究还原"为什么这么选"
- 把决策放回当时的环境——今天看是败笔的选择，当年可能是唯一合理的选择

## 叙事要求

1. **有故事弧线**：起承转合，一个产品"为什么某时间点突然爆发"要有铺垫和转折
2. **因果关系清晰**：让读者感受到"因为 X，所以 Y"
3. **多元丰富**：把相关的人物、事件、背景信息都拽进来
4. **不要流水账**：❌ "2023年1月发布A，3月发布B" ✅ 讲清每次发布的背景、动机、影响

## 信息标注

- 关键事件标来源（公司公告/新闻/研报/采访）
- 无法确认的时间线标"推测/待核实"
- 决策动机是推断的，明确标"推测"
