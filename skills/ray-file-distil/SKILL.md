# ray-file-distil — 资料蒸馏· 知识萃取

把成型知识（书/长文档/报告）蒸馏成一个**可用的 skill**。核心不是摘要，是抽出**认知骨架**——去掉血肉（案例/故事/修辞），留下可运行的结构。

> **定位分工**：本 skill 是**蒸馏器**（把已有知识提炼成 skill）；`ray-skill-generator` 是**生成器**（从零创建 skill）。generator 造，distil 炼——两者互补，本 skill 面向"手里已有一份成型资料"的场景。

> **关键区分**：捕捉的是 HOW the material thinks（怎么想），不是 WHAT it says（说了什么）。

## 输入确认（开始前必做）

收到资料后，先确认 4 件事：

| 确认项 | 说明 |
|--------|------|
| **资料类型** | 书 / 长文档 / 报告 / 其他 |
| **格式** | PDF / TXT / EPUB / MOBI / DOCX / MD |
| **蒸馏目标** | 方法论（步骤/流程）？思维方式（心智模型）？综合？ |
| **单一 or 多个** | 单一主题 → 1 个 skill；文集/多主题 → 拆多个 |

**多份材料融合（多 PDF/多文档场景必做）**：输入是多份材料（如 3 份 RCA 手册、2 本书）时，**主从关系不要自行决定**——列出各材料的核心贡献（A=全流程方法论、B=工具集、C=分类词典），向用户提 2-3 个融合方案（A 为主+B/C 补充 / 平等融合 / 分阶段）让其拍板。主从选错 = 整个 skill 的认知骨架跑偏，这个决策必须留给用户（2026-08-15 RCA 蒸馏实战：CCPS+ABS+Root Cause Map 三份 1106 页，融合方案由用户拍板）。

> **主从判断不能只看篇幅**（2026-09-01 批7 实证）：批7 四本书里"枝干"26 号 59 万字符 > "主干"22 号 42 万字符——但 22 号仍是主干（方法总纲+31 工具章谱系+检查表），26 号只是机理与定量补充。判断主从看**方法论覆盖面**（哪本定义整个思考框架）而非字符量；数据/理论厚书可能是枝叶，薄而全的工具书可能是主干。融合方案陈述时**不要用字符量暗示主从**，用"谁给框架、谁补细节"。

> **数据书/数值表类资料的蒸馏定位**（2026-09-01 批8 实证）：38 号（数据收集分析）与 55 号（失效率数据表）是典型"数据书"——方法论占比低，但**概念模型必须提取**：失效模式分类（主动/被动+严重度三档）、数据结构（四类数据）、Taxonomy 逻辑、失效率定义（失效数/暴露量）、删失/共因/Weibull 概念。蒸馏数据书 = 蒸馏"**怎么用数据**"的判断框架（数据怎么分类/怎么确认匹配/怎么处理删失/怎么转换工厂数据），**不是蒸馏数值表**——数值表会过时（55 号 1989 版），判断框架永不过时。产出 skill 的边界段要显式声明"不输出数值，数值查原书"。

> **"拆两"方案：主题跨度大时拆 skill 优于硬融**（2026-09-01 批9 实证）：批9 五本书（静电 58/61 + 自动化 53 + 阻火 56 + 泄放 24）主题跨度大，用户拍板**拆两个 skill**（静电 + 自动化/阻火/泄放）而非硬融一个。判断拆分的标准：①书群内主题是否形成内聚链条（58+61 静电是完整链，53+56+24 自动化-阻火-泄放是另一条链）②融合后模型数是否超 7（超了该拆）③拆分后每个 skill 的触发场景是否清晰独立。**融合方案陈述时要给"拆 N 个"选项**（不是只有"融 1 个"），让用户拍板。

**格式处理链路**（中文资料专项，详见 `references/format-handling.md`）：文字版直接读 / 扫描版 OCR / 编码检测转 UTF-8 / docx 无样式回退重建目录。

## 六阶段流程

### 阶段 0：整料理解

1. 读取资料全文（大文件分层精读：目录层→摘要层→精读层；>50k token 用 REPL 式探针 grep/sed 按需切片，见 `references/format-handling.md`）
2. 产出结构化概览：核心问题（资料试图回答什么）/ 核心答案（主要论点 200 字内）/ 目标读者
3. **展示概览给用户确认**："骨架我理解对了吗？" 确认后再进入下一阶段

### 阶段 1：核心模型提取（最关键，决定质量上限）

**五步法**（详见 `references/extraction-method.md`）：

1. **扫自命名框架**：Grep 搜"模型|法则|循环|公式|原则|铁律|维度|步骤|方法"等信号词，列出候选
2. **锁定精确定义**：每个候选回原文定位定义，**不凭印象写**；找不到标"待核实"
3. **梳理模型关系**：层级（A 含 B）/ 流程（A→B→C）/ 支撑（A 是 B 的基础），画文字版关系图
4. **从案例反推隐含模型**：作者反复用同一种方法但未命名 → 抽象成模型，**标"延伸解读，非原书命名"**
5. **模型验证 3 问**：原书有没有明说？边界条件是什么？输入→输出是什么？

**三重验证**（每个候选模型过一遍，不过则淘汰）：

- **V1 跨域复现**：资料中至少 2 个独立段落有佐证
- **V2 生成力**：能用它回答资料里没明说的新问题
- **V3 排他性**：不是任何聪明人都会说的常识

### 阶段 2：构建 skill

用 RIA++ 六段（详见 `references/templates.md`）：

| 段 | 含义 | 要求 |
|----|------|------|
| **R** Reading | 原文引用 | ≤150 字/段，标出处 |
| **I** Interpretation | 用自己的话重写方法论骨架 | 避免照搬原书 |
| **A1** Past Application | 资料中作者用过的案例 | 佐证 |
| **A2** Future Trigger | 用户什么情境会需要 → `description` 触发词 | 明确 trigger |
| **E** Execution | 1-2-3 可执行步骤 | 可操作 |
| **B** Boundary | 什么时候不适用 / 作者盲点 | 诚实边界 |

### 阶段 3：选模板生成

按资料性质选模板（详见 `references/templates.md`）：

| 模板 | 适合 | 例子 |
|------|------|------|
| **A 方法论型** | 步骤/流程清晰可操作 | 深度工作、GTD |
| **B 思维方式型** | 心智模型/认知类 | 第一性原理、系统思考 |
| **C 综合型** | 既有步骤又有认知 | 多数内容丰富的书 |
| **D 语录金句型** | 金句/原则集 | 穷查理宝典、纳瓦尔宝典 |
| **E 战略心法型** | 道重于术 | 孙子兵法、道德经 |

**原则**：能保留原书措辞（金句/原文）就保留，不强行翻译成流水线步骤——那会失真。分不准时默认 C 综合型。

### 阶段 4：质量验证

按 `references/quality-checklist.md` 逐项核对：

- **完整性测试**：选 3 个资料中明确讨论过的问题，用新 skill 分析，结果应一致
- **迁移测试**：选 1 个资料未讨论但在应用范围内的问题，能推导出合理分析
- **真实案例测试（抽象测试替代不了）**：完整性/迁移测试都是抽象层面，**发现不了"知道但做不到"的执行落差**——主动向用户提议拿一个真实案例跑一遍。2026-08-15 RCA 蒸馏实战：抽象测试全过，但用吸尘器案例实跑才发现"正向陈述"要求没落地（写成了缺席表述）——只有实操能暴露这类落差。**案例结论与 skill 标准矩阵/模型不一致时，标注差异并核实来源**（可能是案例用了不同标准，也可能是 skill 模型有误）——不静默接受任一方（2026-08-31 701 实证：报告"严重度3+可能性1→I级" vs Stoessel 标准矩阵 II 级，差异来自跨标准查表）。**案例选择要匹配 skill 核心能力域**（2026-09-01 批7 实证）：人因 skill 选 BP Texas City（人因贡献显著：疲劳/误读/报警忽视/程序缺陷），不用工艺参数类案例（701 氧化釜）——案例里该 skill 的模型必须"有得可验"；选错案例会测不出模型真实运行能力。可用同一案例跑多个 skill（分层验证），但案例自身要突出被测 skill 的核心域。
>
> **同一案例跨 skill 分层验证（2026-09-01 批10 实证）**：同一案例（Bhopal）用不同 skill 视角跑，**产出完全不同的补丁**——批8 设备视角补丁（SCE 状态/保护层可用性/外部物质进入）vs 批10 应急视角补丁（应急资源可用性/缓解组合失效/选址权重），互不重叠且各有价值。这说明：①分层验证不是"重复跑一遍"，每个视角都暴露该 skill 独有的执行落差 ②复用案例时**说明视角差异**（验证报告要标注"批X 用 Y 视角"）③若分层验证发现补丁高度重叠，说明两个 skill 边界没分清楚（该合并或重划）——**补丁重叠度是 skill 边界健康的反向指标**。

> **非正版/跨领域书处理（2026-09-01 批14 实证）**：书库里可能混入**非正版/非本领域**的书籍——批14 的 65 号"dust control handbook"是 Noyes 出版社（非 CCPS 正版，工业卫生视角粉尘）。处理：①阶段 0 整料时**识别书目来源**（出版社/作者/系列——CCPS 正版有统一编号）②非正版/跨领域书**降权重**（作为枝节并入，不当主干）③产出 skill 边界段**注明来源**（"65 号非 CCPS 正版，工业卫生视角"）④判断"领域是否匹配"——65 号是职业卫生（工人健康），与粉尘防爆（爆炸防护）是不同维度，不要混入 dust-relief。
- **诱饵测试（边界验证）**：设计 3-5 个"不该调用"的场景（"这不是这个 skill 的活"），确认 description 触发词和 Boundary 段**不会误触发**。正向测试（完整性/迁移/真实案例）证明"能用"，诱饵测试证明"不滥用"——只测能用、不测边界，等于没验证"何时不用"这条承诺
- **反编造**：所有关键术语回查原文；隐含模型标"延伸解读"；案例无法确认出处就删

**通过标准（v1.4.0 新增，量化判定，不靠感觉）**：

| 检查项 | 通过标准 | 不通过信号 |
|--------|---------|-----------|
| 核心模型数量 | 3-7 个，每个有原文佐证 | <3 信息不足，>10 没蒸馏透 |
| 模型失效条件 | 每个模型明确写出边界 | 只写优点不写局限 |
| 迁移测试输出 | "基于模型 X/Y 推断，可能…但不确定" | 斩钉截铁下结论 |
| 反编造抽查 | ≥3 条关键术语回查原文命中 | 凭印象写作 |

**蒸馏完成判据（v1.13.0 新增，最高可测标准）**——上面的检查项证明"方法对"，本判据证明"产出够格"：**一条产出算"真蒸馏完成" = 另一个 agent 只读产出 skill（不读原文）能照做，并产出与资料意图匹配的结果**。判据应用：
- 逐段自检：产出是否仍是"摘要/综述"口吻？若是 → 未完成（摘要 ≠ 蒸馏，agent 无法照做）
- 判据不是"我自己觉得解释清楚了"，而是"换一个 agent 不读原文能不能执行"
- 交付前用判据做**终检**：模拟一个只拿到 skill 的 agent，能否完成资料里的核心任务

> 与阶段 5「70% 成熟度」的关系：完成判据卡的是"骨架对、可执行"，70% 成熟度指的是"实战还需迭代"——两者不冲突，判据是下限，成熟度是预期。

**迭代上限**：阶段 1→4 最多循环 2 轮。2 轮后仍有不通过项 → 把薄弱维度诚实写入 Boundary 段，交付当前最优版本——不无限打磨。

### 阶段 5：命名 + 交付

- **`name`**：英文小写 slug，≤40 字符，只含 `[a-z0-9-]`，体现核心技能（不用书名全称）
- **`description`**：[是什么] + [何时用/触发场景] + [动词动作] + 消歧（同名词要区分）
- **保存**：`~/.workbuddy/skills/<name>/`，frontmatter 加 `agent_created: true`
- **出处索引**：`references/出处索引.md` 记录关键观点对应原书章节
- **INDEX/GLOSSARY 可选增强（v1.13 新增）**——大书拆多 skill 或产出多模型时建：
  - `references/INDEX.md`：模型导航（哪个模型在哪个 section、模型间关系/互链）——agent 查"哪个模型处理 X"时快速定位
  - `references/GLOSSARY.md`：术语统一（同义词/译名映射，如"失控反应 = 热失控 = thermal runaway"）——防 agent 因术语不一致漏检
  - **克制门槛**：小书 / 单模型 / 产出 <3 个模型时可跳过（不为小产出加负担）；INDEX/GLOSSARY 本身 ≤50 行，超了说明该拆
- **交付时设定正确预期**：蒸馏完成 ≈ 70% 成熟度，**不是终点**。建议用户在 1-2 个真实场景试用后，带着问题回来做 1-2 轮"对比吸收"（用 ray-skill-evolve 对比同类成果，或手动对比专家产出）——2026-08-15 RCA 实战：蒸馏后又经 4 轮对比吸收（同类报告×3 + 因果图专项）+ 双案例验证才定稿，剩余 30% 靠实战迭代补齐

## 更新已有蒸馏成果（Fold-in，v1.4.0 新增）

用户拿着新材料回来说"再补充一下"/"最近有新版"时，**不重做蒸馏，增量更新**：

1. **走阶段 0 确认**新材料的类型与目标（和原资料什么关系：同一方法论的深化？新主题？修订版？）
2. **读现有 skill 的模型清单**，逐项对比新材料：
   - **新信息强化现有模型** → 补案例佐证（RIA++ 的 A1 段）
   - **新信息与现有模型矛盾** → 标注演化（"原模型 X，新材料修订为 Y，因为…"），更新模型而非硬保旧版
   - **全新主题/模型** → 走阶段 1 五步法提取后增补
3. **只改涉及的部分**，模型清单、RIA++ 段、Boundary 同步修订；已验证过的部分不重测
4. **Fold-in 交付前必须提议真实案例测试**（v1.6.0 新增）：新增/修订的模型用真实案例跑一遍——抽象测试（完整性/迁移）发现不了"知道但做不到"的执行落差。2026-08-31 Stoessel→thermal-risk 实证：701 氧化釜案例发现矩阵查表差异（报告 I 级 vs Stoessel 标准 II 级）+ 自催化盲区（双氧水体系未做双扫描测试），抽象测试全过
5. **验证发现的问题当场回流**（v1.6.0 新增）：真实案例测试发现的 P1/P2 patch 级问题**当场修进 skill**，不标"待下次版本更新时回流"——验证闭环的最后一环是回流，不是记录。2026-08-31 实证：验证报告写了 P1/P2 标"待下次"，靠 self-neat 审计才补回流
6. 更新 `references/出处索引.md`，标注新材料来源

> 与阶段 5"70% 成熟度"预期衔接：Fold-in 就是那剩余 30% 的实战迭代通道。

## 品味守则

| 原则 | 一句话 |
|------|--------|
| 框架 > 摘要 | 反复出现的核心论点比章节摘要更有价值 |
| 方法论 > 感悟 | 可操作的步骤比"作者认为很重要"更有用 |
| 边界 > 优点 | 知道资料不能干什么，比知道能干什么更重要 |
| 判断 > 知识 | 蒸馏出"作者怎么决策"（if-then 规则 / 阈值 / 权衡 / 嗅觉信号），不是只列术语——把"认识这些词"升级为"像作者那样行动" |

## 反编造铁律

1. **不凭记忆拆书**：没文本就停下来问用户要，宁可停下来不硬拆
2. **所有关键术语回查原文**：Grep 确认该词确实出现，不确定标"待核实"
3. **隐含模型标"延伸解读"**：不冒充作者原话
4. **案例无法确认出处就删**：宁可少一个案例，不编一个
5. **生成前读 spec，不靠印象写**（v1.1 新增）：填充每个字段（定义/案例/步骤）前，先回到原文或 references 对应规范核对，写完对照校验——不靠"我觉得应该是这样"写作
6. **MISS 先怀疑断言写法，再怀疑原文**（v1.7 新增）：回查 MISS ≠ 编造——批6 实证 3 个 MISS 全是断言措辞与原文不一致（大小写/换行/分词），逐个回查原文全部命中。诊断顺序：换同义词/核心子串重搜 → 查原文同义表述 → 才判定真编造。详见 `references/quality-checklist.md`「反编造回查 MISS 处理规范」

## 失败模式

| 如果…失败/出错 | 兜底动作 |
|--------|---------|
| 资料是扫描版 PDF（无文字层，读取失败）| 提示用户换文字版，或 OCR（逐页写盘，避免中断前功尽弃）|
| 资料公开信息很少（提取失败风险高）| 心智模型减至 2-3 个，标"基于有限信息推测"，诚实边界加大篇幅 |
| 提取出的模型一盘散沙（关系梳理失败）| 说明关系没梳理对——回阶段 1 第 3 步重画关系图 |
| 信息不足却硬要生成（质量兜底失败）| 停止，告知用户质量受限，不强生成 |
| **凭记忆跑流程、未加载本 skill**（元违反）| 立即停止，加载本 skill 逐阶段对照补做。**本 skill 存在的意义就是防遗漏，凭印象跑必然跳过下面几项** |
| **跳过诱饵测试**（最高频遗漏）| 补做 3-5 个"不该调用"场景。只测"能用"不测"不滥用"= 没验证边界承诺 |
| **多材料未请用户拍板主从** | 补提 2-3 个融合方案让用户选，不自行默认"两本都为主" |
| **跳过真实案例测试** | 抽象测试替代不了；主动向用户提议拿一个真实案例跑一遍 |
| **模型数超 7 个** | 先跑 V3 排他性：去掉它哪个判断做不出？若不可替代则保留并在边界说明，别为凑数强行合并 |
| **产出像摘要而非可执行 skill** | 用完成判据终检：换一个 agent 只读产出（不读原文）能否照做？不能 → 重写为程序性知识（checklist/决策规则），去掉叙事 |

## 反例黑名单（❌ 不要做）

❌ 把通用道理包装成资料的"独特见解"
❌ 忽略作者自己承认的局限
❌ 信息不足时强行生成完整框架
❌ 把资料观点当成该领域唯一真理
❌ 语录/心法类硬套"步骤 1/2/3"模板
❌ 编造资料里没有的引用/案例/数据
❌ **凭记忆执行本流程而不加载 skill**（元违反：本 skill 存在的意义就是防遗漏。凭印象跑必然跳过阶段 0 概览确认、V1/V2/V3 三重验证、诱饵测试、多材料拍板——2026-08-31 CCPS 批2/批3 实证）
❌ **只做正向测试就交付**：完整性/迁移/真实案例证明"能用"，诱饵测试才证明"不滥用"
