# 核心模型提取五步法 + 三重验证

> 阶段 1 核心模型提取时用本文件。这是决定 skill 质量上限的关键一步。

## 五步法

### 第 1 步：扫作者自命名的框架

核心模型往往有作者自己起的名字。Grep 搜原文，找信号词：

```
模型|法则|循环|工程|精神|定律|公式|方程|原则|铁律|维度|步骤|方法
图\d|图 \d|见图
```

把命中的概念列成候选清单（通常 10-20 个）。

### 第 2 步：锁定每个模型的精确定义

每个候选模型，**回到原文 Grep 定位定义**——不凭印象写：

- 优先用原书图（"图 1-1"）标题和注释——图往往是模型的浓缩
- 有明确一句话定义 → 直接引用，标出处
- 定义散见多章 → 从多处拼出，标"综合自第 X 章/第 Y 章"
- 找不到明确定义 → 标"待核实"，不脑补

### 第 3 步：梳理模型间关系（最关键）

核心模型之间通常有三种关系，画成**文字版关系图**：

| 关系 | 含义 | 例子 |
|------|------|------|
| **层级** | A 包含 B | 主模型 ⊃ 子方法 |
| **流程** | A → B → C | 阶段递进 |
| **支撑** | A 是 B 的基础 | 基础决定质量 |

> 一本好方法论书，核心模型之间一定有结构；提取出来是一盘散沙 = 关系没梳理对。

### 第 4 步：从案例反推隐含模型

作者反复用同一种方法解决问题但未系统命名 → 那就是隐含模型：

- 扫案例章，问"作者每次解决问题的套路是什么？"
- 抽象成模型，**标"延伸解读，非原书命名"**——不冒充作者说的

### 第 5 步：模型验证 3 问

每个模型问三个问题，答不上回原文补或标"待核实"：

1. **原书有没有明说？** 还是我脑补的？（脑补的标"延伸解读"或删）
2. **边界条件？** 什么时候适用/不适用？（写进 skill 适用边界）
3. **输入→输出？** 从什么状态到什么状态？（写进 skill 概述）

## 三重验证（候选模型筛选）

每个候选模型过一遍，不过则淘汰（写入 rejected 保留审计轨迹）：

| 验证 | 问题 | 不过的信号 |
|------|------|-----------|
| **V1 跨域复现** | 资料中至少 2 个独立段落有佐证？ | 只出现一次 |
| **V2 生成力** | 能用它回答资料没明说的新问题？ | 只能复述原文 |
| **V3 排他性** | 不是任何聪明人都会说的常识？ | 是通用道理 |

## 提取内容分类

| 类别 | 数量 | 说明 |
|------|------|------|
| 核心模型 | 3-7 个 | 骨架，放 skill 最前面 |
| 方法论/清单 | 3-8 条 | 可操作、可验证、可迁移 |
| 关键概念 | 5-15 个 | 作者自创或重新定义的术语 |
| 案例模式 | 3-5 个 | 佐证框架的最小案例片段 |
| 应用边界 | — | 适合/不适合 + 作者盲区 |

## 译本术语统一

中文译本术语常不统一（growth mindset → 成长型思维/成长性心态）。提取前先建"统一译法→原文词"对照表，全书统一，并标注原文词避免歧义。
