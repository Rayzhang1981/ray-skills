# 格式处理链路

> 阶段 0 读取资料时用本文件。覆盖中文资料（扫描版/复杂排版/译本）与**英文技术材料**（手册/指南/标准）的读取与清洗。

## 支持格式与推荐读法

| 格式 | 推荐读法 | 说明 |
|------|---------|------|
| `.md` / `.txt` | 直接读取 | 中文 TXT 常是 GBK 编码，先检测再转 UTF-8 |
| `.pdf` | 文本型用 `pdftotext -layout`；扫描型需 OCR | 中文 PDF 多为扫描/双栏，直接提取易乱码缺字 |
| `.epub` / `.mobi` | Calibre `ebook-convert` 转 Markdown | 常有 DRM 或不标准结构 |
| `.docx` | python-docx 抽取 | 中文书常**不带 Heading 样式**，需回退文本特征重建目录 |

## 英文技术材料专项（手册/指南/标准类）

英文技术 PDF（如 CCPS/ABS/NFPA 手册）与中文书踩的坑完全不同：

1. **大 PDF 分层精读**：300-550 页技术手册直接 Read 必爆 context。链路：**pypdf 全文导出 txt → Grep 定位章节信号词 → Read 分层精读**（目录层→摘要层→精读层）。临时 txt 用完即删。
2. **术语精确定义必须回原文**：技术材料的术语有严格定义（如 ABS 体系里 causal factor ≠ root cause ≠ contributing factor），**不凭印象翻译**——每个核心术语回原文定位定义段落，蒸馏时建"中英术语对照表"。
3. **表格/图是核心信息载体**：技术手册的关键知识常在表格和分类树里（如 Root Cause Map 的 233 节点树几乎全是表格结构）——提取时**不能只抓正文段落**，表格行列关系本身就是方法论。openpyxl 解析 xlsx 失败时改用 zipfile + xml.etree.ElementTree 直接解析 sharedStrings/worksheets。
4. **多份手册融合**：见 SKILL.md 阶段 0「多份材料融合」——主从关系由用户拍板。
5. **PDF 章节定位三坑**（2026-08-31 Stoessel 2020 蒸馏实证）：
   - **正则误匹配表格编号**：Grep 搜 "Chapter 3"/"3.1" 时，"Table 3.1"/"Figure 3.1" 会被误匹配——定位到表格而非章节正文。解法：信号词加边界（如 `^Chapter 3$` 或 `Chapter 3[^0-9]`），命中后看上下文行再精读
   - **目录页码偏移不稳定**：PDF 目录页页码与实际页偏移（封面/前言/版权页占页数不定），按目录页码直接跳转会错位。解法：用章节标题文本定位（Grep 章节名），不用页码
   - **重复提取超时**：大 PDF 反复 Read 同一区域会爆 context/超时。解法：一次提取写入临时 txt，后续用 Grep 按需切片，不重复 Read 原文

## 中文 PDF 专项

1. **先判断文本型还是扫描型**：`pdftotext book.pdf - | head` 看输出。有可读文字→文本型；空白/乱码→扫描型。
2. **文本型**：`pdftotext -layout book.pdf book.txt`（`-layout` 保排版）。双栏可能串栏，转完检查。
3. **扫描型（需 OCR）**：PyMuPDF 拆页 → 逐页 `tesseract page.png out -l chi_sim+eng` → 拼接。无 tesseract 时用 `rapidocr-onnxruntime`（纯 Python 自带模型）或 `paddleocr`。
4. **失败回退**：`pdftotext` 未装 → python + pymupdf/pdfplumber；tesseract 未装 → rapidocr/paddleocr；仍不行 → 请用户提供文字版。
5. **复杂排版**：提取后修正跨栏错行，不轻信原始顺序。

## 中文 DOCX 专项

1. **抽取全文**：python-docx 遍历段落与样式。真实中文书常不用 Heading 样式。
2. **样式为空回退**：正则匹配 `^第[一二三四五六七八九十百零0-9]+章`、`^序|前言|引言|附录|后记` 等特征词重建目录。
3. **分页符/页码**：docx 提取丢失物理页码，用"章节+小节"定位（非页码）。
4. **文本框/表格嵌套**：`document.paragraphs` 和 `document.tables` 分别遍历。

## 编码检测与清洗

```bash
# 检测编码
file book.txt
# GBK → UTF-8
iconv -f GBK -t UTF-8 book.txt > book.utf8.txt
```

失败回退：python `chardet` 自动检测编码再转码。

## 清洗与去噪

- **统一编码**：全部转 UTF-8
- **过滤无关内容**：序言/致谢/参考文献/索引/版权页/广告插页——默认剔除
- **防案例稀释**：实战案例书夹带大量学员故事，方法论提取时降权或跳过纯案例章，只保留"能佐证方法的最小案例片段"
- **中文特有修正**：合并被换行打断的段落；去多余全角/半角空格；OCR 误字（的/地/得、已/己）酌情修正

## 分层精读（控 token）

中文书动辄几十万字，全量读必爆 context：

1. **目录层**：先读目录/章节标题，建立结构地图
2. **摘要层**：每章只读开头结尾与黑体/小标题
3. **精读层**：只对"核心方法论章""关键案例章"深读
4. **终止条件**：连续若干章未出现新方法论术语，或只剩案例章/结语时，停止深读转入提取

## REPL 式探针（v1.4.0 新增，大文件的程序化访问）

> 把全文 txt 当**可查询语料**，不是一次性读完的对象。200 页书 ≈ 75k token，每章重读一遍（28 章）≈ 2M token；用探针按需切片，成本与产出成正比而非与原文体量成正比。>50k token 的大文件必用。

```bash
# ① 先量体积，再决定策略
wc -w full_text.txt

# ② 定位章节偏移，不加载全文
grep -n -E "^\s*(第[一二三四五六七八九十百]+[章回]|Chapter|CHAPTER)\s*" full_text.txt | head -40

# ③ 只拉需要的切片（start/end 行号来自 ② 的偏移）
sed -n '<start>,<end>p' full_text.txt

# ④ 写入 skill 前验证术语确实出现（呼应反编造铁律）
grep -c -i "术语或人名" full_text.txt

# ⑤ 定向 Read 带偏移，不整读
# Read(file_path, offset=<行号>, limit=<行数>)
```

适用环节：阶段 0 结构勘查、阶段 1 术语回查、阶段 4 反编造抽查。小文件（<50k token）整读即可，不必过度工程。

## 大文件蒸馏路线预决策（实测选型，2026-08-30 新增）

> 用户担心"大书/图片书 token 浪费"时，第一反应常是"先用对话版拆解省 token"——**实测表明这是误解**：两条路线的 token 总量几乎持平，差别在"上下文分配"不在"量"。选型前先实测书的真实属性，别凭体积猜。

**实测方法**（pypdf / PyMuPDF）：`page_count` + 每页 `get_text()` 字符数 + 扫描页比例（字符 <20 的页计为扫描页）。

| 书的实际属性 | 推荐路线 | 理由（实测基准） |
|------|------|------|
| 纯文字版 + 已按章拆成多 PDF | **直接分层精读（探针）** | 一次会话装得下大章（如 40k token），零中转；token ≈ 读全量 + 回查，无额外开销 |
| 纯文字版 + 整本单一大 PDF | 先 `pdftotext -layout` 出 txt → 探针分层 | 同上行，只是多一步本地转 txt（免费、不耗 token） |
| 纯扫描版/图片书（0 文字层） | **对话版多模态拆解 → 工作单 → distil** | 免 OCR（本机 tesseract 常不在 PATH）、读图不丢双栏/图表/公式 |
| 混合（少量扫描页） | 直接 distil + 扫描页单独 OCR 补 | 只为 1-2 页扫描不值得搭对话版流程 |

**三条铁律**：
1. **先实测再选型**：体积大 ≠ 要绕路。文字版 400 页（≈40 万 token）直接蒸馏，比"对话版拆+中转"更省事且 token 持平
2. **对话版拆解的独有价值 = 读图免 OCR**，不是"省 token"。仅当书无法被文字化（纯图片）时才是必选项
3. **IMA 只做补佐证**：RAG 检索只给 top 片段，做不了骨架拆解。工作单里某模型只有单处证据时，用 IMA 对话查精确答案补第二佐证

**反编造**：结论基于 2026-08-30 两本实测——中文 LOPA 书（CCPS 2010 中译）233 页 0 字符 = 纯扫描；CCPS HEP 3rd（18 号文件夹）29 章节 PDF、411 页、101 万字符 ≈ 40.5 万 token、99.5% 文字版、已按章拆好。非凭印象。
