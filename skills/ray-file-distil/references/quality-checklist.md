# 质量自检清单

> 阶段 4 质量验证时用本文件。逐项核对，任一不过先修再交付。

## 完整性测试

选 3 个资料中明确讨论过的问题，用新 skill 分析，结果应与资料结论一致。

## 迁移测试

选 1 个资料未讨论但在应用范围内的问题，用 skill 推导出合理分析（"基于框架 X，可能…但不确定"）。

## 自检清单

- [ ] **核心模型已提炼**：五步法找出了作者自命名的框架，每个定义已回原文锁定
- [ ] **模型关系图已梳理**：层级/流程/支撑关系已画成文字版，放 skill 最前面
- [ ] `name` 是英文小写 slug，≤40 字符，仅含 `[a-z0-9-]`
- [ ] `description` 含触发词 + 使用场景 + 动词动作，无同名词歧义
- [ ] `description` **三段式**含 `⚠️不调用` 路由护栏；已过「边界段↔触发词反向一致性检查」（见下节）
- [ ] 内容**可操作/可调用**，不是空泛摘要
- [ ] **未编造**原书没有的引用/案例/数据（有疑义标"待核实"或附出处）
- [ ] **隐含模型已标注**（非原书命名的模型标"延伸解读"，不冒充作者原话）
- [ ] 译本术语已统一，关键外文词已标注原文
- [ ] 去噪完成（无序言/致谢/广告残留）
- [ ] 中文书用了合适模板（语录/心法类未硬套步骤型）
- [ ] 关键观点附了出处索引

## ⚠️ description ↔ 边界段反向一致性检查（v1.5.1 新增，高频 bug）

> 2026-08-31 CCPS 批1/2/3 实测：**边界段写了"不适合 X"，触发词却同时裸列 X** —— 边界说不要、触发词在招手。这比"没写边界"更隐蔽：写的人以为自己声明过了，路由却仍会把它拉起来。

**检查方法**：把边界段"不适合"清单里的每个关键词，拿去 description 触发词列表里**反向搜一遍**，有交集 = 矛盾：

| 情况 | 处理 |
|------|------|
| 该词在本 skill 确有合法场景（如 PHA 里的"要不要上 LOPA"、SIS 里的"LOPA 保护层判定"） | 保留触发词但**加限定语**区分场景，并在 ⚠️不调用段点名排除执行层场景 |
| 该词纯属执行层 / 属其他 skill（如"相容性"数据查询、"泄放尺寸计算"、"PFDavg 验算"） | **从触发词删除**，只在 ⚠️不调用段保留作路由目标 |

**推荐结构**：description 用三段式 —— `场景描述 + 触发词 + ⚠️不调用路由护栏`。只有触发词、没有护栏的 description，等于把路由决策全交给关键词匹配。

> **⚠️ 检查时两段独立，防假阳性（v1.7.0 新增，2026-08-31 批6 实测）**：初版脚本把 `⚠️不调用：` 段里的消歧词（如"F-N 曲线""风险等值线"用作路由目标）误判为触发词冲突——**触发词段是"本 skill 能做什么"，⚠️不调用段是"本 skill 不做什么 + 路由去哪"，两段的词天然会有重复**。检查时先按 `触发词：` 与 `⚠️不调用：` 切分两段，只把「⚠️不调用段列出的词」拿去「触发词段」搜，若触发词段该词**只出现在"不调用"语境**（如"F-N 曲线（→ 专业 QRA 软件）"）则不冲突；真正冲突是**同一裸词同时作为本 skill 的能力卖点与边界排除**。批5/批6 标准做法：`check_desc_batch5.py` / 参考脚本分离两段独立检查。

**一键检查**：

```bash
DESC=$(sed -n '4p' SKILL.md)   # 取 description 行
for w in LOPA 相容性 泄放 PFDavg 物性; do
  echo "$DESC" | grep -q "$w" && echo "⚠️ 冲突: $w"
done
```

## 数量标准（通过/不通过信号）

| 检查项 | 通过 | 不通过 |
|--------|------|--------|
| 核心模型 | 3-7 个，各有来源证据 | <3 或 >10 |
| 方法论/清单 | 3-8 条，可操作 | <3 或全是泛泛原则 |
| 概念词汇表 | 5-15 个，有定义 | 只列术语不给定义 |
| 应用边界 | 明确写适用范围和局限 | 只写优点不写局限 |
| 案例 | 至少 3 个，有书中支撑 | 无案例或案例不准确 |

## 反编造回查 MISS 处理规范（v1.7.0 新增，2026-08-31 批6 实测）

> 批6 实证：首轮断言回查 **3 个 MISS**，逐条回查原文后发现全部是**断言关键词写法与原文措辞不完全匹配**（如 "frequency of an incident is less well understood" 被拆成两半、大小写差异、换行断词），最终 20/20 全过。**MISS 不等于编造**，先诊断再下结论：

| MISS 原因 | 诊断法 | 处理 |
|-----------|--------|------|
| 断言关键词写法与原文措辞不一致（最常见） | 换同义词/核心子串/大小写不敏感重搜；原文可能跨行 | 修正断言写法后重搜，命中即算通过 |
| 原文确有该概念但用不同表述 | 搜概念核心词（如 probit 搜 "mean value of 5" 拆开搜 "5"） | 确认概念存在即算通过 |
| 原文真没有（真编造） | 回查失败且无任何同义表述 | 删除该断言/标注"延伸解读" |

**纪律**：MISS 后**先怀疑断言写法，再怀疑原文**——写断言时尽量贴近原文措辞（可先 grep 原文再写断言），减少假阴性；真编造零容忍。
