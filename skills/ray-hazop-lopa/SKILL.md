# ray-hazop-lopa

工艺安全 HAZOP+LOPA 定量分析报告生成器。融合团队正式报告框架（26 列 LOPA 全链路）与 AI 定量分析深度（动力学/泄放/MAWP），输出可直接交付的 HTML 报告。

## 适用场景

| 场景 | 输入 | 输出 |
|------|------|------|
| 生成新报告 | 工艺规程 + 反应热评估报告 + 设备清单 + 参考文献 | LOPA 定量报告 HTML（主报告+附件） |
| 审查已有报告 | HAZOP 分析记录 xlsm（团队版） | 深度分析 + 12 点优化建议 |
| 专项校核 | 热评估报告 / 泄放需求 | 附件级计算（动力学/泄放/MAWP） |

## 角色边界（v1.2.0 新增）

**本 skill 是 HAZOP 参与专家的分析助手，不是 HAZOP 主席，更不是最终裁决者。**
- ✅ 做：提取证据、标注缺口（缺失/矛盾/弱证据）、起草会议提问（给主席/工艺/设备/仪表/电气/消防/业主各专业）、给出候选原因/后果/待核实保护层、计算校核
- ❌ 不做：签发 HAZOP 结论、关闭行动项、批准设计、替代正式研讨会记录
- 所有输出定性为「供会议讨论的专家预案」，不是正式工作表结论——交付时在报告显著位置注明

## Red-team 复查（v1.2.0 新增，报告生成后必做）

生成报告后逐图（逐节点）做一轮对抗性复查，与 12 点自检互补（自检管格式，复查管内容）：

| 复查动作 | 说明 |
|---------|------|
| 删除不适用行 | 与图纸/数据不符的偏差行直接删，不留"以防万一" |
| 合并重复 | 同节点内重复场景合并（保留证据最强者） |
| 标记矛盾 | 与源图纸、拓扑证据、后期澄清矛盾的场景打红旗，写入行动项 |
| 证据回指 | 每个结论必须能指回来源（工艺规程页码/热评估曲线/计算书）——指不回 = 删 |
| 查漏 | 每张 P&ID 至少过一遍：泄压/联锁/止回/放空/双阀/惰化 六类保护是否都被问到 |

## 工作流（五步）

1. **输入收集与解析**
   - 读工艺规程（PDF/Word）、反应热评估报告（RC1/ARC/DSC/TSU）、设备数据表、参考文献 PDF
   - PDF/Word 转文本：markitdown / pdf 技能；xlsm 用 openpyxl（venv：`C:\Users\rayzh\.workbuddy\binaries\python\envs\default\Scripts\python.exe`，read_only+data_only 模式）

2. **数据提取与来源审计**
   - 提取关键参数：反应热/ΔTad/MTSR/TMRad（RC1/ARC）、热稳定性（起始分解温度/分解热/温升速率/Phi）、设备 MAWP
   - 建立**数据来源审计表**三态：实测 ✅ / 估算 🟡 / 缺口 ❌；估算项不进 LOPA 概率定级，仅定性支持

3. **定量分析（按需模块）**
   - 热风险：ΔTad/MTSR/TMRad/Stoessel 矩阵分级（热评估报告实测数据优先）
   - 双氧水/过氧化物分解动力学：两点 Arrhenius 外推（Ea/R = ln(k2/k1)/(1/T1−1/T2)），数值积分求温升时间线；污染 kF 放大坍缩
   - 泄放面积：API 520 纯气体（下限）｜DIERS/OMEGA 两相流（主方法）｜刘嚆储罐泄压口（常压设计）｜赵红乔 kF 污染修正——四方法交叉
   - MAWP：圆筒按 **GB/T 150.3-2011 式(3-1) 反解 `[Pw] = 2·[σ]t·φ·δe/(Di + δe)`**（默认口径）；ASME VIII-1 UG-27 口径用 `--code asme`。⚠️ 参数语义三连：`--D`＝**内径**、`--t`＝**有效厚度 δe**（非名义厚度）、`--S`＝**设计温度下**许用应力（查 GB/T 150.2）

4. **报告生成**
   - 26 列 LOPA 全链路表：场景号→偏移→原因→Cp→CF→Pp→S→Rp→IPL(PFD·状态)→Pr→Rr→缓解性保护→行动建议(PFD)→Rf
   - 结构：工艺与数据基线（含审计表）→ 风险矩阵与概率映射 → 节点划分 → 节点工作表 → 共因失效 → 残余风险声明 → 风险统计 → 行动项闭环 → SIL 衔接 → 版本记录
   - 附件分页化：估算项转独立附件页（计算细节+SVG 图表），单文件 Tab 切换（templates/lopa-report-template.html 骨架）

5. **质量自检（每版必做）**
   - 12 点检查清单逐项核对（checklists/lopa-12point-checklist.md）
   - 乱码扫描：`\ufffd` 计数 = 0
   - HTML 标签配对（`<section>` 开/关计数、`</html>` 闭合）
   - Edge headless 渲染验证（`--headless --screenshot`）

5b. **交付收口十条**（v1.4.2 补六条；v1.7.0 由「蒸腈/精腈 6 台容器 MAWP 技术说明」扩 4 条；每条都有实证事故，逐条过）

   1. **决定性判据＝重生成比对**：由数据文件（`report_data.py` 之类）**重生成**报告
      （把生成器的输出目录重定向到临时目录，**不碰交付目录**），与交付件**逐字节比对**。
      一条判据一次覆盖**全部中间步骤**（位号补全→正文改写→版本行→新增场景），强于逐步声明比对。**必做**。
   2. **逐格复验的声明必须按「渲染域全集」派生，不按「我记得改了什么」**。
      事故：声明生成器先漏 7 类（新行数值/标志字段、STATS 传导、共因表、数据来源表、行动项编号顺延、版本行、新提问），
      再漏 `DESIGN_BASIS`/`MEASURE_CRITERIA`/`LITERATURE_VALUES` 三个渲染集合，两轮共报 **139 处假 FAIL**。
      ⇒ 新增**数据集合**或**渲染分支**时，同步扩展声明器。
   3. **口径同步扫描（改一处、扫全链）**：同一事实常出现在多处——设备 MAWP 同时出现在
      「设备设计参数基线表」「数据来源审计表」「缺口清单正文」「场景后果栏」**共 4 处**。
      改一处后必须 grep 全部出现位置逐一同步，否则报告自相矛盾。
   4. **交付验收必须逐「域」声明覆盖面**：文本域／**样式表域**／数据集合域／**图像件域**各有自己的发现者。
      实证：`<style>` 被模板字典 repr 顶掉（页面完全无样式），而结构检查器仍判「0 错 0 警」——
      **样式表内容此前根本不在它的域内**。凡改渲染模板，**必须附一条「产物外观仍成立」的断言**。
   5. **负控不可省**：新检查器／新声明器**必须拿已知坏样本反验一次**
      （空声明文件应报出全部差异；坏样式表应被判失败）。**只跑正例等于没验**。
   6. **PDF 重导的静默失效**：Edge `--print-to-pdf` 在 ① 残留进程占用同一 `--user-data-dir`、
      ② 全新空 profile 首启初始化 时**会静默不打印**（退出码看着正常、**文件大小与修补前分毫不差**）。
      验收必须看**时间戳 + 页数 + 关键文本**，不能只看退出码或"文件存在"。
      另：输出路径含**空格**时不要用 `Start-Process -ArgumentList`（会被拆成多参数报
      "Multiple targets are not supported in headless mode"），直接逐参成串调用。
   7. **声明器要的是「前版数据快照」，不是 HTML**——`gen_expect*` 类脚本按**数据模块**对账
      （它 `exec_module` 传入的文件），HANDOFF 只写 `<旧> <新>` 时**必须注明类型**，
      否则首轮会误传 HTML 报 `SyntaxError`（本次实证）。
      **无精确前版快照时**（旧 bak 落后于后补的补丁）：对当前数据**逐处逆替换重建**
      一份 `_report_data_pre_rN.py`——每个逆替换**断言唯一命中**，重建后**双模块对账**
      （场景数相等、FINDINGS 计数差 == 本轮新增数），比翻旧 bak 可靠。
   8. **落笔器必须幂等，且判据顺序是「先查 new、再查 old」**：追加型插入（锚点文本原样保留、
      新块插在其后）会让**锚点继续存在** ⇒ 若先判「old 在不在」，会把**已应用**误判为**未应用**
      → **重复插入**（本次 F25 插了两份，靠塌缩脚本修复）。正确顺序：
      `if new in src: 跳过（已应用）` → 再校验 `old` 的唯一命中数。
   9. **共用 stdout 的双重包装会关掉底层 buffer**：脚本 A `exec` 脚本 B 的头部
      （B 内含 `sys.stdout = TextIOWrapper(...)`）时，A 再包一层 ⇒ **内层 wrapper 被 GC 时
      close 掉底层 buffer**，其后一切输出 `ValueError: I/O operation on closed file`。
      正解：**exec 后直接用内层那个包装，绝不再包**。
  10. **交付件内嵌 SVG：`<text>` 里不得放 HTML 标签**（如 `<b>`）——HTML 解析器会
      **提前闭合 SVG 结构**，其后框图与文字被当普通文本流抛出（整块塌陷）。
      **门禁不报、结构检查不咬**，只有**目视渲染**能发现。配套：目视验收分两步——
      **全图看布局 + 裁切放大看细节**；并校验长条标签**是否越出 viewBox**（本次实证两处越界）。

## LOPA 计算规则

- Pp = Cp × CF；Pr = Pp × Π(PFD)
- **仅"有效"状态预防性 IPL 计入 PFD**（待验证→不计或保守；不成立→明确标注）
- **缓解性 IPL（泄爆/隔爆/围堰/喷淋/锁气卸灰）不进 Pr，但进 Rf**——在后果/缓解维度体现，不乘进预防侧频率（NFPA 68 / ISO 16447 / GB/T 32857；CCPS 2015 §6.3 + DT 5.8–5.49）
- 管理措施（SOP/检查表/防干转保护器）不计 PFD，作 CF 修正
- Cp↔矩阵等级映射：可能性等级 1-7 ↔ 年概率 <10⁻⁶ ~ >10⁻¹（矩阵为 7×可能性 × 5×严重性，四维后果：人员/财产/环境/声誉）

### LOPA 教材校验版（Crowl & Louvar 4th ed. Ch12，作 26 列报告的**交叉校验简版**）

> **定位**：本节是**教材口径**的 LOPA 速查，用途 ＝ 对已生成报告做**交叉校验**（六步是否走全、频率调整能否复现），**不替代**本 skill 主流程、**不替代** CCPS LOPA 指南。出处：Crowl & Louvar, *Chemical Process Safety*, 4th ed., Ch12（p327–334）。
> ⚠️ **本节口径均为教材版**；与 CCPS 指南冲突处已**并列留痕**，不得单向采信。

**LOPA 定位与五条固有局限（教材自列，p328）**
- 定义：LOPA ＝ **半定量、简化的 QRA**——用**数量级类别**表示频率 / 后果严重度 / 保护层失效可能性；结果**应恒比精细 QRA 保守**；有不确定性或结果不满意 ⇒ **升级 QRA**。
- 适用阶段：概念设计 / 中试 / 详细设计 / 常规运行 / 变更扩建（Table 11-3）。
- 🚫 **不是场景识别工具**——必须先由 HAZOP / What-If 喂场景。
- 五条局限（p328）：① 非场景识别工具 ② 不能替代 QRA ③ 比 HAZOP 费时、简单决策价值小 ④ **跨场景比较仅在「同失效数据选法 ＋ 同容忍判据」内有效** ⑤ **跨组织不可比**（容忍判据与实施差异）。

**IPL 七判据（教材版，p327–328）**
① 独立性（不受初始原因与其他保护层失效影响）② 功能性（对特定异常工况执行所需响应）③ 完整性（能交付预期风险削减）④ 可靠性（规定条件、规定时间按意图动作）⑤ 可审查性 ⑥ 访问安全（防未授权/无意更改的管理系统）⑦ MOC（变更须评审/记录/批准）。
> 与本生态互指：`ray-pha` 的 IPL 判定为「八层保护归因 ＋ 七属性 ＋ 七因素严格度」；**教材七判据是其教学子集，判 IPL 资格仍以 `ray-pha` 为准**。

**六步流程（p328–330）**
① 单后果筛选场景 → ② 场景 ＝ 单一「原因-后果」对 → ③ 初始事件频率（**假定全部预防性屏障已失效**）→ ④ 识别 IPL 并赋 PFD → ⑤ `f = IE × ∏PFD`（式 12-31）；**多场景同后果再按式 12-32 求和** → ⑥ 对照容忍判据，不满足则加层。

**频率三步调整（教学流程，p329）**
① 查缺省表（Table 12-2）→ ② 按需求修正（年运行 1/12 则**频率 ÷ 12**）＋ **预防性维护修正（年 PM 4 次则频率 ÷ 4）** → ③ 乘各 IPL 的 PFD。

- 🚨 **双计数陷阱（p330）**：历史频率**可能已含某保护层**——问「每罐必有高液位联锁」是**公司要求**还是**IPL**？**必须防 IPL 双计**，须由有经验的团队成员澄清。（与本 skill 既有铁律「**仅"有效"状态预防性 IPL 计入 PFD**」同源；本条给出教材侧的追问方式。）

## 计算红线（工艺计算通用）

1. 单位换算必须双校验（Pa/kPa、kJ/min→W、m³/h vs kg/h——已两次踩坑）
2. 化学反应式先做原子平衡验证（C/H/N/O 数）
3. MAWP ≠ 设计压力（按实际壁厚/封头计算）；**算 MAWP 时 `t` 必须用有效厚度 δe = 名义厚度 − 钢板负偏差 − 腐蚀裕量** —— 用名义厚度会系统性高估（δn=5 / δe=3.7 时高估 35%）
4. 用户给的数据先确认口径（单位？单台还是合计？）
5. 时间类计算脚本打印时单位标签必须与变量实际单位一致（跨函数传值先核对）
6. **nRT/V 分压计算 V 必须用 m³**（勿 ×1000 转 L）；**MPa→bar 是 ×10 不是 ÷10**（2026-08-11 calc_mawp/calc_massbal 双踩坑；手算 O₂ 分压曾把 MPa 当 bar）
7. **公式必须可指明出处**：写进脚本/文档的公式要能说出「哪个标准的哪一条」，标了标准名就必须与之一致。反例（2026-10-01 订正）：`calc_mawp.py` 原式 `P=2SEt/(D+0.8t)` 被标为「GB 150」，实则与 GB/T 150.3、ASME UG-27 **都不对应**
8. **改计算脚本后必跑 `--selftest`**，且自检**必须含负控**（正例 + 负控 + 单位 + 边界）——只跑正例等于没验
