## ⚠️ 版本保存（重要！必须执行）

### 为什么必须保存版本？
- 避免样式错乱后回滚困难
- 每次完成重要功能后，可以回溯到稳定状态
- 节省空间，使用 Git Tag（几乎零额外空间）

### 何时保存版本？
- 完成一个新模块的转换后
- 完成 UI 优化后
- 完成计算逻辑验证后
- **完成重要功能后，必须询问用户："本版本是否保存？"**

### 如何保存版本？

**方式一：询问用户（推荐）**
```
在完成重要功能后，主动询问用户：
"本版本是否保存为 v1.X？"
如果用户选择"保存"，执行：
1. git add . && git commit -m "描述本次更改"
2. git tag -a v1.X -m "版本说明"
3. 更新 VERSION_LOG.md
```

**方式二：使用保存脚本**
```bash
# Windows (双击运行)
save_version.bat

# Git Bash
./save_version.sh
```

脚本会自动：
1. 检查未提交的更改
2. 自动递增版本号（v1.0 → v1.1）
3. 创建 Git 标签
4. 更新 VERSION_LOG.md

### 版本回滚方法
```bash
# 回滚到指定版本（临时查看）
git checkout v1.0

# 返回最新版本
git checkout master

# 查看所有版本
git tag -l | sort -V
```

### 版本号规则
- 格式：`v主版本.次版本`（如 v1.0, v1.1, v2.0）
- 小改动递增次版本号（v1.0 → v1.1）
- 大功能更新递增主版本号（v1.9 → v2.0）
