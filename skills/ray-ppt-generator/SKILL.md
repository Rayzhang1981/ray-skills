# Ray PPT Generator — PPT 内容引擎 + 可编辑 PPTX 生成

> **定位（v3.6 明确）**：本 skill 聚焦「**内容生成**」——把材料/主题变成高质量 PPT 内容与可编辑 PPTX 初稿，并同步产出**演讲稿 MD**。排版做到"够用"（生成即做好基础版式）；需对**已有 PPTX 深度美化/换肤/修复**时，用 `ray-ppt-refine`（独立 skill，见文末分工）。

基于 `python-pptx` 库快速生成专业级可编辑 PPTX 文件。适用于培训课件、安全汇报、流程图解等场景。不依赖 `ppt-implement` skill，无预览弹窗干扰。

## 触发条件

当用户要求：
- 基于 PDF/Word/数据生成 PPT
- 制作培训课件 / 汇报 PPT / 流程图 PPT
- 批量生成多页 PPTX
- 输出为可编辑的 PowerPoint 文件

## 需求确认（动手前必做）

**先判断输入模式（v3.5 新增）**：

| 用户输入 | 走哪个 |
|---------|--------|
| 给了**资料**（文档/PDF/报告/视频转写稿），要"总结并做 PPT" | **资料→PPT 模式**：见 `references/doc-to-ppt.md`（理解资料→提炼素材→叙事转化→排版） |
| 给了**已有 PPTX**，要"扩充/加模块/改部分内容"，且**保持原格式风格** | **已有 deck 扩充模式**：见 `references/extend-deck.md`（2026-08-27 新增：复用原版式新增页 + 保格式就地改文字 + XML 重排页序） |
| 只给了**主题/标题** | 本文件常规模式（下方需求确认 + 内容缺口补充） |

**扩充模式 vs 从头生成（决策要点）**：用户说"以这份 PPT 为底""保持原格式/风格一致""在这个课件基础上加"→ 扩充模式，**不要从零重造**——重造版式对不上原 deck（字体/色板/装饰细节很难完全复刻），工作量还大。扩充模式核心三件套：①新页**复用原 deck 样式常量**（先 dump 原 deck 的颜色/字体/版式坐标再动手）；②原页改文字用 `set_shape_text` 保格式替换（坑见 extend-deck.md）；③页序用 `reorder_slides`（重建 `sldIdLst`）统一收口。

> 判断口诀：**"先对齐需求再开做，结构定错后期翻修代价最高"**。

## 内容缺口自动补充

**如果用户输入内容较少或不完整，必须主动联网检索补充内容，不要用空洞文案硬填。**

**识别缺口**：
- 用户只给了主题 → 检索该主题的市场数据/趋势/案例
- 用户只给了标题 → 补充正文要点和支撑数据
- 用户描述模糊 → 明确行业/场景/受众

**检索执行**：用 `web_search` / `web_fetch` 搜：
- "[主题] + 数据/报告/趋势/案例"
- 优先权威数据源（Gartner、IDC、艾瑞、行业白皮书）
- 优先最近 6 个月的时效性数据

**填充原则**：
- 每个要点至少补充 2-3 句详细说明
- 添加真实数据、案例、数字支撑（**禁止编造数据**，无来源数据必须标注"估算"）
- 每页正文至少 80-150 字，不空洞
- 化工安全场景优先引用 GB 标准/事故案例数据

## 核心原则

### 1. 方案选型：绝不混用 ppt-implement

| 场景 | 方案 | 是否加载 ppt-implement |
|------|------|------------------------|
| 快速生成可编辑 PPTX | **python-pptx**（本 skill） | **不加载** |
| 需要精美网页预览/动画 | ppt-implement 完整工作流 | 加载，走 5173 预览 |

**绝对禁止混用**：加载 `ppt-implement` skill 后使用 python-pptx 生成文件，会触发其 hooks 反复尝试启动 5173 预览服务器，导致黑窗口反复弹出。若已误加载，需手动禁用两个脚本中的 `startServer` / `start_server` 函数。

### 2. 页面尺寸：13.333" × 7.5"（16:9）

```python
from pptx import Presentation
from pptx.util import Inches
prs = Presentation()
prs.slide_width = Inches(13.333)
prs.slide_height = Inches(7.5)
blank = prs.slide_layouts[6]  # 空白布局
```

### 3. 颜色常量：先定义再使用

`SAFE_BLUE(0x005293)` 主色 / `ACCENT_ORANGE(0xE67E22)` 强调 / `DARK_TEXT(0x2C3E50)` 正文 / 警示红绿常量。完整常量见 `references/code-templates.md` 第 0 节。

### 4. 字体：中文环境统一微软雅黑

```python
def set_font(run, name='Microsoft YaHei', size=Pt(14), bold=False, color=DARK_TEXT):
    run.font.name = name
    run.font.size = size
    run.font.bold = bold
    run.font.color.rgb = color
```

**字号参考**：标题栏 32pt 粗 / 副标题 16-18pt / 条目标题 18-20pt 粗 / 条目描述 12-14pt / 流程框 11-12pt / 页脚 10pt

**文字层次（v3.4 新增）**：不要只用一种正文色——用**五级灰阶**拉开层次（常量见 code-templates.md 第 0 节）：`TEXT_MAIN` 正文 / `TEXT_SUB` 次要 / `TEXT_MUTED` 弱化（来源、标注）/ `TEXT_FAINT` 最弱（页标签、深底弱字）。**数据/技术页正文可压到 10.5-11pt**（配半号字微调），比默认 13pt 更有印刷感；标题仍保持大号对比。

### 5. 文字排版：自动换行防溢出（核心教训）

**每个文本框必须启用 `word_wrap = True`**——否则中文长文本会溢出截断。框尺寸预留 **20% 以上余量**；两栏布局每栏宽 6.0-6.2"，间距 0.3-0.5"。

### 6. 统一标题栏 + 页脚

`add_title_bar()` / `add_footer()` 见 `references/code-templates.md` 第 0 节。页码框必须左移到 `PRS_WIDTH - Inches(3.8)` 避免溢出。

**页标签（v3.4 新增）**：`add_title_bar(tag=...)` 可在标题栏**右上角加灰色小字**标本页定位/来源/时长（如"条文说明 5.1.4"/"调查报告认定的直接原因"），杂志眉线感，几乎零成本。

**数据来源标注（v3.4 新增）**：数据/技术/学术页**必须在底部加来源**——`add_source_note(slide, "数据来源：GB 51283—2020 条文说明")`（9.5pt 弱灰）。这是课件的严谨性体现，引标准/报告/检测数据时不可省。

### 7. 多脚本拆分策略

单脚本生成 25+ 页容易因代码过长导致维护困难。拆分为 part1.py（生成前半） + part2.py（加载已有 PPTX 追加后半，见 code-templates.md 拆分配方）。

### 8. 临时文件 → 目标文件（避免权限冲突）

**不要直接写入目标目录**（可能 Permission denied）。先写入临时目录，再用 `shutil.copy2` 复制到最终位置。

### 9. Logo 添加（全页统一）

用 PIL 读尺寸算宽高比，右上角统一位置，遍历全部 slides 添加。代码见 `references/code-templates.md`。

### 10. 视觉设计规范

- **一页一主题**：标题即观点，内容支撑标题
- **少字多图**：超过 50 字的页面要警惕，用列表/框图代替大段文字
- **配色 dominance（v3.3 新增）**：主色占 60-70% 视觉权重，1-2 个辅助色 + 1 个强调色，**绝不平均分配**；主题相关配色，不要默认蓝
- **对比**：高风险用红底，低风险用绿底，警示用橙/红
- **留白**：文字框四周留 0.15" 以上内边距
- **3 秒法则（v3.3 新增）**：观众 3 秒内理解页面要点，否则内容太密
- **AI 痕迹规避（v3.3 新增）**：标题下不加装饰线（AI 生成标志）；全 deck 不重复同一版式；正文左对齐（只有标题居中）；不整页纯文字——每页至少一个视觉元素

### 11. 版式函数调用契约（v3.9 新增，防双页）

> 本 skill 的**页面函数**（`references/code-templates.md` 的 `add_cover_slide` / `add_content_slide` / `add_table_slide` / `add_vertical_chain_slide` / `add_stat_panel_slide` / `add_chart_slide` / `timeline_deadline_slide` / `card_matrix_slide` / `traffic_light_slide` / `heatmap_table_slide` / `metro_lines_slide` / `stair_levels_slide` 等全部 2.x 函数）**内部自带建页**（函数体内调用 `prs.slides.add_slide(layout)`）。

**铁律：调用任何页面函数（`add_*_slide(...)` / `*_slide(...)`）的页面函数内，不得再自己建页**——否则产生双页（页面函数建一页 + 版式函数又建一页）。实战踩坑：65 页版多 6 页、90 页版多 13 页，同一错误犯 2 次。

⚠️ **v3.20.0 修正**：本原则原列举的 `chain_slide` / `card_slide` / `stat_slide` / `table_slide` / `two_col_slide` / `checklist_slide` / `section_slide` 这 7 个名字**在 `references/` 里从来没有定义过**（历史遗留，全目录 grep `def <名>(` 零命中）——按名字复制会找不到函数。规则不变，名字以本行上方所列实际函数为准。

**写法模板（版式函数页面）**：
```python
def p46():
    steps = [...]              # 只写数据
    s = add_vertical_chain_slide(prs, '标题', steps, colors, layout, tag='...')  # 函数体内已建页
    notes(s, '口播稿...')
```

**写法模板（手写布局页面）**：
```python
def p05():
    s = prs.slides.add_slide(prs.slide_layouts[6])   # 自己建页（手写布局）
    add_title_bar(s, '标题', '副标题', tag='...')
    # ... 手写 rect/txt ...
    add_footer(s, 5, total=10, reg_no='文件编号')
```

**判断口诀**："本页用版式函数 → 页函数只写数据；本页手写 → 页函数自己建页。二选一，绝不混用。"

**🔍 生成前自查（v3.20.0 由 grep 钩子改脚本，防复发）**：规则写入不等于自动遵守——v3.9 晋升后实战写新页（y01/y02/y05）依然犯了 3 次。写完全部页面函数、运行脚本前，先跑：
```bash
python scripts/qa_ppt.py --dblpage gen_*.py          # 双页隐患静态扫描（不读 pptx）
python scripts/qa_ppt.py <生成的.pptx>               # 生成后三项体检（见原则 12）
```
有命中 → 删掉该页函数里多余的自建页行，把页面函数调用改为 `s = <页面函数>(...)`。自查不过不运行。
> 为什么弃用原 grep 钩子：① Windows/DSH 环境**没有 `grep` 命令**，钩子不可执行；② 原正则只覆盖"自建页 + 调版式函数"这一种写法，另两种（只调版式函数 / 纯手写）不触发；③ 原钩子硬编码了 7 个不存在的函数名。

### 12. 布局行高自适应 + 越界检测（v3.9 新增，防溢出）

- **行高按条目数自适应**：表格/事件链/条目页的行高步进要随行数/条目数压缩，防止最后一行溢出页面。已验证公式：竖向事件链 `row_h = min(0.98, (5.45 - (n-1)*gap) / n)`；表格函数加 `row_h` / `font_size` 参数（12 行表用 0.42 行高 + 9.5pt，7 行表用 0.55）。
- **生成后必跑越界检测**（QA 第一动作，不能只靠肉眼）：用 python-pptx 重读文件，遍历所有 shape，检查 `left+width > slide_width` 或 `top+height > slide_height`（含文本/形状），越界即修。**"看着没超"不算数——文本框 word_wrap 后文字可能溢出框体，必须用脚本检测。**
- **装饰形状不越页**：封面/结束页等装饰性 rect/oval 必须完全在页面边界内（0 ≤ x ≤ 13.333"，0 ≤ y ≤ 7.5"）——突出页边的"角部装饰"视觉上突兀（用户实测反馈"丑"）。

## 配图策略（v3.8 新增）

> PPT 做好 = 文字内容 + 合适配图。配图决策是**内容规划的一部分**——在页面规划表阶段就为每页决定"要不要图、哪类图、从哪来"。**本 skill 只做配图决策与编排，不自建生图能力**（防漂移：生图能力复用现有 skill，见下）。

### 配图三类来源（先分类，再定来源）

| 类型 | 典型场景 | 来源 | 理由 |
|------|---------|------|------|
| **信息类** | 流程图/事件链/防护分级/对比图 | **自己画**（python-pptx 原生形状） | 与内容强耦合，网上找不到完全匹配的；原生形状风格统一且可编辑 |
| **氛围类** | 封面背景/章节页/意境图 | ①免版权图库（Unsplash/Pexels）②AI 生图 | 图库快但化工场景覆盖差（反应釜/HAZOP 会议等几乎无贴切图）；AI 可控 |
| **证据类** | 事故现场/设备照片/合规文档截图 | **必须真实照片** | ⚠️ **红线：事故报告/合规文档禁止 AI 生成"现场图"**——真实性是证据的生命 |

### 生图编排（调用外部 skill，不复制能力）

氛围类图需要 AI 生成时，按场景选执行层：

| 需求 | 调用 | 说明 |
|------|------|------|
| 通用 AI 生图 | `ImageGen`（工具） | 文生图/图生图，默认选项 |
| 独立计费生图 | `ray-wuyin-image` | 速创 API，ImageGen 不可用时的备选 |
| 手绘风示意图 | `sketch-illustration` | 流程图/功能说明/PPT 配图（Sketch 极简/水彩等 5 种风格） |

**生图 prompt 规范**：风格词（如"商务简约、扁平插画"）+ 尺寸 16:9 + **无文字**（AI 生成文字必乱码，文字一律后期用 python-pptx 加）+ 配色与所选 PALETTE 协调。

### 免版权工业图获取（v3.12 新增，实战验证 2026-08-17）

氛围类图库路线（无需注册的最快路径 + 可编程 API 方案）：

| 路径 | 做法 | 适用 |
|------|------|------|
| **Pexels 直链免注册**（实战推荐） | WebSearch 搜 `pexels photo 主题` → 拿 photo id → 直接 `curl "https://images.pexels.com/photos/{id}/pexels-photo-{id}.jpeg?auto=compress&cs=tinysrgb&w=1200"` | 一次性找 3-5 张图，最快，无注册无 key |
| Pexels API（可编程） | 注册 https://www.pexels.com/api/ 拿 key → `curl -H "Authorization: KEY" "https://api.pexels.com/v1/search?query=industrial"` | 批量/动态换关键词 |
| Unsplash API（可编程） | 注册 https://unsplash.com/developers 拿 Access Key（50 次/时）→ `curl -G "https://api.unsplash.com/search/photos" -H "Authorization: Client-ID KEY" --data-urlencode "query=industrial factory"` | 同上 |

**灰度化（统一插图风格）**：`PIL: Image.open(url).convert('L')`（'L'=灰度）；背景用途再加压暗+染主色调（`ImageEnhance.Brightness` + `Image.blend`），保证文字可读。**页脚标注图片来源**（如"图片来源：Pexels，经灰度处理"）——免版权可商用，标注是礼貌也是溯源。

⚠️ 网络注意：Wikimedia Commons 国内常不可达；Pexels CDN（images.pexels.com）与 baidu 可达；www.pexels.com 网页有 403 反爬（用 WebSearch 拿 photo id 绕开）。

### 插入规范（与 ray-ppt-refine 诊断库对齐）

- 等比缩放，不拉伸变形
- 避开页脚区与标题栏
- 图片不遮正文；半透明蒙版上压文字时保证对比度
- 记录图片来源（图库 URL / AI 生成标记），备查

### 判断口诀

**"信息图自己画，氛围图找或生，证据图必真实；生图靠编排，能力不进 skill"**。

## 演讲者备注（Speaker Notes）

**python-pptx 原生支持每页备注**（`slide.notes_slide`），生成时务必填写——演示者开「演讲者视图」即可看到逐字稿。函数 `add_speaker_notes` 见 `references/code-templates.md`。

**逐字稿编写 3 规则**：

| # | 规则 | 说明 |
|---|------|------|
| 1 | **不是讲稿，是提示信号** | 加粗核心词 + 过渡句独立成段，帮演讲者抓节奏，不逐字朗读 |
| 2 | **每页 150-300 字** | 对应 2-3 分钟/页；超过则说明内容太满需精简 |
| 3 | **用口语，不用书面语** | "因此"→"所以"，听起来像在讲而不是在读 |

> 备注写在 notes 里，**不写在页面上**——页面只放面向观众的内容。

## 演讲稿 MD 产出（v3.6 新增）

生成 PPTX 时**同步导出一份独立演讲稿 MD**——与每页一一对应的口播稿，是演讲者手上的完整脚本（区别于写在 PPTX notes 里的提示信号）。

**实现（v3.20.0 补，原仅有要求、没有做法）——单源导出，天然抗漂移**：

**不要"另写一遍"演讲稿**——那是两处真相，改一处必漂移。正解＝**写完 PPTX 的 `notes_slide` 后，从 PPTX 回读生成 MD**：

```bash
python scripts/export_speech.py <生成的.pptx> <演讲稿.md> --titles "封面,结论先行,措施一,措施二,..."
```

`scripts/export_speech.py` 逐页读 `slide.notes_slide.notes_text_frame.text` 成文；页标题用 `--titles`（或 `--titles-file`）传入——**脚本不猜标题**，标题散在 `add_title_bar` 的文本框里，猜错比留空更坏。改口播稿 = 改 PPTX 备注层 → 重跑导出，MD 永远与 deck 同步。

**格式决策（md 权威源 + word 可选）**：

| 格式 | 角色 | 何时用 |
|------|------|--------|
| **MD**（默认，权威源） | 长期演进的活文档 | 演讲稿跟着 PPT 改；md 轻量、可版本控制、易再加工 |
| **Word**（可选导出） | 打印 / 分享 / 给非技术人员 | 需要时用 pandoc 或 python-docx 一键转，**不做权威源** |

**MD 结构**：每页一节——`## 第 N 页：{标题}` + 150-300 字口播稿（沿用上方"逐字稿 3 规则"：口语、提示信号、每页 150-300 字）。

**同步原则**：演讲稿与 PPTX 同源产出、逐页对应，**权威源在本 skill**。`ray-ppt-refine` 只动排版、不动内容结构，**不另造演讲稿**；若 refine 改了页数/标题，由它提示失同步，回本 skill 重新导出。

## 生成后必做 QA

> **核心原则："假设第一次渲染是错的，至少做一轮 fix-and-verify 再交付"**。
> 代码证明"结构存在"，不证明"版式舒服"——必须实际打开检查。

### 内容 QA
- [ ] 标题即观点，内容支撑标题（一页一主题）
- [ ] 数据准确、无错别字、无占位文字残留（"XXX"、"待补充"）
- [ ] 每页 ≥ 3-5 个要点，不空洞

### 叙事完整性
- [ ] **目标一致性**：deck 回答了用户的核心问题，重点/结论/语气适合目标受众
- [ ] **逻辑承接**：开场→论证/展开→结论/行动，页与页之间连贯过渡，不跳步
- [ ] **每页服务整体**：没有重复、断层、空白页或明显不匹配的页面类型
- [ ] **交付完整性**：最终文件存在且能打开，页数/格式正确，首尾页非空白

### 视觉 QA（转图片逐页看，v3.3 升级）

- **生成后必跑 `python scripts/qa_ppt.py <文件.pptx>`**（QA 第一动作，不能只靠肉眼）：一次跑三项——① **越界**（shape 右下角 ≤ 页面边界，含文本/形状）② **正文区重叠**（`y∈[1.55,7.05]` 内文本两两相交 > 0.06 in² 即报）③ **文本溢出**（按 CJK em 宽度估算行数 × 行高 vs 框高）。越界即修。
- [ ] **越界检测脚本 0 报错**（python-pptx 重读，shape 右下角 ≤ 页面边界）
- [ ] **交叉引用自洽**：文案里凡出现"见第 N 页"的，回读第 N 页确认内容**确实在该页**（实战：写了一处指向并不存在的页内容，脚本查不出）
- [ ] **无孤立标点 / 单字成行（widow）**：末行只剩一个标点或一两个字 ＝ 文本框偏窄，收窄措辞或加宽框
- [ ] **装饰件不压正文**：越界检测只查"出不出画布"，**查不出"压在文字上"**——装饰 rect/oval 必须目检确认未遮盖文本
- [ ] **卡内标题不加装饰线**：本 skill 只禁了"页标题下装饰线"，卡片内小标题下的短色条**同样是 AI 指纹**，一并禁
- [ ] 文字无溢出（中文长文本最容易溢出——确认所有 text_frame 都 word_wrap）
- [ ] 无重叠（文本框/形状碰撞）、元素间距 ≥ 0.3"
- [ ] 边距足够（距幻灯片边缘 ≥ 0.5"）
- [ ] 配色统一且**非默认蓝**；对比度足够（正文 ≥ 12pt，深底白字/浅底深字）
- [ ] 无标题下装饰线、无 lorem/占位残留
- [ ] 图片不越界、比例正常、不与页脚碰撞
- [ ] 页脚页码紧贴右下角（left≈12.25"、右边缘≈13.20"），封面/目录等无 title_bar 的页也统一

**fix-and-verify 循环（必做一轮）**：
1. 生成 → 导出图片 → 逐页找问题（**找不到问题时，再怀疑一次——假设一定有问题**）
2. 列出全部问题 → 修复
3. 重新导出**受影响页**复验——一个修复常引入新问题
4. 直到完整检查一遍无新问题才交付

### 技术 QA
- [ ] 文件能正常打开（python-pptx 生成后至少验证一次）
- [ ] 页码连续、页脚正确
- [ ] 若用 Win32COM 后处理，确认备份文件存在

**QA 通过标准**：上述清单全绿才交付；任一红项 → 修 → 重验 → 再交付。

## 常见坑与排查

| 问题 | 原因 | 解决 |
|------|------|------|
| 文字溢出框外 | 未启用 `word_wrap = True` | 所有 text_frame 都要设置 |
| 中文显示为宋体 | 未设置 `font.name = 'Microsoft YaHei'` | 每个 run 都要设置字体 |
| **页数翻倍（22 页变 28 / 90 页变 103）** | 页面函数先建页又调用自带建页的版式函数 | 见核心原则 11「版式函数调用契约」：二选一，绝不混用 |
| **布局越界（最后一行溢出页面）** | 表格/事件链/条目页行高未按行数自适应 | 见核心原则 12：行高按条目数压缩 + 生成后必跑越界检测 |
| **装饰形状突出页面（封面角部图案）** | rect/oval 坐标超出画布边界 | 装饰形状必须完全在 0-13.333"×0-7.5" 内（见核心原则 12） |
| 页码文字溢出 | 页码框太靠右 | 页码框收窄（宽 0.95"）紧贴右下角，右边缘 13.20"，距页边 0.13" |
| 流程框文字挤在一起 | 框高度不够 / 字号太大 | 框高 +0.2"，描述字号降到 11-12pt |
| Permission denied | 直接写入被占用的文件 | 先写临时目录，再 shutil.copy2 |
| 黑窗口反复弹出 | 误加载了 ppt-implement skill | 不加载 ppt-implement，或禁用其 hooks |
| 多页后脚本过长 | 单文件维护困难 | 拆分为 part1 + part2（公共模块 + load_prs 追加） |
| **扩充已有 deck 时保格式改文字报 IndexError** | 原 shape 段落数不足，`set_shape_text(para=1)` 越界 | para=0 写标题 → `clear_paragraphs(keep=1)` → `add_para()` 追加（见 `references/extend-deck.md`） |
| **新页插不进指定位置 / move_slide 失败** | 逐页移动依赖 rId 反查，易错 | 新页全部追加尾部 → 顺序表拼最终页序 → `reorder_slides` 一次重排（见 `references/extend-deck.md`） |
| 标题下装饰线 / 默认蓝 | AI 生成通病 | 用留白/背景色替代；选主题相关配色 |

## 与 ray-ppt-refine 的分工（正交，可组合不耦合）

| | ray-ppt-generator（本 skill） | ray-ppt-refine（独立 skill） |
|---|---|---|
| **定位** | 内容引擎：从无到有 | 排版美化器：从有到好 |
| **输入** | 材料 / 主题关键词 | 任意已有 PPTX |
| **输出** | PPTX 初稿 + 演讲稿 MD | 美化调整后的 PPTX |
| **排版** | 够用排版（生成即做好基础版式） | 深度美化（验收 + 改造） |

**边界**：两者独立可用、互不依赖——generator 一步到位产出可交付 PPTX；refine 自包含，能美化任意来源的 PPTX（含非 generator 产出）。需深度美化时，在 generator 之后单独跑 refine。

**演进方向**：本 skill 聚焦"最强内容生成器"（资料提炼 / 叙事弧 / 演讲稿）；refine 聚焦"最强版式美化器"（检测 / 换肤 / 修复）。经验由 ray-self-reflection 回流，高手由 ray-skill-evolve 学习。
