# Ray PPT Refine — PPT 排版美化器（验收 + 改造）

> **定位**：对**已有 PPTX** 做排版美化——检测排版问题、批量修复、一键换肤。**只动排版，不动内容**。与 `ray-ppt-generator` 正交互补（详见文末「与 ray-ppt-generator 的关系」表）。

## 四条铁律（先于一切流程）

1. **只动排版，不动内容结构**。能改的：字体、字号、颜色、配色、对齐、间距、缩进、元素位置、版式布局。**不能改的**：页数、标题文字、观点、正文内容、逻辑顺序——那是内容，归作者/generator 管。
2. **失同步必提示，不另造演讲稿**。若美化必须改动结构（拆页/合并页/改标题），先停下警告："这会破坏演讲稿/备注的逐页同步"，用户确认后才动；演讲稿由 generator 单源产出，本 skill 不生成演讲稿。
3. **视觉 QA 驱动，不信代码信图片**。代码证明"结构存在"，不证明"版式舒服"——**先转图片逐页看诊断，修复后再转图片复验**，至少一轮 fix-and-verify。
4. **主要文字必须可编辑**（v2.1.0 新增）。美化后交付的 PPTX 必须保持：主标题/副标题/正文/关键数字/图表标签/页脚说明都在 **PPT 原生文本框**里，可被用户直接编辑；**不得**把文本转图片、不得把整页合成为一张图、不得为了"视觉效果"牺牲可编辑性。装饰性图形（logo、复杂插画、照片背景）可以是图片，但**信息层必须是文本**。判定红线：`pictures=0` 不是目标，但 `text_as_picture > 0` 就是失败。

## 常见崩坏模式（每次 refine 前必读，先于 5 步流程）

> 告诉 AI 要做什么效果一般，告诉它前人最容易在哪里塌效果更好。以下三种反模式均在真实执行中复现过，每次必须主动警惕。

### 反模式 1：口头宣布"美化完成"（最常见）

**错误做法**：
> 「4 页样张已完成美化，配色统一、字体一致，可以批量化了」（没跑任何脚本，没转任何图）

**问题所在**：判断"美化完成"的依据是 AI 自己的观感，不是程序输出、也不是 VL 核验。无论理由多充分，这句话都是 AI 在给自己写完成证书。

**正确做法**：
1. 执行 `python scripts/refine_gate_check.py <refine后pptx路径> <诊断json>`
2. 读取 `<工作目录>/refine_gate_result.json`
3. 只有 `"passed": true` 时才能进入批量修复 / 交付
4. 如果 `"passed": false`，按 `user_code_errors[]` 修复后重跑

> **当前模型无多模态（读不了 PNG）时**：视觉核验走 `ray-ppt-ocr-eyes` 降级链路（OCR+VL 逐页描述），见 `references/refine-toolkit.md` 第 2 节末尾——**链路存在 ≠ 可以跳过，"模型看不了图"不是跳过视觉 QA 的理由**。

---

### 反模式 2：跳过样张直接批量改 100 页

**错误做法**：
> 拿到 95 页 PPT，直接对每个页面跑统一字号缩放 + 统一字体替换，跑完才发现页脚被放大 / 卡片页被撑爆 / 表格列宽重排。

**问题所在**：每条规则都有边界（页脚白名单、卡片页排除、表格只换字体），这些边界要在样张上验证，不能在全量上裸跑。

**正确做法**：
1. 先选 3-5 页**代表性样张**（封面/章节页/典型内容页/表格页/卡片页各一），跑完整 refine 流水线
2. 对样张转图 VL 核验 + 跑 `refine_gate_check.py`，全部通过才进入批量
3. 批量时分页类型排除不适用规则（见「四条铁律」第 4 条 + 常见坑表）

---

### 反模式 3：默认"既然是美化就该全换"，不先问体系

**错误做法**：
> 用户说"美化一下"，直接做 2 轮样张（纸张手绘风→照片灰度化），用户看完才说"化工蓝体系更清爽，保留现有体系只补图"。

**问题所在**：「美化」是个有歧义的词——可能是「换配色体系」「换版式体系」「保留体系补手法（线语言/插图/留白）」三种之一。AI 默认第一种，用户往往想要后两种，导致 N 轮返工。

**正确做法**：
1. **Step 3 诊断确认前必问**：「**换体系 or 保留现有体系补手法？**」
2. 换体系 → 走「一键换肤」（6 套通用 + 化工安全配色）
3. 保留体系补手法 → 走 design-languages/INDEX.md 三因子匹配（差距 0.5 + 内容 0.3 + 偏好 0.2）从 8 类设计语言里选补充手法
4. 用户明确说"看着办"再走推荐路径，并明示推荐理由给用户否决权

## 何时用 / 何时不用

| 该用 | 不该用 |
|------|--------|
| 有一份 PPTX，排版粗糙要美化 | 从零生成 PPT（用 ray-ppt-generator） |
| 统一字体/配色/风格（换肤） | 改内容、改文字、加页删页（内容问题） |
| 修复文字溢出/元素重叠/对齐 | PPT 内容本身要重写（回 generator 或手动） |
| 把默认蓝/AI 痕迹改成专业版式 | 需要联网检索补内容（那是 generator 的活） |

## 工作流程（5 步）

```
备份 → 视觉QA检测 → 诊断清单（用户确认）→ 批量修复 → 复验交付
```

### Step 0：备份（强制）

改任何已有 PPTX 前，先复制备份：`<原名>_backup.pptx`。Win32COM 修改不可逆，备份是后悔药。

### Step 1：读取解析 + 模式选择（沿用模板 vs 重新设计）

用 python-pptx 打开，遍历 slides/shapes/text_frames，摸清结构：页数、每页元素、字体分布、颜色分布。代码见 `references/refine-toolkit.md` 第 1 节。

**量化诊断阈值（v2.1.0，2026-08-20 新增）**——Step 3 诊断确认时按阈值自动判定，不再依赖描述性语言：

| 检查项 | 阈值（失败即触发） | 说明 |
|--------|-------------------|------|
| 字体不统一 | 字体 Top1 占比 **<70%** | 主字体不是 Microsoft YaHei → 需批量统一 |
| 配色混乱 | 主色在可见 shape 填充中占比 **<40%** | 无主导色；含默认 Office 蓝 `#0000FF` → 建议换肤 |
| 字号过小 | 9-11pt 字号在正文 run 中占比 **>30%** | 小字太多 → 需分档缩放（映射表见 refine-matrix.yaml） |
| 字号过杂 | 字号种类 **>6 种**（排除页脚） | 层级过多 → 建议分档收敛到 4-5 级 |
| 行距异常 | 段落 line_spacing 均值 **<1.2 或 >2.5** | 行距太紧/太松 → 批量调 spacing |

```python
# 量化诊断示例（Step 3 确认前跑）
fonts = Counter()  # 所有 run 的字体
font_colors = Counter()  # 所有可见 shape 的填充色
body_sizes = Counter()  # 正文字号（排除页脚白名单）
for slide in prs.slides:
    for shape in slide.shapes:
        # ... 统计逻辑

top1_font_ratio = fonts.most_common(1)[0][1] / sum(fonts.values()) if fonts else 0
if top1_font_ratio < 0.70:
    diagnostics["font_consistency"] = {"status": "fail", "top1_ratio": top1_font_ratio}
```

阈值细节见 `references/refine-matrix.yaml`。

**模式选择（必做，美化的第一个决策）**——问用户：

| 模式 | 做什么 | 适用 |
|------|--------|------|
| **沿用模板** | 只优化内容排版——修溢出、统一字体/字号、对齐、图表配色对齐模板色系；**不动母版、页眉页脚、背景、Logo、主题色等全局元素** | 已有品牌模板，只需优化内容 |
| **重新设计** | 含模板在内的整体视觉重塑（走下方"一键换肤"） | 无模板 / 模板太丑，要整体升级 |

> 拿不准时默认"沿用模板"——保守改造，不动全局元素。用户明确要换风格才走"重新设计"。

**设计语言匹配（v2.0 新增，选"重新设计"时必做）**——读 `references/design-languages/INDEX.md`，按三因子加权（差距 0.5 + 内容 0.3 + 偏好 0.2）推荐 2-3 套设计语言让用户选：

```
1. 提取目标 deck 版式特征（标题栏样式/列表页占比/卡片存在性/章节页样式/插图风格）
2. 与 design-languages/ 各档案的「特征指纹」比对 → 差距越大改造价值越高
3. 内容类型匹配（培训课件→B卡片徽章/A手绘线；技术汇报→C大数字/D深色科技；公文→E政务；事故→A时间线）
4. 用户偏好修正（"化工蓝体系更清爽"→偏好保留体系补手法；历史选过 +10 分）
5. AskUserQuestion 推荐 2-3 套让用户选（铁律：用户说"美化"≠要换体系，先问）
```

选定后：读该语言 `profile.md`（特征/改造路径）+ 看 `layouts/*.png` 样板 + 用 `palette.json` 配色 token + 复用 `assets/` 素材。

### Step 2：视觉 QA 检测（核心）

**用 `export_slides_to_images()` 把每页导出 PNG，逐页看**——不要只信解析数据。同时跑排版扫描器自动初筛。产出"问题清单"。检测维度见下「诊断模式库」。

### Step 3：诊断清单 → 用户确认改造方案

把检测到的问题整理成清单，按优先级排列，**给用户确认改造范围再动手**：

```
发现 N 处排版问题：
🔴 严重：3 页文字溢出（P3/P7/P12）、全 deck 字体不统一（宋体混入）
🟡 建议：配色默认蓝无主题、5 页元素未对齐
🟢 可选：标题层级可再拉开
改造方案：①统一微软雅黑 ②应用[商务深蓝]配色 ③修复溢出页 ... 确认？
```

**杠杆收敛（v2.2.0 新增，外部对比吸收）**：诊断清单可能列出 10+ 项，但**汇报只挑 3-5 个最大改造杠杆**（对观感提升贡献最大的项），其余归入"次要项（可后补）"一句话带过。原因：清单过长会分散用户注意力、拖延确认；多数时候 3-5 个杠杆改完 deck 已质变，次要项用户会主动要求补。**判断口诀**："改完这 3-5 项，用户会明显觉得'好多了'吗？" 不会 → 杠杆没选对。

### Step 4：代表性页面预览 → 批量修复

**先做样张再批量**（降低返工）：不一次性改全部——先改 3-5 页**不同类型**的代表页（文字信息页 / 数据图表页 / 结论汇总页），转图给用户预览，确认风格对味后，再用 Win32COM 批量执行剩余页（保留渐变/阴影等效果，python-pptx 重排会丢效果）。修复方法见 `references/refine-toolkit.md` 第 3-5 节。

### Step 5：复验交付（⭐ 机读化门禁，v2.1.0）

> **核心原则**：门禁必须机读化（学 Mck gate_check），AI 不得口头宣布"QA 通过"。

1. **先跑门禁脚本**（必须，不得跳过）：
```bash
python ~/.workbuddy/skills/ray-ppt-refine/scripts/refine_gate_check.py \
    <refine后pptx路径> <诊断清单.json> --outdir <工作目录>
```
2. 读取 `<工作目录>/refine_gate_result.json`：
   - `"passed": true` → 进入转图复验
   - `"passed": false` → 修复 `user_code_errors[]` 列出的问题，重跑门禁
3. **转图 VL 核验**（门禁覆盖不到的视觉层面：色感/留白感/设计感）
   - 重跑 Step 1 的 `export_slides_to_images()` 导出**受影响页**，逐页复验——一个修复常引入新问题
   - 重点看：样张一致性、新字体渲染效果、配图协调性、档位/卡片/警示条风格统一
4. 门禁 + VL 全绿才交付；回 Step 4 再修一轮（最多 2 轮，2 轮仍有问题说明要拆方案 B 重写脚本）

## 排版问题诊断模式库

| 问题模式 | 检测方法 | 修复方法 |
|---------|---------|---------|
| **文字溢出** | 文本框文字多/未 word_wrap；图片中文字顶到边框 | 启用 word_wrap、缩字号、框加大、或拆栏 |
| **字体不统一** | 扫描 run.font.name，统计非微软雅黑（宋体/Calibri 混入） | Win32COM 批量统一 `Microsoft YaHei` |
| **配色混乱** | 颜色种类过多 / 默认蓝 / 无主色 | 一键换肤：应用配色方案库（主色 60-70%） |
| **层级不清** | 标题正文同字号 / 无灰阶 | 拉开字号对比（标题大、正文小），用灰阶分主次 |
| **对齐/间距** | 元素左边缘不齐 / 间距忽大忽小 | 统一左对齐、间距 ≥0.3"、边距 ≥0.5" |
| **元素重叠** | 图片中文本框/形状碰撞 | 移位、调层级、缩尺寸 |
| **AI 痕迹** | 标题下装饰线 / 全 deck 重复同一版式 / 纯文字页 | 删装饰线、变化版式、加视觉元素 |
| **图片问题** | 越界 / 比例失调 / 与页脚碰撞 | 等比缩放、归位、避开页脚区 |
| **图标素材来源**（v2.5 新增） | 需要"小图标/徽章"却不知道该去哪拿：iconfont 主力格式是 **SVG，python-pptx 原生不支持**（实测 add_picture 对 SVG 抛错），venv 无 cairosvg/svglib | ①单色简单语义图标（盾牌/警报/齿轮）→ iconfont 下 **PNG**（透明底）直接做图标池，或拆 SVG path 用 FREEFORM 重绘（保矢量可编辑）；②多色复杂插画 → 走 ImageGen/图库，不从 iconfont 硬取；③图标字体（iconfont 前端玩法）python-pptx 无字形支持，不用。完整能力边界见 generator code-templates 2.25 |
| **图文不协调** | 图片与内容无关（如化工安全页配沙滩风景）/ 图上有 AI 乱码文字 / 图风格与全 deck 不统一（卡通+写实混搭）/ 图遮正文或压字对比度不足 | ①内容无关→**提示用户换图（给建议，不自行换——换图是内容决策，归 generator）**；②AI 乱码字→裁掉文字区或建议重生成（无文字版）；③风格混搭→统一为同一风格；④压字→加半透明蒙版或移位 |
| **图表混乱** | 图表带网格线 / 系列颜色杂 / 数据标签挤 | 去网格线、统一配色、只突出关键数据系列 |
| **重点淹没** | 核心信息和普通信息一个样 | 识别关键信息，用加粗/放大/强调色突出，引导注意力 |
| **线性元素缺失**（v1.2 新增） | 统计细长形状/箭头/横线数量：时间线/流程/事件链页**无线元素**（轴线/连接线/分隔线）→ 视觉"块状呆板" | 补"线"语言：细长矩形（宽>>高）做轴线/分隔线、箭头连接流程节点、虚线引导阅读路径。参考高手版手法：447 个细长 freeform（高均 0.3"）构建线性节奏 |
| **版式单调**（v2.3 新增） | 连续 3+ 页都是"标题+列表块"；内容类型与版式不匹配（时限内容用列表、分级内容用表格） | 按**内容类型换版式**（6 个实战验证手法，源码在 generator code-templates 2.16-2.21）：硬时限→横向时间轴（时限徽章+轴线+说明卡）；目录/职责/要点→卡片矩阵（左色条+数字圆点）；DO/DON'T→红绿灯对比（左绿右红+中央信号灯）；梯度考核→热力图表格（整行绿→红底色）；分级上报→双通道地铁图（每通道一条线+站点）；级别划分→阶梯图（台阶逐级升高）。这是"美化改结构"的最大杠杆 |
| **图形隐喻半成品**（v2.3 新增） | 页面声称"环形流程/循环"但节点间无连线箭头（视觉=散点）；旋转椭圆拼花/拼人形等复杂隐喻造型生硬 | 二选一：①补全连接语言（弧形箭头/循环连线）让隐喻成立；②**退回朴素布局**（条带/步骤条）——隐喻做一半不如不做。复杂有机造型（花瓣/五角）不推荐：python-pptx 旋转椭圆拼贴效果生硬 |
| **配色微调无感**（v2.3 新增） | 换肤用了邻近色（如 #005293→#0D3B66），用户第一眼"看不出变化" | 换配色要么拉开色相/明度差距（蓝→绿/深蓝→暖灰），要么先问清意图：用户要"变个样子"就拉大差距，要"更沉稳"就保留体系只补手法（铁律 3 的量化版） |
| **重排不减密**（v2.3 新增） | 美化轮把原页文字原样塞进新图形（卡片/时间轴/阶梯），信息密度不降，用户评"换汤不换药/效果一般" | 重排必须伴随**减法**：每页先定"主角"（3 秒内先看到的一个图形/数字/大字），描述文字砍 30%，次要信息下沉为小字或页脚。高手版式的本质是"每页一个主角+大量留白"，不是"新形状装旧内容" |
| **网格失准**（v2.4 新增） | 元素间"说不上来的乱"：对齐看起来差 1-2px、间距忽宽忽窄、徽章与文字框错位——dump 坐标发现离散（如 315 个不同坐标值，仅 4% 落在常见倍数上） | **对齐到 20pt 设计网格**（0.278" 基准格，页边距 40pt=2 格、卡片间隙 8-10pt=半格）：改版式/新增元素时坐标一律取网格倍数；字号同步取整（无 10.8/12.5 小数档）。验证：重读文件统计坐标网格命中率，目标 ≥60%（手法已回 generator 2.22 gx(n) 函数） |
| **插图风格未统一**（v1.2 增强） | 有图但风格混搭 / 彩色图与全 deck 冷色系不协调 | **统一灰度/滤镜是排版范畴修复**（PIL 灰度化即可，不动图内容）：全 deck 图片统一灰度或同一色调后，视觉立刻统一。高手版 51 张图全部灰度处理（含封面/分区页全页背景图 + 要素页固定位置插图） |

> 判断口诀：**先严重后建议——溢出/字体/配色是硬伤，对齐/层级/痕迹是提升，线/图是质感**。

## 设计哲学：AI slop 反模式警告（v1.4 新增，吸收 GH 27k 星 frontend-slides）

> 模型默认会收敛到**平庸的通配设计**（"AI slop"审美）——美化前先认通病，再给对策：

| 通病（默认会犯） | 对策（要主动做） |
|------------------|------------------|
| 均匀配色、无主色 dominance | 主色占 60-70% 视觉权重，1-2 辅色 + 1 强调色，绝不平均分配 |
| 居中排版的"填充感" | 正文左对齐（只有标题/封面居中）；不整页纯文字 |
| 默认蓝 / 无主题色 | 从主题文化/行业汲取配色（化工→安全蓝/纸张手绘风），不用默认值 |
| 为装饰而装饰（角部图案/无意义图形） | 每个视觉元素服务信息层级，删掉会让页变差的才留 |
| 同质化重复版式 | 全 deck 不重复同一版式；每页至少一个差异化视觉锚点 |

**自检**："这页删掉任何一个元素会变差吗？" 不会 → **删掉**（减优于加）。

### 配图落地三坑（v1.3 新增，实战验证 2026-08-17）

> 给已有 deck 配图（灰度照片/插图）时的高频坑与解法：

| 坑 | 现象 | 解法 |
|----|------|------|
| **横向图进竖框留白大** | 1200×800 照片放进 3.3×4.4 竖框，按比例缩放后只占 3.3×2.2，上下空 2"+，图显小（用户反馈"图小空白大"） | **装饰插图用 cover 不用 contain**：居中裁成与框同比例再撑满白框（PIL crop），零留白。代码见 refine-toolkit.md「配图工具」 |
| **白框与图片错位** | 白框按"图片缩放尺寸"定位、图片按"传入框"居中——两个基准不一致 → 图片偏下、白框漏底（用户反馈"图片靠下漏白框"） | **单一基准**：先算图片实际位置（框内居中），白框围绕图片实际位置外扩（四边各 0.05"） |
| **插图与相邻元素重叠** | 插图底边 6.65 撞底部说明条 6.35（重叠 0.3"） | 配图后**必跑专项检查**：每张插图底边 vs 底部说明条/卡片标题位置，插图高限按最矮相邻元素预留 0.1"+ |

**配图决策链**：先扫描空白（右半区→网格→精确小区域逐层收敛）→ 有空白直接配 → **无空白不要强行塞图**（会遮内容）→ 改用**布局让位**（公共函数收窄文字宽，批量让出侧边栏）→ 让位后仍验证插图与相邻元素。

### 图片来源决策（v1.5 新增，2026-08-18 三图库实测）

> 配图素材从哪来？按「通用主题 vs 专业主题」分流，**下载图必须 VL 核验**。

| 来源 | 适用 | 实测结论（2026-08-18） | 注意 |
|------|------|----------------------|------|
| **ImageGen 生成** | 专业化工安全主题（受限空间/动火/中毒救援/危化品储存）| 语义 100% 可控、风格统一、竖版 3:4 直接适配 | 每张带"AI生成"水印 → **PIL 裁右下角 8%×6%**；生成后 VL 核验内容防跑偏 |
| **Pexels 下载** | 通用主题（灭火器/安全帽/脚手架/警示牌）| ✅ 可访问；搜 "confined space entry" 有可用免费图（如 7417585 灰度警示牌），但**专业好图在 iStock 付费赞助位**，免费结果混隧道/星空等无关图 | **必须英文关键词**；逐张 VL 核验真实内容（9 张池图 2 张跑偏：可口可乐产线/戴头饰女性）|
| **Pixabay 下载** | 通用主题 | ✅ 可访问；**中文搜索歧义严重**——"受限空间"匹配成"太空/宇宙"，前 10 全跑偏 | 用英文关键词 "confined space" |
| **Unsplash 下载** | 通用主题 | ⚠️ 直连超时，国内访问不稳定 | 不优先 |

**决策规则**：
1. 通用主题（PPE/消防/警示/高处）→ 优先下载图（免费），**逐张 VL 核验**再入映射
2. 专业主题（特殊作业/中毒救援/危化品工艺）→ ImageGen 生成（语义可控）
3. 无论哪条路，**绝不按文件标题猜主题**（P9 错配教训：按 "construction worker" 想当然标高处，实为货仓工人）
4. 风格统一优先：下载照片是彩色实拍，与灰度扁平插画混搭会破坏统一 → 混用时**统一灰度化**（PIL 灰度）

## 一键换肤（配色方案库）

> **换肤前先确认意图（v1.4.1 新增，2026-08-17 实战教训）**：用户说"美化/换肤"不等于要换配色体系——可能只想**保留现有体系补手法**（线语言/插图/留白）。动手做样张前先问一句："换体系 or 保留现有体系只补手法？"（本次实战：连续做了 2 轮样张——纸张手绘风→照片灰度化，用户才说"化工蓝体系更清爽"，若先问可省 2 轮样张）

检测到"配色混乱/默认蓝/无主题"时，推荐换肤。内置 6 套通用 + 化工安全配色（RGB 见 `references/refine-toolkit.md` 第 4 节）。按场景推荐 2-3 套让用户选：

| 场景 | 推荐配色 |
|------|---------|
| 商务汇报/年终总结 | 商务深蓝 / 炭灰极简 |
| 技术分享/产品发布 | 科技深空 / 商务深蓝 |
| 培训课件/教学 | 暖陶简约 / 青绿信任 |
| 化工安全/危化品 | 化工安全配色（SAFE_BLUE 系列） |
| 工程师/技术受众培训 | 纸张手绘风（#F4F2EE 米白 / #9D5A37 棕褐 / #252525 近黑，图纸感） |

换肤 = 批量替换主色/辅色/强调色 + 标题栏/页脚配色，**不动内容文字**。

## 常见坑与排查

| 问题 | 原因 | 解决 |
|------|------|------|
| Win32COM 改完效果丢失 | python-pptx 重写会丢渐变/阴影 | 用 Win32COM 修改，不用 python-pptx 重排 |
| 颜色没改成 | `.RGB` 是 BGR 顺序 | 用 `rgb_to_bgr()` 转换 |
| COM 索引报错 | COM 索引从 1 开始，非 0 | 遍历从 1 起；`True = -1` |
| 文件被占用无法写 | 直接改被打开的文件 | 先关 PowerPoint；先写临时文件再替换 |
| `'method' object is not iterable`（COM 遍历文本） | `TextRange.Paragraphs` / `Paragraphs(pi).Runs` 是方法不是属性 | 必须带括号调用：`tr.Paragraphs()`、`Paragraphs(pi).Runs(ri)`，索引从 1 开始（0 越界） |
| bash 内联 Python 改 PPT 路径失效 | bash 吞掉反斜杠：`D:\Work` 变 `D:/Work` | COM 工作流一律用独立 `.py` 文件（Write 工具写盘再执行），不用 `python -c` 内联 |
| `os.remove` 报 `SAFE_DELETE_FAIL_CLOSED` | 沙盒回收站不可用，删除 fail-closed 拒绝 | 不删旧文件，直接 `SaveAs` 覆盖目标路径 |
| 批量改字号把页脚/页眉改坏 | 页脚页眉也是文本 shape，被统一缩放规则命中 | 先按文本内容（"Rianlon"/"Page"/页码）识别页脚页眉元素，白名单排除；页眉标签单独给较小增量 |
| 表格字号缩放变形 | 表格单元格用 `tr.Paragraphs(pi).Runs(ri)` 遍历，直接改 `.Size` 会触发列宽重排 | 表格只换字体不换字号；字号缩放仅对普通文本框生效 |
| 改完演讲稿对不上 | 动了页数/标题 | 违反铁律 2——应提前警告，已改则提示回 generator 重导 |
| **横向图进竖框留白大** | contain 缩放（按比例）在竖框上下留白 | 装饰插图用 **cover**（居中裁切撑满框），见「配图落地三坑」 |
| **白框与图错位** | 白框基准与图片居中基准不一致 | 白框围绕图片实际位置外扩（单一基准） |
| **插图撞底部条** | 插图底边 > 相邻元素顶部 | 插图高限按最矮相邻元素预留 0.1"+ |
| **批量注入参数错位**（banner 插进函数参数列表 / icons 注入错页） | 跨行正则 `.*?\)` 在多行函数调用上不可靠，插入点定位错 | 用**括号深度匹配**定位完整调用块（`p\d+ = 函数名\(` 起，数括号找配对 `)`），再精确 Edit；注入后跑一致性核对脚本逐页比对 |
| **徽章与右侧竖图同页重复** | 图标池与 PAGE_ILLU 右侧图共用同一资产池 → 同页出现 0.55" 徽章 + 3.7×5.2" 大图同图 | 替换右侧竖图（约束：不在本页 icons + 不与前后页大图重复）；QA 按"同页 sha1 重复"判定，跨页徽章复用放行 |
| **banner 与内容重叠** | banner 默认 bottom 但内容区满 | 先量内容区底边 y，banner pos='bottom'（y=6.45 高 0.4）或 pos='top'（y=1.18 高 0.3）二选一，间隙 ≥0.02" |

## 卡片图标徽章 + 通栏警示条（v1.5.4 新增，Plan C 实战）

**图标徽章（E7）**：给卡片加 1:1 方形照片徽章，形成"徽章+标题+描述"卡片语言。
- 零外部资源：用现有灰度写实方形图（1024×1024）直接缩略即可；白底圆角衬垫 0.61" + 照片 0.55"（衬垫外扩 0.03"）
- 布局避让：有徽章时标题右移（x=徽章右+0.15"）、描述下移（y+0.72"）；无图标时回退原位（标题 x+0.35"、描述 y+0.62"）
- **注入方式**：`cards()` 加 `icons=[...]` 参数（路径列表与 items 等长）；映射表单独存 JSON（页→每卡图标 key），脚本读取注入
- **同池冲突红线**：徽章图标池与右侧竖图（PAGE_ILLU）共用资产时，同页必出现"大图+同图小徽章"——右侧竖图自动替换（不在本页 icons + 不与前后页大图重复 + 语义分组优先）

**通栏警示条（E8）**：关键警示页加全宽色条（白字加粗居中），比普通文字醒目。
- `banner()` 双位置：`pos='bottom'`（y=6.45 高 0.4）用于底部有空间页；`pos='top'`（y=1.18 高 0.3）用于内容满页（先量内容区底边，防重叠）
- 配色遵循功能分色：RED=警示、ORANGE=注意

## 反例黑名单（❌ 不要做）

❌ 改内容——页数/标题/观点/正文文字（那是内容，归作者 / generator）
❌ 用 python-pptx 重写排版——会丢渐变/阴影效果，改用 Win32COM
❌ 不备份就改——Win32COM 不可逆，先 `_backup.pptx`
❌ 只信扫描器不看图——数据给线索、图片给真相，修复后必须转图复验
❌ 改结构不警告——动了页数/标题却不提示演讲稿失同步
