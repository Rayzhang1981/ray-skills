## Step 3：要点提炼（故事链逻辑）

将检索内容结构化为**故事链**，适配信息图版面：

```
① 是什么（定义 + 核心特征）
② 为什么重要（危险性 / 事故后果 / 法规要求）
③ 怎么做（控制措施 / 设计要点 / 操作步骤）
④ 红线（重大隐患判定条款 / 禁止项）
```

**故事线 pitch（可选，内容有多个叙事角度时用）**：当素材可支撑 ≥2 种截然不同的叙事（如"后果有多严重" vs "防线怎么建" vs "新规变了什么"），先给用户 2-3 个候选角度（含推荐）让用户选；单一角度明显时直接走默认故事链，不问。

**数据真实性铁律（不可违反）：**
- **禁止编造统计数字**：所有数字必须来自检索结果或用户提供；检索不到的定量数据宁可不放，不得凭印象填数
- **定性/法律断言不得超出原文**：图解配文不得添加原文没有的法律后果、处罚、时限断言（如"构成犯罪""罚款 X 万"）——读图人会把它当原文引用（2026-09-29 实证：自审抓掉配文里原文没有的"构成犯罪"）
- **示例性数值必须标注**："示例"、"示意" 等字样标明非真实数据
- **数字人性化格式**：12.4 万而非 124000；单位必须展示（t/a、kPa、%）
- **法规条款号必须精确**：AQ 3067 条款引用要与原文核对，错一条即全图失信

**信息密度判断：**
- 稀（≤50字）→ 一个巨大锚点元素
- 中（50-200字）→ 2-3个区块，有主有次
- 密（200+字）→ 多区块网格，实验室手册感 ← **化工安全类多用此档**

## Step 3.5：竖版/横版决策

在要点提炼完成后、渲染前，根据内容规模判断使用竖版还是横版。

### 决策三要素

| 维度 | 竖版阈值 | 横版阈值 |
|------|---------|---------|
| **核心卡片数**（不含 Hero/Footer） | ≤4 张 | **≥5 张** → 横版 |
| **信息区块类型数**（概况/时间轴/违规清单/措施/处罚记录/调查组/金句等） | ≤3 种 | **≥4 种** → 强烈建议横版 |
| **预估单列总高度**（1080px 宽 × 竖版） | ≤3000px | **>3000px** → 横版 |

### 主题类型自动偏向

| 主题类型 | 默认方向 | 说明 |
|---------|:------:|------|
| 事故分析类（A）+ 包含违规/处罚清单 | **横版** | 信息层次多（概况→经过→原因→违规→措施→处罚→调查组），竖版必然超长 |
| 事故分析类（A）纯时间轴（无违规清单） | 竖版 | 如"XX泄漏"/"XX火灾"，4 段以内时间轴竖版即可 |
| 工艺安全类（B） | 竖版 | 典型结构：定义→危险性→措施→红线，正好 4 张卡 |
| 制度标准类（C） | 竖版 | 典型结构：标准信息→核心条款→关键变化→实施，4 张卡 |
| 用户明确要求"横版"/"太长，改横版" | **立即出横版** | 不犹豫 |

### 横版画布与字体规范（16:10，1920×1200）

布局：三列等宽 grid（`1fr 1fr 1fr`），列间距 24px，每列 2 卡竖排（`flex-direction:column; gap:18px`）；Hero 左文字+右统计数字（flex）；底部横跨区金句+调查要求并排（`flex:1; gap:20px`），置于三列后、Footer 前。

字体（列宽约 600px，相对竖版整体缩小但保可读）：Hero 标题 60-68px / 统计数字 56-64px / 卡片标题栏 22-25px / 列表正文 20-22px / 时间轴·违规条 18-19px / 底部标语 30-34px。

### 决策流程

```
Step 3 要点提炼完成
    ↓
卡片数 ≥5？ ──是──→ 横版（16:10）
    ↓否
区块类型 ≥4 种？ ──是──→ 横版
    ↓否
事故分析类 + 有违规清单？ ──是──→ 横版
    ↓否
竖版输出 (1080px 宽)
```

3. 化工安全类内容更适合专业、清晰的浅色风格

### 主题专项布局指引

不同化工安全主题适合不同的布局模式。根据关键词自动判断并选择：

**类型 A：事故分析类**（关键词含"事故""调查""XX爆炸""XX泄漏"等）
- **推荐结构**：时间轴（accordion 或 step 列表）
- **布局模式**：
  1. 顶部：大标题 + 事故基本信息卡片（蓝底白字标题栏）
  2. 事故经过：**橙色标题栏卡片**，内含时间轴或流程图
  3. 原因分析：**红色标题栏卡片**，分"直接原因""间接原因""管理原因"三个子区块
  4. 防范措施：**绿色标题栏卡片**，列出整改建议（图标化列表）
  5. 底部：**深蓝底收尾条**，配金句标语
- **色彩方案**：蓝色（概况）→ 橙色（经过）→ 红色（原因）→ 绿色（措施）→ 深蓝底收尾

**类型 B：工艺安全类**（关键词含"硝化""氯化""HAZOP""LOPA"等工艺或分析方法）
- **推荐结构**：彩色标题栏卡片组（定义→危险性→控制措施→法规红线）
- **布局模式**：
  1. 顶部：大标题 + 工艺定义卡片（蓝底白字标题栏）
  2. 危险性分析：**红色标题栏卡片**，内含"爆炸类型""事故后果"等图标化列表
  3. 控制措施：**蓝色标题栏卡片**，分"工程控制""管理控制""应急措施"三个子区块，各配图标
  4. 法规红线：**红色标题栏卡片**，列出重大隐患判定条款（用红色圆圈编号）
  5. 底部：**深蓝底收尾条**，配金句标语
- **色彩方案**：蓝色（定义/措施）→ 红色（危险性/红线）→ 绿色（合规/通过）→ 深蓝底收尾

**类型 C：制度标准类**（关键词含"AQ""标准""规定""条例"等）
- **推荐结构**：彩色标题栏卡片组（标准信息→核心条款→关键变化→实施要求）
- **布局模式**：
  1. 顶部：大标题 + 标准编号（深蓝灰文字，关键词用红色高亮）
  2. 标准信息卡片：**蓝色标题栏**，内含标准编号、生效日期、适用范围（图标化列表）
  3. 核心条款：**非对称网格**，重要条款用大卡片（红色标题栏），次要条款用小卡片（蓝色/绿色标题栏）
  4. 关键变化：**橙色标题栏卡片**，列出与旧版对比（可用↑↓→符号表示变化方向）
  5. 实施要求：**绿色标题栏卡片**，列出企业需采取的措施（图标化列表）
  6. 底部：**深蓝底收尾条**
- **色彩方案**：蓝色（标准信息）→ 红色（核心条款/重大变化）→ 橙色（关键变化）→ 绿色（实施要求）→ 深蓝底收尾

**类型 D：多类并列对比**（v2.8 新增；内容为「N 类 × M 维」矩阵：演练类型／作业许可类型／隐患等级等 ≥3 类并列、各类字段结构相同）
- **推荐结构**：Hero 数据锚点 + 彩色标题栏卡片组 + 深色收尾条
- **布局模式**：
  1. Hero 区：标题 + **关键频次/数字锚点块**（每类一个：大号数字 + 单位 + 小注，头版可见——最 actionable 的信息不得藏进卡片或表格）
  2. 主区：每类一张**彩色标题栏卡片**（蓝/橙/绿/红四色分级，标题栏右侧胶囊徽章放该类频次），卡内按维度行展开，每行配 SVG 图标 + 色块标签
  3. 侧列或下带：横向对比区（如"N 种形式怎么选"），编号列表卡
  4. 底部收尾**双轨**：深色条金句（给岗位员工）+ 法条依据/闭环要求（给检查者）
- **⚠️ 不用大表格**：表格是「文件形态」，同类并列对比用表格会丧失「图」的扫读性（2026-10-01 应急演练明白卡实证：同素材表格版被卡片版在美观度上明显反超）；**≥6 列纯参数矩阵才回到表格**
- **画布按用途定**：打印上墙 → A4 比例（横版 1920×1358，1:1 打印无留边）；纯屏显 → 16:10（1920×1200）；接单时先问一句用途

**字体规范（手机端可读）：**
- 最大元素：80-108px（作为"地形"，不只是文字）
- 标题：60-80px
- 正文：≥36px（手机上约 12.9px）
- 标注 / 来源：≥24px（手机上约 8.6px）
- 行高：≥1.6
- 最大:最小 ≥ 10:1

**90/8/2 色彩法则：**
- 90% 中性色（--bg + --ink 文字）
- 8% 结构色（--green 一个区块或色条）
- 2% 弹点色（--pink，**整张图仅 1-2 处**）

**反死亡清单（必须检查）：**
- [ ] 弹点色用了 >2 处 → 减少到 2 处以内
- [ ] 所有文字都在 30-44px 区间 → 需要有 ≥10:1 的大小对比
- [ ] 三列等宽布局 → 改为 2fr+1fr 或非对称网格
- [ ] 正文字号 <36px → 调到 36px 以上
- [ ] 换一个主题，这个布局还说得通 → 如果是，说明做的是模板而非设计
- [ ] **盖上文字认不出主题** → 视觉隐喻失败：图形/构图应独立传达"这是关于什么的安全话题"，而非纯文字排版
- [ ] **缺少顶部预警条** → 安全主题必须有视觉警示元素
- [ ] **全浅色无层次** → 用左边条（色条）、浅色背景块（#F8F9FA）、SVG 图标建立层次，**不用大面积深色底**
- [ ] **法规编号/分类名称纯文字** → 改为标签/徽章形式
- [ ] **信息图底部无收尾** → 添加统计条或金句引用
- [ ] **卡片无图标装饰** → 每个要点卡片配 SVG 内联图标（v2.8 强化：推荐四件套——人形/双人/靶心/清单，一套 26px 线稿覆盖多数卡片行；绝对定位或仅 CSS 尺寸的 svg 必须走 rasterizeIcons 栅格化，见 rendering-pitfalls.md v2.6.0 节。**勿因导出风险干脆不用图标**——那会退回「文件感」排版）
- [ ] **事故分析类用了网格布局** → 改为时间轴/事件链布局
- [ ] **多种信息类型无分类标签** → 添加彩色分类标签 + 图例
- [ ] **图标列表用了 flex 布局** → 改为 `display:block; position:relative` + 图标绝对定位，防止中文竖排
- [ ] **`<strong>` 标签在窄空间被压成竖排** → 加 `display:inline-block; white-space:nowrap`
- [ ] **彩色标签/徽章文字竖排** → 加 `white-space:nowrap`；4字以上标签用 `<br>` 手动断行（如"先兆<br>中暑"）
- [ ] **grid 三列等宽内有中文标签** → 改为 `flex` + `min-width` + `white-space:nowrap`

```python
PROMPT = (
```

检索不到的定量数据不放，不得凭印象编造（编造的数字模型照画，且更难校对）。

### 默认参数（承接 wuyin-image A/B 实测结论）

| 参数 | 默认 | 依据 |
|---|---|---|
| model | `sunburst` | 版式分栏利用优于 flare 的全宽堆叠 |
| quality | `high` | max 档实测页脚多一字；档位高 ≠ 文字可靠 |
| size | `2:3`（1024*1536） | 信息图竖版标准比例 |

### B 通道交付门

不得带错交付。安全内容无来源标注 = 可信度归零，署名与来源标注沿用 Step 5 要求。

## 混合模式：AI 局部素材 + HTML 排版（v2.7 新增 · 层 2 专用）

定位：高密度信息图（≥4 节）既要 AI 的视觉活泼、又要 HTML 的排版精准时用。
分工铁律：**ray-concept-image 只出局部素材，排版与全部文字由本 skill HTML 层负责**——AI 不再直接出整图（高密度整图版式失控，2026-09-29 粉尘燃爆图实证：素材风格混杂 / 版式均质 / 文字密排）。

### 四步数据流

```
① AI 局部素材（ray-concept-image generate_image 批量出图）
    ↓
② 素材清单协议（逐张登记比例/底色/风格）
    ↓
③ HTML 排版嵌入（img 卡片化融合）
    ↓
④ 双门验收交付（门 1/门 2 照走 + 逐字校对）
```

### ① 素材生成

先列素材清单再逐张生成（**禁止整图一把梭 prompt**）。调用方式沿用 B 通道的 `generate_image()` 模块调用：

| 素材 | 比例建议 | 底色约定 | 内容 |
|---|---|---|---|
| hero 主视觉 | 与画布区配（如竖版头图 2:1 横幅） | 与主题色一致纯色底 | 主题场景（设备/事故隐喻） |
| 分节配图 ×N | 1:1 或 4:3 | 纯白底 | 每节一个视觉锚点 |

**风格锚点词**（每张 prompt 都带，保证多图风格统一）：
`统一插画风，{主题配色}，扁平工业风，简洁线条，无文字，无边框`

**素材图内禁止出现任何文字**——文字全部由 HTML 层负责。这是混合模式相对 AI 整图的核心优势：文字零错、随时可改。
参数策略：素材无文字 → 起步 `flare + medium`（快速试错买时间），不满意再 `sunburst + high`。

### ②③ HTML 嵌入要点

- `<img src="assets/xx.png">` 引用本地素材；PNG/JPG 是合法 CanvasImageSource，**html2canvas 直接支持，无 v2.6.0 内联 SVG 那组坑**
- 素材按「图片卡」融合：圆角 + 阴影 + 与底色约定呼应；hero 可作 header 背景配半透明遮罩承标题
- 素材文件与 HTML 同目录 `assets/` 子目录；需单文件交付时 base64 内嵌（注意体积膨胀）

### ④ 验收

门 1 / 门 2 照走；逐字校对对象从整图变为 HTML 文本层（错字率天然为零，数据与条款号仍须校对）；素材对照清单逐张核风格锚点词（跨图风格漂移 = 重生成该张）。

## Step 5：输出与交付

**⚠️ 交付双门（未过双门不得交付）：**

**门 1·渲染前机械预检**（HTML 写完后逐项过）：
- [ ] 无文字重叠/溢出容器/被裁剪（重点：标签、徽章、时间轴节点）
- [ ] **内部区块无相互重叠**（v2.8 新增）：固定高画布 + flex/grid 下内容总高超限时，溢出发生在**内部区块之间**（如表格被压缩、末行徽章被下一节标题压住），画布级 bbox 溢出检测**查不到**——量测脚本须加兄弟节点 bbox 相交检测（2026-10-01 实证：画布零溢出仍漏检，靠门 2 目测抓到、三轮迭代才收敛）
- [ ] 无字号低于可读下限（正文 ≥36px 竖版 / ≥18px 横版）
- [ ] 无内容逃出画布边界；底部不留半空尴尬区
- [ ] 三大高危写法已排除（nowrap+inline-block / var() 短属性 / linear-gradient，详见 references/rendering-pitfalls.md）
- **无头浏览器实测（Playwright 本机可用，路径与姿势见「已知问题与限制」表）**：量测字形几何 + 实测 html2canvas 导出（含画布尺寸与 toBlob 字节数）——"浏览器能看 ≠ html2canvas 能导"，必须导出实物核对；**双视口负控（宽视口 + 1080 窄视口，缺一不可）**：窄视口量测 NO-CLIP + 窄/宽导出字节数一致（不一致 = 缩放污染未解耦）——只测宽视口测不出 onclone 缺失

**门 2·成品自审**（Read 导出 PNG 或预览截图后逐项过，**未看过成品不交付**）：
- [ ] 盖住文字仍能认出主题吗？（不能 → 视觉隐喻失败，重做布局）
- [ ] 焦点唯一吗？（眯眼测试：第一眼落在一个主视觉上）
- [ ] 图形比例真实吗？（柱长/色块面积与数值成比例）
- [ ] 文字有溢出、裁剪、碰撞、孤行吗？
- [ ] 换个主题这布局还成立吗？（成立 → 做成了模板而非设计）


**底部收尾条署名与来源标注（必做）：**
- 左下角署名：标语下方左侧固定显示 `Ray谈化工 · PS Inforgraphic`（半透明白色，16px，字母间距1px）
- **数据来源标注**（署名旁或 Footer 右侧，≥24px）：事故分析类标调查报告名称+编号；工艺/标准类标法规标准号（如"依据 AQ 3067-2026"）；无权威来源的示意图标"示意"。安全内容无来源 = 可信度归零
- **收尾双轨**（v2.8 新增，管理/制度类必做）：深色收尾条放**源材料里的岗位金句**（给一线员工，如「知风险·知报警·知停车·知处置」），金句上方或页脚放**法条依据与闭环要求**（给检查者）——两层受众一句都不能少（2026-10-01 应急演练明白卡实证：只放法条不抓眼、只放金句过不了检查）

**PNG 截图（html2canvas 方案）：**
在 HTML 中集成 html2canvas（库引入 + **画布外顶部工具栏按钮**（勿 fixed 悬浮——窄视口会遮挡画布内容）+ toBlob 截图脚本 + viewport meta 四件套，完整代码模板见 `references/rendering-pitfalls.md` 首节）。关键参数：`scale:3`（高DPI手机必须≥3x）、`toBlob()`、`useCORS:true`、`backgroundColor:'#FFFFFF'`。
**固定宽度画布（横版 1920 / 竖版 1080）必配 fit 自适应缩放**（wrapper + transform:scale + resize 监听），否则窄窗口右侧撞壁；导出必配 **onclone 解耦**（仅克隆文档解除缩放，页面显示不动、导出恒 1:1），否则窄视口导出分辨率缩水。完整代码与实测判据见 `references/rendering-pitfalls.md`「窄视口适配 + onclone 解耦」节。

**scale 选型 / 常见排查 / html2canvas 防坑**：见 `references/rendering-pitfalls.md`。
