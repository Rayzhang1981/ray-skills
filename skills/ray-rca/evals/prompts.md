# evals/prompts.md — 触发与边界用例

> **用途**：验证本 skill **能被路由到**（should-trigger）且**不会被误触发**（near-miss）。
> **判据**：should-trigger 须命中本 skill；near-miss 须**不**命中本 skill（而是落到指明的兄弟 skill）。
> **生成时点**：2026-10-11 ｜ **来源**：02 批次蒸馏收口轮（`ray-file-distil` P0-2 首次落地）
> **⚠️ 覆盖面声明**：本件为**路由/边界层**回归套件。**内容级盲测本轮未对本 skill 执行**。

## 一、should-trigger（应调用本 skill）

1. **「这起事故的根本原因是什么？为什么没被拦住？」**
   - 期望命中：**证据台账 → 竞争假设 → 因果因子 → 根因编码 → 建议闭环**；**屏障（保护层）失效**视角而非"人的不安全行为"。
   - 关键判断点：必须**先立事实基线与时间线**，再谈因果；**不得跳过竞争假设直接给单一结论**。

2. **「CSB 那个调查报告说的问题，跟我们这起像不像？」**
   - 期望命中：**外部案例的结构化吸收**（保护层失效模式对照），而非故事复述。

3. **「整改建议写完怎么验证它真的有效？」**
   - 期望命中：**整改验证**与**结论变更/撤回**机制（结论可以被新证据推翻；旧稿留底）。

4. **「这起事件要不要升级为正式调查？查多深？」**
   - 期望命中：**分级判据**（按后果/潜在后果定调查级别）——注意与体系侧分工。
