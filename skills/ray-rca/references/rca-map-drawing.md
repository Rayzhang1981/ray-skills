# RCA Map 因果链分析图绘制规范

> 因果分析的成果必须**看得见**。一张因果链图胜过三页文字——它让读者一眼看清"哪些因共同造就了这个果"，也让分析者自己暴露逻辑缺口（画不出来的因果链通常就是想不清楚的因果链）。
>
> 本规范定义三级图体系：**L1 E&CF 图（事实组织）→ L2 CED 因果图（因果推理）→ L3 根因路径链（编码追溯）**。三级共用同一套数据，逐级可追溯。

---

## 总览：三级图体系

| 级别 | 图名 | 回答的问题 | 数据来源 | 主要载体 |
|------|------|-----------|---------|---------|
| **L1** | E&CF 图（事件与因果因子图） | 事情按什么顺序发生、当时存在什么条件？ | 第 2 步时间线（事件/条件标注） | HTML 内嵌 SVG |
| **L2** | CED 因果图（Cause & Effect Diagram） | 这个结果是由哪些实际发生的行动/实际存在的条件共同造成的？ | 第 3 步因果因子 + 充分性检验 | HTML 内嵌 SVG（**必含**） |
| **L3** | 根因路径链 | 每个因果因子追到哪个管理系统根因节点？ | 第 4 步 Root Cause Map 编码 | 表格"路径链"列（见 report-template.md） |

**可追溯原则**：L3 的每个根因节点，能沿 L2 的分支走回某个因果因子；L2 的每个因果因子，能在 L1 的时间线上找到对应事件/条件。画完图做一次反向抽查：任挑一个根因，能否沿图走回事发现场？走不回去 = 链断了，回第 3/4 步补。

## L1 · E&CF 图（事件与因果因子图）

ABS SOURCE™ 的核心工具，把时间线从"列表"变成"图"。

### 符号约定

| 元素 | 图形 | 说明 |
|------|------|------|
| **事件 event** | 矩形（实线框） | 离散的、一次性发生的动作/状态改变（如"夹具卡盘就位""焊缝断裂"） |
| **条件 condition** | 椭圆（虚线框） | 持续存在的状态（如"管内注水顶油""非防爆对讲机在场"），虚线纵向挂在其影响的事件下方 |
| **时序主线** | 实线箭头（左→右） | 连接事件，表示时间先后 |
| **条件挂靠** | 虚线（无箭头） | 条件 → 其相关事件 |
| **因果因子** | 事件/条件加**色标**（橙） | 被第 3 步识别为因果因子的节点，醒目标出 |

### 绘制规则

1. 主线只放**事件**，严格按时序；**条件**不放主线，挂在相关事件下方（一个条件可挂多个事件）。
2. 每个节点文字 = 一句完整过去时陈述（不是词组），与第 2 步时间线的措辞一致。
3. 证据等级用线型区分：**Fact 实线框 / Inference 实线框+灰字 / Hypothesis 虚线框**（Assumption 不上图，只进数据质量表）。
4. 跨尺度事故（如盘锦：9 年→4 天→14 秒）按时间线分尺度拆成多段，段间用"接续符"（⤇ 或标注"接尺度 B"）连接，**不要**强行压进一张图。
5. 复杂分支（如并行作业线）允许 2–3 条并行泳道，但每条泳道内仍严格左→右时序。

### 何时画

- 急性重大事故（正式 RCA）：**必画**，它是因果因子识别的审查底图。
- 轻微事件（ACA）：可省，用带事件/条件标注的时间线列表代替。

## L2 · CED 因果图（核心交付图）

Causal Learning 的核心工具，也是本 skill **HTML 报告必须包含**的图。

### 结构约定

```
                    ┌──────────────┐
                    │   顶事件      │  ← 问题陈述的 Actual（一句正向陈述）
                    └──────┬───────┘
                           │ AND/OR 门
        ┌──────────┬───────┴───────┬──────────┐
        │  分支①   │     分支②     │  分支③   │  ← 一级因果分支（每个因果因子一支）
        └────┬─────┘               │
             │ 逐层追问"为什么"      │
        ┌────┴─────┐
        │  中间原因  │  ← 每框一句完整过去时正向陈述
        └────┬─────┘
             │
        ┌────┴─────┐
        │ 根因 R#   │  ← 编码到 Root Cause Map 节点，红色标出
        └──────────┘
```

### 绘制规则（逐条硬约束）

1. **顶事件 = 问题陈述的 Actual**，一字不改。顶事件放图顶，箭头**由因指向果**（下→上汇入，或上→下展开均可，全图统一；本规范示例用"顶事件在上、原因在下，箭头向上指果"）。
2. **每个框 = 一句完整的过去时正向陈述**，主语+谓语齐全：
   - ✅ "作业人员紧固新夹具螺栓，向已减薄管道施加附加载荷"
   - ❌ "紧固螺栓"（不是句子） ❌ "未及时检测壁厚"（缺席表述，禁）
3. **AND / OR 逻辑显式标注**：多个原因共同导致一个结果时，汇入线穿过 **AND 门**（半圆/横杠符）；任一成即导致时标 **OR**。画完对每个门做充分性检验："这些原因合在一起是否**充分**导致结果？少了哪个就不行？"
4. **物理机理层套用因果逻辑结构库**（`causal-logic-structures.md`）：断裂=应力>强度、泄漏=源+路径+驱动力、火灾=三要素……结构上缺少要素的分支直接暴露缺口。
5. **根因节点红色标出**，框内写 `R# + 根因名 + Map 编码`（如 `R1 变更管理失效 #119/#121`），与 L3 路径链、报告根因表编号一致。
6. **证据等级标注**：Hypothesis 级陈述用虚线框 + 角标"H"，其余如实线。点火源这类多机理并存的用 OR 门 + 每机理独立虚线框。
7. **一分支一页/一屏**：总体图（顶事件+一级分支）一张，每个一级分支的纵深链各一张。分支纵深图标题注明分支编号与名称（如"CF1 管道为何在作业中断裂"）。
8. 框内文字不超过两行；放不下就拆框，**不缩字号**。

### 反向质检（画完必做）

- 从任一根因框出发沿箭头向上走，能否无跳跃地走到顶事件？
- 每个 AND 门：遮住任一支，结果是否仍成立？仍成立 → 该支不是必要原因，删或降级。
- 全图搜"未/没/没有"字样 → 有则改正向陈述。
- **条件句反向验证（根因→顶事件逐环断开）**：对每个根因 R#，沿因果链向上逐环问"如果 R# 被纠正，它直接创造的那个原因还会发生吗？——若会，该环断开；若断开，继续问上一环，直到判断顶事件是否因此不发生或降级"。链条在某一环断不掉（该原因还有别的充分来源），说明 R# 不是该路径的决定性根因，需回到第 4 步重挖。这等价于把"建议回溯测试"前置到画图阶段，提前暴露"根因与顶事件之间其实不连通"的逻辑漏洞。

## L3 · 根因路径链（表格化，不单独画图）

L3 不画独立图，在报告的根因编码表中加**"完整路径链"列**，把每个因果因子到根因的编码路径写成一行链式文本：

```
CF1 → EPG（设备绩效差距）→ 设备可靠性程序 #28 → 例行检查保养 #57
CF1 → EPG → 变更控制 #119 → 未做变更评估 #121
```

规则：
- 路径链从因果因子层（EPG/FLPPG）写到**最深确认节点**；
- 一个 CF 有多条路径时分行写，每行一条；
- 路径节点编号必须与 `root-cause-map.md` 一致，禁止自造编号；
- 候选根因（证据不足）在链尾加 `（候选）`。

## 载体与渲染策略

| 载体 | L1 E&CF | L2 CED | L3 路径链 |
|------|---------|--------|----------|
| **HTML 报告** | 内嵌 SVG（可选，重大事故含） | **内嵌 SVG，必含**（总体图 + 各分支纵深图） | 根因编码表"路径链"列 |
| **Word 报告** | 文本树降级（`├─ └─` 缩进）或省略 | 文本树降级：顶事件 → 分支 → 根因三级缩进 | 同上（表格列） |
| **PPT 报告** | 省略（时间线页代替） | 一页总体因果图（顶事件+一级分支框图），纵深链并入对应分支页 | 根因页表格 |

**HTML 内嵌 SVG 要点**（自包含、离线可用、不引外部库）：
- 单张 SVG，`viewBox="0 0 W H"`，`width="100%"`；
- 配色沿用报告调色板：顶事件/根因用红系，中间原因用琥珀系，事实框用蓝系，AND/OR 门用灰；
- 事件=矩形 `rx=8`，条件=椭圆，Hypothesis=虚线框 `stroke-dasharray="5,4"`；
- 箭头用统一 `<marker>`，实线=因果流向，虚线=条件挂靠；
- 文字不小于 12px，框内文字居中；
- 不用 Mermaid 等外部渲染库——HTML 报告必须断网可开。

**Word/PPT 文本树降级格式**：

```
顶事件：13:24:10 管道焊缝断裂，介质大量喷出
└─ AND：应力 > 强度
   ├─ 强度降至临界（AND：20钢材质 + 酸碱介质 + 8年）〔Fact〕
   │  └─ 根因 R1 变更管理失效 #119/#121
   │  └─ 根因 R2 完整性管理缺位 #28/#58
   └─ 紧固螺栓施加附加载荷〔Fact〕
```

## 范例：盘锦浩业"1·15"事故

**总体因果图（顶事件 + 一级 AND 分支）**：

```
                        顶事件：2023-01-15 13:25:53 装置区蒸气云爆炸着火
        ┌───────────────┼────────────────┬─────────────────┐
     分支①            分支②            分支③             分支④
  管道为何断裂      介质为何喷出       点火源为何        人员为何高密
  （结构失效）     形成可爆气云       作用于气云        度暴露
  （流体运动）     （火灾三要素）     （OR双机理）      （作业组织）
```

**分支①纵深链（节选，完整见盘锦 HTML 报告 v2）**：

- 顶事件 ← AND（强度降至临界 + 紧固螺栓附加载荷）
- 强度降至临界 ← AND（20 钢材质 + 酸碱腐蚀介质 + 8 年服役）〔腐蚀逻辑结构〕
- 20 钢材质为何在场 → R1 变更管理失效 `#119/#121`（未经设计变更代用）
- 腐蚀为何 8 年未识别 → R2 设备完整性管理缺位 `#28/#58`（年度检查缺失、检验未比对设计）

**L3 路径链示例**：

```
CF1 → EPG → 变更控制 #119 → 未做变更评估 #121
CF1 → EPG → 设备可靠性程序 #28 → 例行检查保养 #57
CF3 → FLPPG → 程序 #122 → 正确程序未使用 #123
```

> 完整可运行的 SVG 范例见盘锦浩业 HTML 报告 v2（`盘锦浩业1·15事故_根因分析报告_v2.html`）第五章。
