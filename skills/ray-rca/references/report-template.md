# 根因分析报告模板

> 来源：CCPS《Guidelines for Investigating Process Safety Incidents》第 13 章 + ABS Handbook + TapRoot 报告 + Causal Learning 方法论。无统一报告格式，按组织需求裁剪。

## 三种输出形式（内容同源，载体三选）

分析结论与五问骨架完全一致，只按场景选择载体与取舍：

| 形式 | 章节取舍 | 特点 | 典型场景 |
|------|---------|------|----------|
| **HTML 报告** | 全量章节 | 时间线可视化、因果链图、对照表；可离线打开 | 屏幕阅读、内部分享、快速预览 |
| **Word 报告** | 全量章节 | 表格为主、正式排版；便于打印盖章 | 正式存档、上报监管、打印分发 |
| **PPT 报告** | 精简为 6–8 页要点 | 每页一主题、突出结论与建议 | 领导汇报、培训宣讲、警示教育 |

### PPT 精简映射（页面 ↔ 章节）

| PPT 页 | 内容 | 对应全量章节 |
|--------|------|--------------|
| 1 封面 | 标题 + 事故概要 + 关键数据（伤亡/损失/根因数） | 标题页 + 执行摘要 |
| 2 事故概况 | 时间 / 地点 / 后果 / 工艺背景 | 报告说明 + 事故描述 |
| 3 时间线 | 事件/条件时间轴（突出关键节点） | 时间线 |
| 4 因果因子 | 因果因子清单（含"消除即防"逻辑） | 因果分析 |
| 5 根因 | 根因编码 + 数据质量标注 | 根因 + 数据质量评估 |
| 6 关键学习 | 洞察式要点（非建议式） | 关键学习要点 |
| 7 建议 | Owner / 期限 / 控制层级 | 建议双测试表 |

> 生成工具提示：Word 可复用 docx-js / python-docx；PPT 可复用 python-pptx。分析结论（五问 + 对照表数据）作为唯一事实源，三种载体各自取用，避免三份内容不一致。

## 证据放行补充（必用）

先填写 `investigation-ledger-template.md` 的证据、假设、模型、屏障、结论变更和整改六表；判据见 `investigation-quality-control.md`。执行摘要最后写，结论等级不得高于其关键依据。原件未经审阅时明确写口述或转述，不因已录入表格即称实测。

交付逐层声明结构、算术、模型、案件归因的覆盖面。输入纠错须记录撤回链。责任方/期限由获授权人员确认，AI不得代签或生成未经批准的承诺。

## 报告要回答的五个问题

1. **发生了什么？**（What happened）
2. **怎么发生的？**（How did it happen）
3. **为什么发生？**（Why did it happen）
4. **管理系统层面的多个根因是什么？**（Multiple system-related root causes）
5. **如何防止复发或降低风险？**（What can be done）

## 标准章节结构（全量版）

| 章节 | 内容要点 |
|------|----------|
| **标题页** | 报告日期 |
| **目录** | — |
| **执行摘要** | 事故+关键后果+重要发现+因果因子+根因+建议的精简汇总；1–2 页；**最后写**；复杂事故才需要 |
| **一、报告说明** | 分析目的与方法 / 素材来源与分析边界 / 与官方报告的关系（详见下方「关键章节详解 ①」） |
| **二、事故描述** | **只描述发生了什么，不解释原因**；企业/装置背景、事故管道/设备情况、事发经过、后果与应急 |
| **三、问题描述** | Expected / Actual / Impact 三段式；Actual 即因果分析顶事件 |
| **四、时间线** | **分尺度**（年/月、月/日、时/分/秒）+ 末尾「时间线观察」（详见详解 ③） |
| **五、发现 Findings** | 事实发现，标注证据来源（人证/物证/电子数据/位置/文件） |
| **六、因果分析** | 因果因子识别 + 根因编码（Root Cause Map），正向陈述，套用 `causal-logic-structures.md`；**含因果链图**（CED，按 `rca-map-drawing.md`：HTML 内嵌 SVG / Word·PPT 文本树） |
| **七、数据质量评估** | 关键因果陈述逐条标注数据质量（专门表，详见详解 ④） |
| **八、关键学习要点（OIC）** | 用 **OIC 表**呈现：观察／洞见／结论三行分离（详见详解 ⑤） |
| **九、建议** | 逐条对应根因 + 双测试表格（建议/期望状态/回溯/前瞻）+ 综合回溯（详见详解 ⑥） |
| **十、非促成因素** | 被查明与事故无关、但有学习价值的因素 |
| **十一、屏障有效性分析** | **双向**：失效屏障（进入因果分析）+ **起效屏障**（哪些保护层拦住了本该更糟的后果，如应急处置、相邻装置未波及）；防"只见失效"偏见，提示建议是"补强"而非"另起炉灶" |
| **附件** | 被证伪/低概率场景及理由、照片、图表、计算、实验/金相报告、调查方法说明、参考文献 |
| **参考文献** | 团队得出结论所依据的文件 |
| **质量检查清单** | 报告末尾 self-check（详见「质量检查清单」节） |

## 关键章节详解

### ① 报告说明（透明、可追溯）

明确三件事，让读者知道结论的可靠边界：

- **分析目的与方法**：用什么方法论（本 skill 为 CCPS + SOURCE™ + Root Cause Map 融合）、三个阶段（发现/学习/行动）、全程以因果推理为主线。
- **素材来源与分析边界**：分析基于什么素材（调查报告/访谈/物证）；未开展哪些独立工作（如未现场复核、未独立访谈）；哪些结论由逻辑推导而非直接证据（须在数据质量表中降级标注）。
- **与官方报告的关系**：不重复官方的责任认定，而是转换视角——把事故视为绩效系统的输出，追问"管理系统的哪个环节失守"，产出供同类组织借鉴的学习要点与建议。

### ② 事故描述（只描述，不解释）

- 本节的纪律：**只陈述实际发生的事实，不出现原因判断、不出现"未/没有"的缺席表述、不出现"应该"**。
- 原因分析全部放在「因果分析」章节——事实与因果分离，防止把结论偷渡进事实描述。
- 建议用一句话声明纪律（如"本节只描述发生了什么，不解释原因"）。

### ③ 时间线（分尺度 + 观察）

- **分尺度**：事故跨度大时（如"设计变更→服役 9 年→事发 14 秒"），按尺度拆成多条时间线：年/月尺度（建设与变更）、月/日尺度（检验与泄漏管理）、时/分/秒尺度（事发当日）。
- 每条时间线**只呈现实际发生的事件**，节点标注「事件/条件」。
- **时间线观察**：时间线末尾加一段"仅按时序、不作因果判断"的观察，提炼时序特征（如"从再次泄漏到断裂历时 4 天、三次堵漏失败；从卡盘就位到断裂仅 14 秒"）——这种"收束感"往往本身就是一个洞察。

### ④ 数据质量评估表

把散落在根因里的数据质量标注，集中成一张表，逐条列出**关键因果陈述 + 证据依据 + 质量等级**：

| 关键因果陈述 | 证据依据 | 质量等级 |
|-------------|----------|----------|
| 事故管道实际材质为 20 钢，设计为 316 不锈钢 | 设计图纸；2014/2018/2021 三次检验报告均标注 20 钢 | Fact 事实 |
| 焊缝腐蚀减薄使强度降至作业载荷之下 | 材质+腐蚀介质+8 年服役+断裂时机逻辑推导（原报告无实测壁厚） | Inference 推断 |
| 点火源为非防爆对讲机或吊车热表面 | 专家组综合分析；两种机理均满足条件但无直接影像 | Hypothesis 假设 |

- 等级：**Fact 事实 ＞ Inference 推断 ＞ Hypothesis 假设 ＞ Assumption 臆断**。
- 低于 Inference 的陈述**不冒充确认结论**，并列入"待补充证据"清单。

### ⑤ 关键学习要点（OIC 表：观察—洞见—结论）

学习要点用 **OIC 表**呈现，把**证据（观察）与推理（洞见、结论）显式分离**——观察是触动分析者的数据本身（不作评判），洞见是从观察中读出的意义，结论是"如果洞见成立，还可以认识到什么"。每组学习要点一张三行表：

| 要素 | 内容 |
|------|------|
| **观察 Observation** | 2014 年监督检验、2018 与 2021 年两次定期检验报告中，事故管道材质均标注为 20 钢；设计图纸为 316 不锈钢。 |
| **洞见 Insight** | 材质与设计不符这一事实，在书面记录中持续可见了约 9 年。 |
| **结论 Conclusion** | 如果一项关键偏差可以长期"可见"而不触发任何行动，那么检验报告的信息流并没有进入任何决策循环——检验产出的是文件，而不是判断。 |

写作要点：
- **观察**只写数据/记录本身，可引用原始文件编号；不带形容词、不带判断。
- **洞见**一句话点破规律（可迁移、非建议式），供同类组织对照自检。示例风格：*"临时措施每成功一次，组织对根本原因的感知就迟钝一分。"*
- **结论**用"如果……那么……"句式外推，指出系统层面的含义。
- 一个事故通常提炼 4–6 组 OIC；可顺带归纳**系统层原因**（深于管理系统的"组织心智模型"，如"先干后补、违规获利"的共有信念）——这是最上位的学习。
- OIC 表是"关键学习要点"的升级版：每条要点可追溯回具体观察，防止洞察变成无根的口号。

### ⑥ 建议双测试表

每条建议用四列表呈现，末尾加"综合回溯"：

| 建议（针对的原因） | 期望状态 | 回溯测试（回到事故前） | 前瞻测试（面向未来） |
|-------------------|----------|----------------------|---------------------|
| R1 建立泄漏分级与强制停车触发机制（针对：根源未排查） | 避免：设备完整性未知时反复带压作业 | 2022 年首次泄漏后即检测壁厚→腐蚀暴露→停车换管，事发作业不复存在 | 以"次数"为硬触发、不依赖个人判断，可持续；副作用是增加非计划停车 |
| R2 … | … | … | … |

- **回溯测试**：如果该措施早已存在，会在时间线哪一点截断事故链？之后会发生什么？
- **前瞻测试**：对未来类似事故多有效？当前系统能否持续？有无副作用？
- **综合回溯**：把所有建议的截断点列出来，指出"多层防线各自独立，任何一层起效都能改变结局"——说明纠正措施须成体系实施，而非只补最后一环。

## 核心对照表（报告正文最实用的一节）

把每条**发现 → 因果因子 → 根因 → 建议**做成一张对照表，保证逻辑链条清晰可追溯：

| # | 发现（事实） | 证据来源 | 因果因子 | 根因路径链（CF → 类别 → 节点编码） | 根因（含数据质量） | 建议 | 责任人·期限 | 控制层级 |
|---|-------------|----------|----------|----------------------|------|------|------|--------|
| 1 | 溢流罐液位开关失效 | 物证/电子 | 液位开关在液位超限时持续处于关闭指示（EPG） | CF1 → EPG → 设备可靠性程序 #28 → 关键设备未识别 #30 | 关键设备未纳入检测〔Fact〕 | 将液位开关纳入关键设备清单，建立周期测试 | 设备部·重启前 | 工程控制 |
| 2 | 物料在未取样确认状态下被转移 | 人证/纸 | 操作工直接执行了转移作业（FLPPG） | CF2 → FLPPG → 程序 #122 → 步骤顺序错误 #141 | 程序缺陷〔Inference〕 | 修订取样程序；补训并考核 | 工艺部·X月X日 | 管理控制 |
| … | | | | | | | | |

> 说明：上表为**示例占位**，实际填写须依据真实调查证据；因果因子用**正面陈述**（写"实际发生的行动/条件"，不用"未/没"缺席表述）；**根因路径链**从因果因子层（EPG/FLPPG）写到最深确认节点，编号与 `references/root-cause-map.md` 一致（一个 CF 有多条路径时在单元格内分行），候选根因在链尾加（候选）；数据质量按「Fact / Inference / Hypothesis / Assumption」标注；控制层级按「消除/替代 → 工程控制 → 管理控制 → PPE」填写。

## 建议的 SMART 属性（逐条自检）

每条建议满足 **S**pecific 具体 / **M**easurable 可衡量 / **A**ttainable 可达成 / **R**ealistic 现实相关 / **T**imescales 有时间表。

建议写作模板（独立陈述，说清三件事）：

> **[做什么]** 组建多学科团队对反应器进料操作程序做逐步审查并更新，填补缺失步骤（吹扫、切断反应物 A、断开拖车）。**[为什么]** 调查组发现多处步骤缺失，已导致接头与阀门多次泄漏。**[完成标志]** 更新版程序经批准发布并对全体操作工完成培训（截至 X 月 X 日）。

**禁忌**：模糊词（"适当的安全措施""提高培训质量"）、命令式空话（"重写操作规程"）、只治症状不治根因。

## 建议的控制层级（优先选高层级）

按效果从高到低排列，**优先选择并突出高层级措施**，不以 PPE 作为主要手段：

| 层级 | 含义 | 示例 |
|------|------|------|
| **① 消除 / 替代** | 从根本上移除危害或用无害物替代 | 铝镁粉尘禁止干式吹扫，改用湿式/惰化清理；停用不合格设备 |
| **② 工程控制** | 用硬件/隔离把人与危害隔开 | 选用经认证的防爆吸尘器；可靠接地与等电位跨接；通风除尘 |
| **③ 管理控制** | 用制度/程序/培训改变行为 | 修订清理制度；专项培训考核；现场巡查签字 |
| **④ PPE** | 最后一道防线 | 防尘面罩、防静电服（仅作补充，不作为主要措施） |

## 写作守则

- **语气指向预防，不归咎个人**；有不确定处用措辞如实体现（"可能""据现有证据"）。
- **范围克制**：只写与事故因果直接相关的内容，应急响应、公关等单独立项，避免"范围蔓延"。
- **保留审计追踪**：报告只是调查记录的一部分，照片、测量、DCS 数据、访谈记录、计算等原始证据按记录保留政策归档，供后续复核。
