## EV-06｜批量补丁脚本的两个静默坑（2026-09-13，self-neat 轮实测）

共同特征：**脚本报"完成"、退出码 0，错误只在回读时才暴露**。

### 坑 1｜文本模式读写默认做换行转换（LF → CRLF）

用 Python 文本模式读入 + 写回同一文件，会把整个文件的 **LF 全量变成 CRLF**。本次连续跑 4 个补丁脚本，6 个目标文件里 **5 个中招**（唯一幸免的 `ray-core.md` 本就是 CRLF）；HANDOFF 凭空 **+751 字节**（＝752 行各多 1 字节）。

危害不在渲染（Markdown 无感），而在**污染 diff**——整个文件看起来全改了，后续排查真改动极难。

根因：文本模式读时按通用换行把 CRLF 归一为 LF，写时又按系统行分隔符把 LF 转回 CRLF；原文件是 LF 就被单向"升格"。

### 坑 2｜脚本里用转义写法描述"字面字符"会自我触发

两处都命中：

① **带圈数字转义差一位** —— 锚点里要写 ⑩，实际写成 `\u246a`（那是 **⑪**；⑩ 是 `\u2469`）→ 命中 0 次、替换 0 次，脚本仍打印"完成"、退出码 0，**静默 MISS**。

② **讲坑的句子自己变成坑** —— 在补丁里加一段说明本坑的文字，其中写了"把回车+换行替换为换行"的**字面转义序列**；它处在三引号字符串内，被 Python 解释成**真实 CR LF 控制字符**写进了目标文件。即：**用来记录坑的那句话，本身制造了一个坑**。

### 修正三条

1. 锚点一律用**字面字符**，不用转义写法；
2. 替换前 `print(count)` 逐条报命中数，MISS 必须可见；
3. 写完**回读三查**：换行样式 / U+FFFD 乱码 / 关键内容存在性。
