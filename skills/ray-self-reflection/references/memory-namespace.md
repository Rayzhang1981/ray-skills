# 记忆 namespace 隔离 + 冲突解决 + GC 衰减（v3.14.0 新增）

> 吸收外部自改进体系的三级存储/namespace/冲突规则，与本地三级存储（MEMORY.md/日志/skill）衔接。**按需加载**：复盘遇到"记忆放哪 + 冲突怎么解 + 何时清理"时读。

## 一、namespace 隔离（放哪，防止全局被项目淹没）

| 经验类型 | 放哪 | 例子 |
|---------|------|------|
| **项目专属** | 对应项目 skill 的实战经验区 或 项目 MEMORY.md | "XX 装置的操作顺序" |
| **领域专属** | 领域 skill（ray-ccps-* 等）或领域分类条目 | "HAZOP 引导词用法" |
| **全局偏好/规则** | 用户级 MEMORY.md（HOT） | "中文走 PowerShell" |

**继承链**：全局 → 领域 → 项目（越具体优先级越高）。经验放错层 = 该见时不见（项目经验进了全局被淹没），或不该见时见（全局噪音进了项目）。

## 二、冲突解决规则（矛盾时听谁的）

| 优先级 | 规则 | 例子 |
|--------|------|------|
| 1 | **最具体优先** | 项目规则 > 领域规则 > 全局规则 |
| 2 | **最新优先**（同层） | 同层两条矛盾，取新 |
| 3 | **模糊 → 问用户** | 无法判定时不得自作主张 |

## 三、GC 衰减自动化（v3.14.0 固化）

| 时点 | 动作 |
|------|------|
| 30 天未引用 | 标记降级候选（不删） |
| 90 天未引用 | 降级/归档到 changelog（不硬删，保留历史） |
| **每季度** | 执行一次全量 GC 检查：扫实战经验区 + MEMORY.md，标记超期条目，汇报用户后归档 |

**GC 不是删除**：降级/合并/归档三选一，**绝不硬删**（丢失信任与历史）。与 self-improving 外部体系的"衰减 + 归档"机制一致。

## 四、与三级存储的衔接

```
HOT（常驻）：MEMORY.md ≤200 行 / ≤25KB
WARM（按需）：项目 skill 实战经验区 / 当日日志
COLD（归档）：references/experience-archive.md / changelog.md
```
