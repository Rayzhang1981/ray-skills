# 周度回顾 + 功能需求捕捉（按需加载）

> 从 SKILL.md 卸载（v3.10.0）。**何时读**：用户说"周度回顾/周报"时、或捕捉到用户隐含的功能需求时。

## 周度回顾（Weekly Retrospective，v3.2 新增）

> 会话级反思解决"单次"，周度回顾解决"趋势"——把一周的碎片经验汇总成方向性结论。

**触发**：用户说"周度回顾 / 周报 / weekly retro / 这周学到了什么"，或每周一次主动提出。

### 执行流程

1. **收集**：读取本周（近 7 天）所有 `YYYY-MM-DD.md` 日志 + 实战经验区新增条目
2. **What Went Well**：列 3-7 条具体成功（带证据——哪天/哪步/哪个工具）
3. **What Didn't Go Well**：每项标注 ①具体任务 ②根因（非症状）③浪费的轮次/时间 ④是否反复出现
4. **技能缺口分析**：哪些 struggle 本可以靠某个 skill 解决？记录到 FEATURE_REQUESTS.md（候选新 skill）
5. **配置审查**：MEMORY.md 是否过大/过时？实战经验区是否超过 30 行？有僵尸条目该衰减/归档了？
6. **行动清单**：Quick wins（<5分钟）/ Medium（<1小时）/ Larger projects，封顶 10 条

### 输出格式

报告模板见 `references/output-templates.md` 模板二（Wins / Struggles / Skill Gaps / Config Issues / Action Items 五段式）。

**原则**：不注水——每行都要有信息量；self-critical——目的是改进不是贴金；cap 10 条行动项。

## 功能需求捕捉（Feature Requests）

用户的隐性需求是 skill 迭代的第一手来源。除了反思"已发生的事"，还要捕捉**"用户想要但现在没有的能力"**。

**捕捉信号（用户说了就算，不等复盘）**：
- "能不能做 X？" / "可不可以加 X？" / "我希望你能…"
- "为什么你不能…" / "这个功能有没有？" / "帮我做个 XX 工具"
- 反复手动操作同一件事 → 隐含"该有个 skill 自动化"的需求

**记录位置**：`FEATURE_REQUESTS.md`（用户级或项目级，没有就创建），格式模板见 `references/output-templates.md` 模板三（含 ID / Priority / Status / 用户意图 / 现状 / 候选实现六段）。

**去向**：
- 单次需求 → 记录即可，不立即做
- 同一 FEAT 出现 ≥2 次 → 升级为候选新 skill，下次迭代时提议用户创建
- 与已有 skill 重叠 → 记录到该 skill 的「实战经验」区或建议增强

**判断口诀**："这个需求反复出现，说明该有个能力覆盖它" —— 记录它，就是给未来的自己递需求清单。
