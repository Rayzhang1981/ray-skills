# 「实战经验」区约定（完整细节）

> 核心（格式/ID/计数+跨任务复发/状态机/毕业衰减）已常驻 SKILL.md「按任务用到的 skill 路由」段；**此处为完整细节**（死路字段说明、See Also、streak、深化建议、毕业/衰减全规则）。**何时读**：写实战经验区且需要状态机/streak/深化建议细节时。

- 位置：SKILL.md 末尾独立 `## 实战经验` 区（没有就创建）
- 格式：`- YYYY-MM-DD｜[LRN-YYYYMMDD-XXX]｜场景：xxx｜经验/教训：xxx｜死路：xxx｜来源：任务名｜计数：N｜状态：pending`（一行一条）
  - **死路字段（Dead-end，v3.2 新增）**：记录"试过但否决的路径 + 原因"，如 `死路：markitdown 处理 .doc（不支持旧格式）`。排除的失败路径往往比成功路径更省时间——下次会话直接跳过。没有死路可写时填 `死路：无`（此时晋升三条件第 3 条不满足，不能晋升）。
- **条目 ID**：每条实战经验带唯一 ID，格式 `LRN-YYYYMMDD-XXX`（LRN=学习 / ERR=错误 / FEAT=功能请求；XXX 为当日顺序号 001/002…）。ID 是全链路锚点：
  - 去重判断靠它（`grep "LRN-20260811"` 就能找到同日条目）
  - `See Also` 关联靠它（新条目与旧条目相关 → 写 `See Also: LRN-20260810-002`）
  - 毕业/衰减追踪靠它（计数变化时按 ID 找到原条目更新）
  - MEMORY.md 红线条目同样带 ID，格式 `[LRN-...]`
- 上限：**~30 行**；超出时最老的毕业或删除
- **计数**：同一教训第 2 次出现 → 按 ID 找到原条目，计数改为 2；第 3 次出现 → **询问用户确认**（"这条已出现 3 次，是否升为 Skill 主流程/红线？"），确认后才毕业
  - **跨任务才算复发（v3.9 新增）**：计数递增的前提是**跨任务/跨会话复发**——同一任务内反复出现（同一次会话里踩 2 次同一个坑）只算 1 次，不算 2 次。**防虚高**：同任务内重复是"一次失败的两处症状"，跨任务复发才是"没记住教训"。参考判据：`Recurrence ≥3 + 跨 ≥2 个不同任务 + 30 天窗口内`才达到晋升门槛（2026-08-17 对比吸收自改进类外部 skill）
- **状态机**：每条条目带显式状态，追踪生命周期：
  - `pending`：刚记录，待验证
  - `resolved`：已解决/已应用（如教训已写进某个 skill 的修复）
  - `monitoring`：已设预防规则，处于观察期（v3.2 新增）
  - `promoted`：已毕业（升为 Skill 主流程或 MEMORY 红线）
  - `wont_fix`：决定不处理（写一句原因）
  - 状态迁移：出现 → pending；应用/验证 → resolved；设了预防规则但仍需观察 → monitoring；毕业 → promoted；放弃 → wont_fix
  - **streak 字段（v3.2 新增）**：`streak: N` 表示连续 N 天未复发。streak 满 30 天 → 从 monitoring 降为 resolved（或按 90 天衰减规则归档）；复发 → streak 清零并重新计数。
  - **深化建议（v3.6 新增）**：`pending` / `monitoring` 状态的条目，必须附一条"怎么进一步验证或深化"——继续观察 N 天 / 对比旧会话 / 收集一个具体案例 / 转成工作流规则 / 下次问针对性问题。**避免"待验证"变成"永远待着"**——每条待定经验都有明确的下一步。
- **毕业**：同一教训出现 ≥3 次 **且用户确认** → 改写进主流程（成为正式指令），从实战区删除——实战区是缓冲区，不是坟场；未经确认即使满 3 次也不毕业
- **衰减**：实战区条目 90 天未被引用（无新计数）→ 降级为"待归档"或移入 MEMORY.md 一行指针，不硬删（归档保留历史，删除失去信任）

**判断口诀**："下次用这个 skill 时，这条经验必须在场吗？" 必须 → 进 skill；重要但通用 → MEMORY.md；可有可无 → 日志。
