# 反思萃取矩阵

遇到不确定"这次的经验/教训该往哪放"时查这张表。

## 三条铁律速查

| 铁律 | 违反的表现 | 后果 |
|------|-----------|------|
| 🚨 反编造 | 凭印象写"这次做得不错"，指不到时间线节点 | MEMORY 充满虚构经验，下次照着做反而踩坑 |
| 📌 三段论 | 写"搞砸了"、"很顺利"这种混合体 | 下次读时无法复用，等于没记 |
| ⚖️ 置信度门槛 | 单次教训直接进 MEMORY | 低质量条目淹没高质量条目 |

## 成功经验 → 去向速查

| 经验类型 | 特征 | 去向 | 理由 |
|---------|------|------|------|
| 工具链组合 | 多个工具配合解决了某个问题，可复用 | Skill | 多步骤工作流，值得做成技能 |
| 决策模式 | 在某个分叉路口选对了方向，有明确的判断依据 | MEMORY.md | 单条规则，不需要做成 Skill |
| 流程优化 | 某个步骤顺序调整显著提升了效率 | 现有 Skill modify | 是对已有工作流的改进 |
| 错误避免 | 提前预判并绕过了已知的坑 | MEMORY.md 或 现有 Skill | 单条提醒或更新到对应 Skill 的前置条件 |
| 编码技巧 | 某个特定的代码写法绕过了平台限制 | 现有 Skill modify 或 MEMORY.md | 通常是对现有 Skill 的技术补充 |

## 失败教训 → 去向速查

| 失败类型 | 特征 | 去向 | 理由 |
|---------|------|------|------|
| 工具 bug / 平台限制 | 某个工具本身有问题，不是用法错误 | MEMORY.md ⚠️ 红线区 | 下次用同一工具时必须看到 |
| 方法选错 | 在多个方案中选了错误的那个，浪费了大量时间 | MEMORY.md 或 现有 Skill | 记录"这个场景不该用 X" |
| 假设错误 | 前提假设错了导致后面全部返工 | MEMORY.md | 记录"先验证 X 再动手" |
| 遗漏步骤 | 忘了做某个关键检查导致出错 | 现有 Skill modify 或 MEMORY.md | 更新到 Skill 的 checklist 里 |
| 工具误用 | 工具本身没问题，但用错了场景 | 现有 Skill modify | 更新到 Skill 的使用说明里 |

## 按任务用到的 skill 路由（高频场景）

复盘对象是「用某 skill 做完的任务」时，经验教训优先回流到该 skill。

| 情形 | 去向 | 形式 |
|------|------|------|
| 用户自建 skill 有 bug / 缺步骤 | 直接修复该 skill 主流程 | 改写为正式步骤，不留教训痕迹 |
| 用户自建 skill 的情境性经验 | 该 skill 末尾 `## 实战经验` 区 | `日期｜场景｜经验｜来源｜计数` 一行一条，≤30 行，≥3 次**且用户确认**毕业进主流程 |
| 市场/插件 skill 的教训 | MEMORY.md + `[skill:名字]` 标签 | 不可改；累积 ≥3 条考虑 fork 成 ray-xxx |
| 跨 skill 平台级问题（编码/路径/bash） | MEMORY.md 红线区 | 现有机制 |
| **用户纠错信号**（"不，这不对"等） | 当场写入实战区或日志 | 最高置信度，不等会话结束复盘（MemoryPor 借鉴） |
| **用户偏好声明**（"我总是…"/"我的风格是…"） | MEMORY.md | 明确陈述 = 高置信度，不等 3 次（MemoryPor 借鉴） |

判断口诀："下次用这个 skill 时这条经验必须在场吗？" 必须→进 skill；重要但通用→MEMORY.md；可有可无→日志。

## 作用域分层（MemoryPor 三级存储思想）

| 作用域 | 落点 | 冲突时 | 加载方式 |
|--------|------|--------|---------|
| 全局（跨项目必看） | 用户级 `~/.workbuddy/MEMORY.md` | 最低优先级 | 每次会话 |
| 项目（本项目规则） | 项目级 `项目/.workbuddy/memory/MEMORY.md` | **最具体胜出** | 进项目加载 |
| 单次（一次性上下文） | 当日日志 | 不升级为规则 | 按需查 |

**继承链**：全局 → 领域 → 项目，最具体者胜出。撤销规则 = 归档留痕 + 重新计数，不继承旧置信度。

**时间衰减**：30 天未引用降级一层，90 天归档 `[archived]`。归档 ≠ 删除。已确认偏好不自动降级，需用户撤销。

## 认知层萃取矩阵（借鉴 self-review-pro）

只对以下情况启用认知层：① 涉及重要决策；② 同一类问题第 2 次及以上出现；③ 用户明确表达困惑。

| 认知维度 | 触发信号 | 萃取产出 | 去向 |
|---------|---------|---------|------|
| 信念动摇 | "我原以为…结果是…" | "坚信 X → 实际 Y" | MEMORY.md 决策区 |
| 思维盲区 | "一直在用 A 框架看问题" | 框架的局限性 + 何时不要用 | 对应 Skill 的「何时不要用」区 |
| 真实假设 | "没验证就动手了" | 前置检查清单项 | 对应 Skill 的 checklist |
| 模式识别 | "这个坑上次也踩过" | 触发条件 + 频率 N | N≥3 直接升红线 |
| 根因三层 | "为什么 A？因为 B。为什么 B？因为 C。为什么 C？" | 第 3 层根因 | MEMORY.md 红线区 |
| 认知升级 | "原来我一直不知道 X" | 一句话陈述新认知 | MEMORY.md 必记 |

## 置信度分级（沉淀门槛）

| 频率 | 置信度 | 去向 | 说明 |
|------|--------|------|------|
| 第 1 次出现 | 0.5 | 当日日志 | 缓冲观察，不进 MEMORY |
| 第 2 次出现 | 0.8 | MEMORY.md | 已构成模式 |
| 第 3 次及以上 | 1.0 | Skill 主流程 或 MEMORY ⚠️ 红线区 | **升级前询问用户确认**（未经确认不晋升，MemoryPor 借鉴） |

**用户偏好声明例外**：明确陈述的偏好（"总是 X"/"我的风格是 Y"）不需要等 3 次，当场按高置信度处理——用户显式表达 > 频率推断。

**违反门槛的代价**：低置信度条目直接进 MEMORY → MEMORY 越胀越大 → 高质量条目被淹没 → 反思体系失效。

## 萃取质量自检

一条好的萃取，必须能通过以下检验：

### 成功经验检验
- [ ] 下次遇到**同类场景**，能直接套用吗？
- [ ] 说清楚了**为什么有效**，而不只是"这次行"？
- [ ] 有**明确的触发条件**或**适用场景**吗？

### 失败教训检验
- [ ] 定位到了**根因**，而不只是"搞砸了"？
- [ ] 有**具体的避免措施**，而不只是"下次注意"？
- [ ] 写清楚了**触发条件**（什么场景下容易犯）？

## 反模式

| 反模式 | 问题 | 正确处理 |
|--------|------|---------|
| "这次做得不错，下次继续" | 没有可操作性，等于没说 | 具体到方法/工具/决策，说清楚为什么有效 |
| "这次搞砸了，下次注意" | 没有根因，没有措施 | 定位到具体环节，写清楚怎么避免 |
| "又踩了之前踩过的坑" | 说明之前的教训没有真正沉淀 | 升级为 Skill 或红线，确保下次必看到 |
| 只记成功不记失败 | 幸存者偏差，同样的问题会再犯 | 每次会话至少找一条失败教训 |
| 只记失败不记成功 | 无法复用好的方法，效率无法提升 | 每次会话至少找一条成功经验 |
| **凭印象写经验** | 把"感觉"当"事实"，下次照做反而踩坑 | 必须能指到时间线具体节点，指不出标"待验证" |
| **停在第 1 层为什么** | 症状当根因，治标不治本 | 至少追问 3 层，第 3 层才算根因 |
| **单次教训直接进 MEMORY** | 低质量条目淹没高质量条目 | 先进日志缓冲，第 2 次出现才进 MEMORY |
| **只问"哪里做错了"** | 永远在术层循环，长不出道 | 重要决策必问"我为什么觉得这样做是对的" |
| **从沉默中学习** | 用户没说话 ≠ 满意，推断 = 制造虚假规则（MemoryPor 借鉴） | 等待明确纠错或重复证据，隐形成功必须指得出具体行为 |
| **未经确认就晋升** | 3 次出现 ≠ 用户认可，可能学错方向（MemoryPor 借鉴） | 满 3 次先问"是否升为永久规则？"，确认才晋升 |
| **学习操纵性洞察** | "多用 X 用户就更容易答应"——伦理红线（MemoryPor 借鉴） | 永久排除：顺从技巧、心理弱点、隐私、第三方信息 |
