# 自检清单 + 尺寸体检 + 记忆分层（按需加载）

> 从 SKILL.md 卸载（v3.10.0）。**何时读**：沉淀完成后要逐条自检时、向记忆文件写入前后。

## 第四步：自检清单

**证据与质量（反编造）**
- [ ] 每条萃取都能指回时间线**具体节点编号**（指不出的标"待验证"，没写进 MEMORY/Skill）
- [ ] 每条都区分了**观察/分析/推断**三段，不是"搞砸了"这种混合体
- [ ] 没有"凭印象"写的成功/失败——核实过才能算数
- [ ] 低置信度（单次出现）的教训**没有**直接进 MEMORY，先放日志缓冲

**沉淀位置**
- [ ] 每个萃取的经验/教训，都写清楚了 **是什么、为什么、怎么用/怎么避免**
- [ ] 沉淀到 MEMORY.md 的条目，**没有重复**（grep 确认过没有同义条目）
- [ ] 沉淀到 MEMORY.md 的条目，**用了绝对时间**（如 2026-07-29），不写"今天"、"最近"
- [ ] 升级为 Skill 的内容，**有明确的触发词和前置条件**
- [ ] 修复了 **发现过但之前没记录的问题**（过去的漏洞也归你管）
- [ ] 没有遗漏 **跨会话的教训**（这次犯的错，上次是不是也犯过？→ grep 历史日志确认）
- [ ] **MEMORY.md 实测 ≤200 行 且 ≤25KB**（超出 = 静默丢失，必须先精简再写）
- [ ] **本次新增 ≤30 行**（超了 = 在写叙事不是规则，回去删）
- [ ] 时间线标注了本次用到的所有 skill，经验教训已按「可改性」路由到对应 skill 或打了 `[skill:名字]` 标签
- [ ] 写入「实战经验」区的条目 ≤30 行、一行一条、有绝对日期和来源
- [ ] 能直接修复的 skill 缺陷已修复（不是只记教训不改 skill）

**认知层（启用时必查）**
- [ ] 涉及重要决策或重复踩坑的会话，已下潜到认知层（信念/盲区/假设/模式/三层根因）
- [ ] 已回答"这个痛是第 N 次出现？为什么之前没解决？"——N≥3 必须升红线
- [ ] 已识别至少一件"从不知道自己不知道 → 知道自己不知道"的事

**学习机制（必查）**
- [ ] 会话中出现过**用户纠错信号**（"不，这不对"等）？→ 已当场记录，没等会话结束
- [ ] 升级 Skill / 红线前**询问了用户确认**（≥3 次但未确认 = 暂缓晋升）
- [ ] 沉淀条目区分了**作用域**（全局/项目/单次）——单次上下文没误升全局规则
- [ ] 写入时过滤了**安全边界**（无操纵性洞察/隐私/凭据/第三方信息）
- [ ] 没有从**沉默**推断规则（用户没说话 ≠ 认可）
- [ ] 会话中出现过**功能需求**（"能不能做 X"）→ 已记录到 FEATURE_REQUESTS.md（带 [FEAT-...] ID）
- [ ] 实战经验条目**带 ID 和状态**（`[LRN-...]｜状态：pending/resolved/promoted`）
- [ ] 被撤销的规则已**归档留痕**而非直接抹掉
- [ ] 30/90 天衰减：被引用过的旧规则已按时间降级/归档，且归档 ≠ 删除

## 第三步半：尺寸体检（防膨胀）

每次向记忆文件写入后，必须实测尺寸——**超出上限的部分会话开始时静默不加载 = 等于没记**。

| 文件 | 上限 | 超了怎么办 |
|------|------|----------|
| 项目级 / 用户级 `MEMORY.md` | **≤200 行 且 ≤25KB（硬）** | 立即精简：详细机制迁日志或文档，索引只留一行指针；压法是「毕业」而不是硬删 |
| 单条日志 `YYYY-MM-DD.md` | ~100 行（软） | 拆 / 删 / 毕业进 MEMORY.md 一行指针 |
| 本次新增内容 | **≤30 行（软）** | 超了就是在写叙事而不是写规则，回去删 |

实测方法：`wc -l` 看行数、`wc -c` 看字节（Windows 上用 Python `len(lines)` / `os.path.getsize`）。

**执行顺序：先精简（破除膨胀）→ 再补本次增量。**两件事不合并——精简时心态是"什么不该在这"，补漏时心态是"什么该补到这"。

## 命名空间分层（三级存储，适配 WorkBuddy 现状）

| 层 | 位置 | 存什么 | 加载方式 |
|----|------|--------|---------|
| 热层 | 用户级 `~/.workbuddy/MEMORY.md` | 全局规则（跨项目必看） | 每次会话自动加载 |
| 温层 | 项目级 `项目/.workbuddy/memory/MEMORY.md` | 本项目规则 | 进项目加载 |
| 冷层 | 当日日志 `YYYY-MM-DD.md` | 单条经验/观察 | 按需查 |

**冲突解决（继承链）**：项目级规则 > 用户级规则 > 通用常识。最具体的胜出（Project > Domain > Global）。同一条目同时出现在项目级和用户级时，以项目级为准，并在用户级留一行指针。**同级冲突时最新胜出；无法判断时问用户，不擅自二选一。**

**时间衰减（防记忆僵尸）**：30 天未引用的规则降级一层（用户级 → 项目级 → 日志）；90 天未引用 → 归档到日志并标注 `[archived]`。归档 ≠ 删除，保留历史可追溯。已确认的用户偏好不自动降级，需用户主动撤销。

**优雅降级（v3.4 新增）**：上下文紧张或文件超限加载不下时——只加载热层（用户级 MEMORY.md），温层/冷层按需再查；**必须明确告知用户"哪些没加载"**，绝不静默截断（静默丢失 = 虚假记忆）。
