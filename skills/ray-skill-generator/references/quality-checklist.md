# 质量验证清单（整合 14 维审计精简版）

> Phase 3 验证时读本文件。逐项核对，全过才发布。

## 一、元数据（HIGH）

- [ ] `name` 小写连字符格式（`my-skill` 非 `MySkill`）
- [ ] `description` 包含：做什么 + 何时用 + 触发词
- [ ] description 用第三人称（"This skill should be used when..."）
- [ ] description 无结尾空话（"灵活应用/根据情况"）
- [ ] `version` 是 SemVer x.y.z
- [ ] `agent_created: true`（可被 skill_manage 修改）

## 二、架构（MEDIUM）

- [ ] 目录结构标准（SKILL.md + scripts/references/assets）
- [ ] SKILL.md <500 行，详细内容进 references/
- [ ] 渐进式披露：有"详见 references/xxx"索引
- [ ] 信息不重复存两处
- [ ] 大 references 文件有 grep 搜索提示

## 三、文本（MEDIUM）

- [ ] imperative 第三人称（"To do X, run Y" 非 "You should"）
- [ ] 无冗余/AI 腔废话（"说白了/换句话说/首先其次综上"）
- [ ] 术语一致（同一概念不换称呼）
- [ ] 无超长段落（>120 字符拆表格/列表）

## 四、代码（HIGH）

- [ ] 脚本有错误处理（成功/失败/异常三条路径）
- [ ] 无魔法数字（加注释说明）
- [ ] 依赖声明完整（SKILL.md 列出需要的包）
- [ ] 脚本可独立运行（不依赖对话上下文）

## 五、失败模式（v2.7 起强制）

- [ ] 有显式失败分支（"如果 X 失败 → Y"≥3 处）
- [ ] 有 fallback 路径、错误恢复
- [ ] 不只写正向流程

## 六、反例黑名单（v2.7 起强制）

- [ ] 有"不要做 X"的反例清单（❌/禁止/避免 ≥3 处）
- [ ] 红线/危险动作单独列出

## 七、脱敏（发布前必查）

- [ ] 无来源署名（"借鉴 xxx"）
- [ ] 维护记录不列具体第三方名
- [ ] 功能性引用（关系表/插件示例）和工具名（pip 包）保留

## 八、安全（新建时自查）

- [ ] 无凭证引用（~/.ssh、~/.aws、~/.env）
- [ ] 无危险命令（curl|bash -i、下载执行）
- [ ] 权限声明清晰（需要什么权限、为什么）

## 质量分级（health_check.py 输出）

| 级 | 判定 | 动作 |
|----|------|------|
| A | ≥90 分无关键缺陷 | 可直接发布 |
| B | ≥80 分 | 建议精简后发布 |
| C | ≥60 分 | 偏大需精简 |
| D | <60 或尺寸超限/frontmatter 缺 | 必须先修 |
