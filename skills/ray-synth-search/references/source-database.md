# 高价值搜索渠道数据库（Source Database）

> 定位：ray-synth-search 的「搜索弹药库」。按任务类型分类的高质量信息渠道，每个渠道用三维评分标注。
> **本库是动态演进的**——每次执行检索任务时，发现新的高价值渠道就沉淀进对应分类，DB 随任务持续生长。

## 使用方式

1. 任务开始时，按「任务类型」查对应分类，选 **≥2 个渠道**（1 主源 + 1 交叉源）
2. 优先 **A 级**；专业领域问题用「领域专项」分类
3. 检索中如果遇到「好用但不在库中」的渠道 → 记入文末「待沉淀区」
4. 任务结束汇报前，把待沉淀渠道按格式正式入库

## 三维评分标准

| 维度 | 含义 | 高 | 中 | 低 |
|------|------|-----|-----|-----|
| **权威性** | 是否官方/专业/可溯源 | 官方机构、学术、正规媒体 | 行业协会、专业社区 | 自媒体、个人 |
| **信息广度** | 覆盖范围 | 跨领域、海量 | 领域内较全 | 单一主题 |
| **信息深度** | 内容深入程度 | 原文、全文、专业分析 | 概况、综述 | 标题、摘要 |

## 渠道分级

- **A 级（核心）**：权威性高 + 信息全 → 首选主源
- **B 级（常用）**：某单维度突出 → 交叉验证源
- **C 级（备选）**：特定场景补充 → 查漏用

> ⚠️ 实测要点（2026-08-31）：
> ①**价格类问题第一原则是查官方定价页**——本次 5 个来源给出 3 套 DeepSeek 价格，只有官方文档准确；
> ②模型/套餐迭代极快，任何"历史价格"都可能已失效，交付前必须标注数据日期；
> ③订阅制套餐的"prompt 配额"常有**消耗倍数**（如高峰时段 3 倍扣配额），标称配额与实际体感差距可达 3 倍；
> ④免费层要区分「永久免费」与「限时试用额度」，只有前者可纳入长期方案；
> ⑤隐私红线：部分免费层会用数据训练模型（Google AI Studio 免费层、Mistral Experiment 档），企业敏感资料须规避；
> ⑥峰谷定价已成常态，给成本建议时*必须*同时给出时段策略（如 DeepSeek 工作日 9-12/14-18 为高峰，周末全天低谷）；
> ⑦**同一模型在不同平台的峰谷定义会错开**——DeepSeek 官方/OpenCode 高峰为京时 9-12、14-18，而硅基流动 9/1 起只有每天 02:00-08:00 便宜。跨平台比价必须**先对齐时段**，否则结论相反（同一时刻官方 ¥4.5 vs 硅基流动 ¥9）；
> ⑧**调价公告页优先于定价页**：定价页常有滞后（含币种不一致），公告页是生效时间的权威口径；
> ⑨「同一套餐两套价」多因**国内版/海外版独立定价**（如 GLM Coding Plan 国内 ¥118/¥538/¥1078 vs 海外 $18/$80/$168），非汇率换算，勿互相折算；
> ⑩**积分制套餐要看乘数**：如 GLM Coding Plan 按 `(新输入×2.3 + 缓存×0.56 + 输出×8)÷10000` 扣积分，旗舰档乘数约 3 倍，选 Flash 档等于额度翻三倍；
> ⑪社区实测的**缓存命中率常低于官方估算**（GLM-Flash 实测约 80% vs 官方按 95% 估算），套餐耐用度评估要打折看。
> ⑫**免费模型清单只认官方页，聚合站数据是陈旧快照**（2026-09-02 实测）：llmpricing.dev 声称 OpenCode Zen 有 30 个 $0 免费模型，官方 Zen 文档实抓只有 6 个。核查发现聚合站列表含 `glm-4.7-free`（2026-03-15 已弃用）、`kimi-k2.5-free`（2026-08-05 已弃用）、`minimax-m2.1-free`（2026-03-15 已弃用）、`glm-5-free`（2026-05-14 已弃用）、`minimax-m2.5-free`（2026-08-05 已弃用），另有 `deepseek-v4-flash-free`/`north-mini-code-free`/`x-preview-f-free` 三个 id 在官方定价表、端点表、隐私例外表中**三处均不存在**——判定为 models.dev 历史数据全量拼接，**未随官方下架同步删除**。判别法：把聚合站的 free 清单与官方「已弃用模型表」交叉比对，命中即证伪。另：同一聚合站给出的**按量价也常滞后**（如硅基流动 V4-Flash 在 9/1 分时定价生效后仍显示旧单一价）。
> ⑬**对 ⑫ 的精确化 —— 聚合站要「分时段信任」，不能一刀切**（2026-09-04 实测）：同一聚合站 `llmpricing.dev`，对新上线模型抓得很准（Muse Spark 1.3 Contributor Free 官方 9/2 上线，聚合站当天即标记 NEW、发布日 2026-09-02、上下文 1,048,576、输出 131,072，与官方完全一致），但历史条目仍然塞满已弃用模型。结论：**聚合站的「新增」信号可用作发现线索（比官方 RSS/公告更快），但「现存清单」不可用于计数或定论** —— 线索去官方四表核验（定价表 / 端点表 / 隐私例外表 / 免费说明列表），四处互证才算确认。判别法不变：见 ⑫ 末句。
> ⑭**套餐「总额度」≠「逐模型额度」，同套餐内各模型分档**（2026-09-09 实测）：Command Code GOAT 宣传「$10→$70」是**套餐月总额**，但官方 pricing 页按模型逐项分档——GPT-5.6 Sol/GLM-5.2/Tencent Hy3/Qwen 3.8 27B 单项 $70，DS V4 Flash 单项 **$60**，Kimi K2.7 Code $60，MiniMax M3 $47，DS V4 Flash Fast $20（九/一新增，2× 订阅价起步）。用户曾把「$70 总额」记成 V4-Flash 单项，8/11 起多源时间线均 $60、从未变过。判别法：报套餐额度必查官方 pricing 页「逐模型」段落，别用宣传总额或记忆值；同款模型跨套餐还要注意（DS V4-Flash：GOAT $60 vs OpenCode Go $30）。额度会随供应谈判**动态调整**（新模型常从 2× 起步），需标注数据日期。

## 动态更新机制（本库如何演进）

**核心原则：渠道库是活资产，不是静态清单。每次任务都是给它「喂数据」的机会。**

### 任务执行中的沉淀

1. 检索中发现「好用且不在库中」的渠道 → 先记入下方「待沉淀区」（渠道名 + URL + 为什么好）
2. 任务结束汇报前，把待沉淀渠道按格式填入对应分类（三维评分 + 分级 + 适用任务）

### 新渠道入库标准（三条件至少满足一）

- ① 已在 **≥1 个真实任务**中验证过（不是听说好）
- ② 三维评分至少一项为「高」
- ③ 不是一次性临时使用（同类任务可复用的）

### 定期维护（每 N 轮或每周）

| 操作 | 说明 |
|------|------|
| 去重 | 同质渠道合并，保留评价更高者 |
| 淘汰 | 失效链接（404/被墙）、降级渠道移入 C 级或删除 |
| 补录 | 把「待沉淀区」正式入库 |
| 复盘 | 记录本轮「哪些分类最常用 / 哪些渠道实际没用上」|

### 分类演进

- 新任务类型出现 → 新增分类（如军工、能源、外贸）
- 领域任务变多 → 从「通用」拆出「领域专项」（参考本库化工/安全示例）
