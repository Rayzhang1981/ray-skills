# 高价值搜索渠道数据库（Source Database）

> 定位：ray-synth-search 的「搜索弹药库」。按任务类型分类的高质量信息渠道，每个渠道用三维评分标注。
> **本库是动态演进的**——每次执行检索任务时，发现新的高价值渠道就沉淀进对应分类，DB 随任务持续生长。

## 使用方式

1. 任务开始时，按「任务类型」查对应分类，选 **≥2 个渠道**（1 主源 + 1 交叉源）
2. 优先 **A 级**；专业领域问题用「领域专项」分类
3. 检索中如果遇到「好用但不在库中」的渠道 → 记入文末「待沉淀区」
4. 任务结束汇报前，把待沉淀渠道按格式正式入库

## 三维评分标准

| 维度 | 含义 | 高 | 中 | 低 |
|------|------|-----|-----|-----|
| **权威性** | 是否官方/专业/可溯源 | 官方机构、学术、正规媒体 | 行业协会、专业社区 | 自媒体、个人 |
| **信息广度** | 覆盖范围 | 跨领域、海量 | 领域内较全 | 单一主题 |
| **信息深度** | 内容深入程度 | 原文、全文、专业分析 | 概况、综述 | 标题、摘要 |

## 渠道分级

- **A 级（核心）**：权威性高 + 信息全 → 首选主源
- **B 级（常用）**：某单维度突出 → 交叉验证源
- **C 级（备选）**：特定场景补充 → 查漏用

> ⚠️ 实测要点（2026-09-19，AQ 3063-2025「工艺装置内储罐是否适用」核验）：
> ① **查"某标准适不适用某对象"，别只看第 1 章范围那三句话**——中国工程标准（尤其 AQ 罐区类）的适用边界**主要靠术语定义锁扣划定**，而非靠排除条款列举。AQ 3063-2025 第 1 章只排除了"石油库、石油储备库"（即厂区之外的库），**通篇未提装置内储罐**；但术语 3.5「罐组」= 布置在**一个防火堤内**的储罐、3.6「罐区」= 一个或多个罐组构成的区域 → **不设防火堤的装置内储罐在定义上就不构成"罐组/罐区"**。判据链应走四步：**范围句 → 术语锁扣 → 同族先例 → 专属条款**，四步走完才可定性。
> ② **术语"注"必须验在不在正文**：网传 AQ 3063 术语 3.6 带一句「注：装置区内的工艺储罐除外」——核验发现**起草组官方解读 PPT 的术语页并无此注**（3.6 仅为"一个或多个罐组构成的区域。[来源:GB 50160-2008,2.0.25]"），该注出自第三方深度解读材料。判据：凡"注 / 附录 / 术语速查"类内容，**必与起草组官方解读或标准正文逐一比对**；第三方补充注释方向可能对，但**不可作为合规依据引用**（本次一致性分按"矛盾封顶 ≤39"处理）。
> ③ **同族标准的排除先例＝最强旁证**：AQ 3018-2008《危险化学品储罐区作业安全通则》第 1 章明确"适用于危险化学品储罐区内的作业，**不适用于与装置一同布置的中间罐区**、加装防爆材料储罐区、覆土罐区和洞罐区"（mem.gov.cn 官网可查 PDF + 4 独立源，✅ 高置信）——证明"罐区类 AQ 标准排除装置内中间罐区"是**一贯立法口径**。
> ④ **政府站 PDF 被 WAF 拦（412）别反复重试**：甘肃省应急管理厅托管的起草组解读 PDF 连续两次 HTTP 412，其内容改由**搜索引擎快照 + 同文转载**取证，并在结论中显式标注"原文未直接取证"。412 与 403 同属"别硬怼"类，走浏览器通道或换同文源。
> ⑤ **适用范围类问题取证源优先级**：起草组官方解读（gov.cn 托管）> 标准正文全文（多平台互校）> 官方案例/法规原文（mem.gov.cn）> 商业标准站适用范围段 > 公众号解读（仅线索，须回源）。
> ⑥ **数值限值必须核「对谁说的」——通用管道限值 ≠ 常压储罐允许值**（2026-09-19，车间内工艺储罐增阻火器 MOC 核验）：条文里有个**现成的数字**极易被默认可套用，把「条文有无此要求」当成「此要求适不适用」。实证：SH/T 3413-2019 **6.2.18**「阻火器正常工况下的压降不应大于 10 kPa」管的是**一般管道**；而常压储罐设计正压仅 +2000 Pa、允许负压仅 −500 Pa ⇒ 10 kPa ＝ 设计正压的 **5 倍**、允许负压的 **20 倍**，**一条「合规」的判据反成事故许可**。正确算法：ΔP_允许 ＝ min(设计正压 − 呼出设定 − 管网背压，吸入设定 − 设计负压) 再扣堵塞裕量。判据：查任何限值前先问「这个数字管的是谁」——是管道？设备？还是罐？再核**承受方余量**（**先找分母、再算分子**）。与「引对了条文、引错了标准」同族，只是作用在**数值层**。

> ⚠️ 实测要点（2026-08-31）：
> ①**价格类问题第一原则是查官方定价页**——本次 5 个来源给出 3 套 DeepSeek 价格，只有官方文档准确；
> ②模型/套餐迭代极快，任何"历史价格"都可能已失效，交付前必须标注数据日期；
> ③订阅制套餐的"prompt 配额"常有**消耗倍数**（如高峰时段 3 倍扣配额），标称配额与实际体感差距可达 3 倍；
> ④免费层要区分「永久免费」与「限时试用额度」，只有前者可纳入长期方案；
> ⑤隐私红线：部分免费层会用数据训练模型（Google AI Studio 免费层、Mistral Experiment 档），企业敏感资料须规避；
> ⑥峰谷定价已成常态，给成本建议时*必须*同时给出时段策略（如 DeepSeek 工作日 9-12/14-18 为高峰，周末全天低谷）；
> ⑦**同一模型在不同平台的峰谷定义会错开**——DeepSeek 官方/OpenCode 高峰为京时 9-12、14-18，而硅基流动 9/1 起只有每天 02:00-08:00 便宜。跨平台比价必须**先对齐时段**，否则结论相反（同一时刻官方 ¥4.5 vs 硅基流动 ¥9）；
> ⑧**调价公告页优先于定价页**：定价页常有滞后（含币种不一致），公告页是生效时间的权威口径；
> ⑨「同一套餐两套价」多因**国内版/海外版独立定价**（如 GLM Coding Plan 国内 ¥118/¥538/¥1078 vs 海外 $18/$80/$168），非汇率换算，勿互相折算；
> ⑩**积分制套餐要看乘数**：如 GLM Coding Plan 按 `(新输入×2.3 + 缓存×0.56 + 输出×8)÷10000` 扣积分，旗舰档乘数约 3 倍，选 Flash 档等于额度翻三倍；
> ⑪社区实测的**缓存命中率常低于官方估算**（GLM-Flash 实测约 80% vs 官方按 95% 估算），套餐耐用度评估要打折看。
> ⑫**免费模型清单只认官方页，聚合站数据是陈旧快照**（2026-09-02 实测）：llmpricing.dev 声称 OpenCode Zen 有 30 个 $0 免费模型，官方 Zen 文档实抓只有 6 个。核查发现聚合站列表含 `glm-4.7-free`（2026-03-15 已弃用）、`kimi-k2.5-free`（2026-08-05 已弃用）、`minimax-m2.1-free`（2026-03-15 已弃用）、`glm-5-free`（2026-05-14 已弃用）、`minimax-m2.5-free`（2026-08-05 已弃用），另有 `deepseek-v4-flash-free`/`north-mini-code-free`/`x-preview-f-free` 三个 id 在官方定价表、端点表、隐私例外表中**三处均不存在**——判定为 models.dev 历史数据全量拼接，**未随官方下架同步删除**。判别法：把聚合站的 free 清单与官方「已弃用模型表」交叉比对，命中即证伪。另：同一聚合站给出的**按量价也常滞后**（如硅基流动 V4-Flash 在 9/1 分时定价生效后仍显示旧单一价）。
> ⑬**对 ⑫ 的精确化 —— 聚合站要「分时段信任」，不能一刀切**（2026-09-04 实测）：同一聚合站 `llmpricing.dev`，对新上线模型抓得很准（Muse Spark 1.3 Contributor Free 官方 9/2 上线，聚合站当天即标记 NEW、发布日 2026-09-02、上下文 1,048,576、输出 131,072，与官方完全一致），但历史条目仍然塞满已弃用模型。结论：**聚合站的「新增」信号可用作发现线索（比官方 RSS/公告更快），但「现存清单」不可用于计数或定论** —— 线索去官方四表核验（定价表 / 端点表 / 隐私例外表 / 免费说明列表），四处互证才算确认。判别法不变：见 ⑫ 末句。
> ⑭**套餐「总额度」≠「逐模型额度」，同套餐内各模型分档**（2026-09-09 实测）：Command Code GOAT 宣传「$10→$70」是**套餐月总额**，但官方 pricing 页按模型逐项分档——GPT-5.6 Sol/GLM-5.2/Tencent Hy3/Qwen 3.8 27B 单项 $70，DS V4 Flash 单项 **$60**，Kimi K2.7 Code $60，MiniMax M3 $47，DS V4 Flash Fast $20（九/一新增，2× 订阅价起步）。用户曾把「$70 总额」记成 V4-Flash 单项，8/11 起多源时间线均 $60、从未变过。判别法：报套餐额度必查官方 pricing 页「逐模型」段落，别用宣传总额或记忆值；同款模型跨套餐还要注意（DS V4-Flash：GOAT $60 vs OpenCode Go $30）。额度会随供应谈判**动态调整**（新模型常从 2× 起步），需标注数据日期。
> ⑮**模型换代/下线看「官方定价页脚注」，比公告和媒体都早**（2026-09-10 实测）：DeepSeek V4.1 Flash 9/10 12:00 转正当天，定价页正文价格表已换、脚注(1)(2) 同时写明「旧版 V4 Flash 与 V4 Flash Vision Exp 现已下线，旧模型名暂时路由到 V4.1 Flash」「V4 Pro 9/14 12:00 起路由至 V4.1 Flash 并按 Flash 计费」——**媒体是同一天转述，官方页脚注就是一手**。判别法：抓定价页时**必须连脚注一起读**，只看价格表会漏掉模型弃用与路由规则；弃用后旧模型名往往仍可调用（兼容路由），别误判为「模型还在」。
> ⑯**厂商发布新模型时，渠道商当天会发「限时折扣/加量」，窗口只有 1–2 周**（2026-09-10 实测）：DeepSeek V4.1 Flash 发布当天，WorkBuddy 给 0.03x 独家倍率（9/10–9/23，对比老 V4-Flash 0.17x ≈ 1/5.7）、OpenCode Go 给 V4.1 Flash 限时 4× 额度（$15→$60）、Command Code GOAT $40→$60 明示至 9/17。这类窗口**不进定价页、只在客户端模型列表/官方 X 帖/产品页角落标注**，靠抓定价页永远看不到。判别法：模型发布日必查**渠道侧**（客户端倍率表、官方 X、合作方公告），并把到期日单独建时间轴——错过窗口的成本远大于比价省下的钱。
> ⑰**比价是相对关系，一家降价会让其他渠道被动变贵**（2026-09-10 实测）：DeepSeek 官方 V4-Flash 降价后（输入 ¥1.5→¥1、缓存命中 ¥0.15→¥0.02），硅基流动的分时价一分没动，结果从「比官方贵 50%（输入）/ 3.3 倍（缓存）」变成「贵 50% / **7.5 倍**」。此前看板写死的结论「硅基流动比官方贵一倍」当场失效。判别法：任何「A 比 B 贵 X 倍」的跨渠道结论**必须带基准日期**，上游一调价就整体重算；给建议时优先用「谁在降价」而不是「谁绝对值低」。

> ⑮**套餐的「按模型额度」是动态值——报额度必须报三个值：常态 / 当前 / 有效期**（2026-09-10 实测）：Command Code GOAT 的按模型额度会因①新模型默认 **2×** 起步（$10 套餐给 $20，谈下条款后自动提升）②**限时促销**再加码（DeepSeek V4.1 Flash：$40 → **$60**，有效期至 2026-09-17，"选择该模型时自动应用"，无开关）。所以"$40"和"$60"都对，取决于问的日期——**只报一个值必然误导**。另：GOAT 的滚动窗口是**计划级**（5 小时 $14 / 每周 $35 / 每月 $70，与按模型额度**并行生效**），比价时要分开看，别把 $40 当成"5 小时能用 $40"。
> ⑯**新模型发布首日，各平台接入速度差异极大——别假设"全都有了"**（2026-09-10 实测，DeepSeek V4.1 Flash 当日 12:00 发布）：腾讯系（WorkBuddy / CodeBuddy / 腾讯云 TokenHub / ima / Marvis）**day0 全量接入 + 两周独家折扣**（官方合作伙伴）；OpenCode **day0 接入**（Go 套餐给限时额度）；Command Code GOAT **day0 接入**并给促销额度；而**硅基流动 release notes 最新条目仍停在 9/3**（只有 9/1 起的 V4-Flash 分时定价），模型广场未见新模型。判别法：**查第三方平台是否上线，看它 release notes / 模型广场的「最新条目日期」，比搜新闻可靠**——新闻只报已上线的，搜不到不等于没上、搜不到也不等于上了。
> ⑰**平台「官方定价页」也可能拿不到**：硅基流动 `cloud.siliconflow.cn/models`（含 `?tags=deepseek`）与模型广场**需登录**，WebFetch 只回落到登录页 HTML（标题「硅基流动统一登录」），拿不到模型清单与价格。该平台只能靠 **release notes 页（免登录）+ 聚合站** 交叉取证，并在结论里标注"定价页未取证"。

## 动态更新机制（本库如何演进）

**核心原则：渠道库是活资产，不是静态清单。每次任务都是给它「喂数据」的机会。**

### 任务执行中的沉淀

1. 检索中发现「好用且不在库中」的渠道 → 先记入下方「待沉淀区」（渠道名 + URL + 为什么好）
2. 任务结束汇报前，把待沉淀渠道按格式填入对应分类（三维评分 + 分级 + 适用任务）

### 新渠道入库标准（三条件至少满足一）

- ① 已在 **≥1 个真实任务**中验证过（不是听说好）
- ② 三维评分至少一项为「高」
- ③ 不是一次性临时使用（同类任务可复用的）

### 定期维护（每 N 轮或每周）

| 操作 | 说明 |
|------|------|
| 去重 | 同质渠道合并，保留评价更高者 |
| 淘汰 | 失效链接（404/被墙）、降级渠道移入 C 级或删除 |
| 补录 | 把「待沉淀区」正式入库 |
| 复盘 | 记录本轮「哪些分类最常用 / 哪些渠道实际没用上」|

### 分类演进

- 新任务类型出现 → 新增分类（如军工、能源、外贸）
- 领域任务变多 → 从「通用」拆出「领域专项」（参考本库化工/安全示例）
