# ray-translate — 化学化工翻译技能（中英双向，含过程安全）

在化学/化工/过程安全领域的中英文文档之间翻译。**领域三层定位**（v3.0.0 扩展）：

- **化学基础**（v3.0.0 新增）：元素/化合物命名、官能团、物性词汇 → `data/termbase/chem.md`
- **化学工程**（v3.0.0 新增）：设备/单元操作/管道仪表/公用工程 → `data/termbase/chem-eng.md`
- **过程安全**（既有资产全保留）：化工安全翻译全部既有能力（Excel 批量、安全培训英文化、警示语规范）+ 原 EN-GLOSSARY 129 条 → `data/termbase/safety.md`

三大方向：

- **方向一 英→中（Excel 批量）**：Excel 工作簿（含 VBA 宏的 .xlsm）批量翻译。以 CHEF Calculation Aid 4.4 翻译项目（13 个 Sheet，~2,126 个单元格，5 轮翻译）积累的最佳实践构建。
- **方向二 中→英（PPT/讲义英文化）**：安全培训 PPT / 讲义 / 讲稿的专业英文化。以 95 页化工厂入厂安全培训 PPT 英文化项目（2026-08-19）积累的方法论构建——**面向外籍化工工程师时，目标是"读起来像是用英语写的"，不是逐字对应**。
- **方向三 英→中（PDF/法规/长文 → 中文）**（v3.2.0 新增）：英文 PDF（法律/法规/指南/事故报告/技术手册）→ 中文交付（默认同格式，v3.2.1）。以 2026-09-04 OSHA Act 514（马来西亚职业安全法全文）+ HIRARC 指南实战沉淀——**结构化文档翻译 + 法律语气 + spec 驱动生成 + QA 抽读**。

**grep 用法**：

```bash

# 查 ZH→EN
grep "储罐" data/termbase/*.md
# 译后拒用译法扫描（对译文，应零命中）
grep -in "反应堆\|坦克\|检查阀\|饲料" 译文文件
```

### 动态库机制（v3.1.0）

| 动作 | 触发 | 去向 |

- **调整节奏**：攒 10 个任务或月度做一次迁移，不逐任务调（机制重了不会被执行）

- **热词表纪律**：只收无歧义词；多义词（base/charge 类）永不入表；热词只免"译前查"，译后拒用扫描照做

## CAT 三段式工作流（v3.0.0 新增）

**① 译前：术语提取与锁定**
- 从原文提取候选术语（高频名词短语/专业词），逐条 `grep` 四库
- **命中 → 锁定**：全文档强制采用库内"推荐 ZH"，不得自行另译
- **未命中 → 核验**：按裁决优先级查证后写入任务级临时术语表（原文|译文|依据）

**② 译中：只注入命中词条**
- 翻译脚本/字典只含"命中锁定项 + 新增核验项"，禁止整库灌入（token 经济 + 避免低频误替换）

**③ 译后：拒用零命中 + 逐条核对**
- `grep` 全部拒用❌译法对译文扫描 → 必须 0 命中
- 逐条核对锁定术语在译文中的实际落位（防"锁定后又被润色改掉"）

**收尾：术语审计入库 + 记台账**
- 每次任务结束，把新增/修订条目按六列 schema 回写四库（来源列标校准依据，如 `CSB 校准`/`术语在线`/`行业通用(待核)`），库随任务增长
- 往 `_hits.md` 追加一行命中台账（日期|任务|命中词条）——动态库升级/毕业的频次信号源

## 通用翻译铁律（双向，开工前先过此节）

> 源头：对比官网通用翻译 skill 的「格式化保留 + 内容规则 + 语义 QC」沉淀（2026-08-20，v2.3.0）。面向化工文档本地化。

**① Don't-translate 保留清单**（原文原样保留，绝不翻译）：
- 占位符/模板变量：`{name}`、`{{var}}`、`%s`、`$1`、`__KEY__`
- 代码/公式：代码块、HTML 标签、XML 键名、API 端点、CSS 类、文件扩展名、正则
- **sdt 元素（Word 结构化文档标签，v2.5.0 补）**：封面标题、规范性引用、文内交叉引用等 `w:sdt` 包裹的内容——翻译时**内容译、sdt 结构标签保留**；若工具自动跳过 sdt 内容，需手动补译封面/引用区（外部同类实测：sdt 处理不当会整段丢失）
- 标识符：URL、email、编号、ID、设备/仪表/管线位号、CAS 号、标准号、数字与日期（除非需做本地化换算）
- 专有名词：品牌名、机构缩写（CCPS/OSHA/API…）、人名
- 单位符号与数值：kPa、ppm、≥、≤、10⁻⁶ 等（见白名单 `KEEP_ENGLISH`）
- **化学专项（v3.0.0 扩充）**：CAS 号、分子式、R/S 构型符号、位次标点等规则 → 见 `references/chem-conventions.md`

**② 语义 QC（机械 QA 之外的补强，交付前过）**：
- [ ] 先通读全文上下文再译，别逐词硬译
- [ ] 译文在目标语中读起来自然流畅（不是"可读的 Chinglish"）
- [ ] 验证所有格式/结构元素（表格、位号、单位、层级）翻译后仍可用
- [ ] 全文档术语、语气、时态一致（同义词唯一化）

## 工作流程 — 方向一：英→中（Excel 批量翻译）

### 第一阶段：分析与准备

1. **读取源文件结构**: 使用 `openpyxl.load_workbook(path, keep_vba=True)` 打开 .xlsm，列出所有 Sheet 名称和行列数
2. **提取唯一文本**: 遍历所有 cell，提取非空、非公式、含英文字母（≥2 个）的字符串，按 Sheet 分类
3. **构建术语字典**: 将提取的文本按优先级排列——先确保以下关键字段完整：
   - 工作表名（13 个）
   - 核心标题/版权/声明
   - 章节标题（每个 Sheet 的 STEP/标题行）
   - 专业术语（单元操作、安全工程、化学危害术语）
   - 表头/列名
   - 表单字段/LOPA 字段
   - 参考文献
   - 化学名/物质名
   - 中英混合长句片段（Introduction 类段落）
4. **规划翻译轮次**: 根据术语量和文本复杂度决定轮次，典型分 3-5 轮
5. **术语评审闭环（v2.1 新增，重要交付必做）**：术语字典建成后导出 `术语评审表.xlsx`（原文|译文|备注）给用户确认，**修订版即绑定**后续所有轮次。小任务可跳过，但交付说明须注明"术语未经用户评审"。

> v3.0.0：第 3 步构建术语字典前，先过 **CAT 三段式**——候选词逐条 grep 四库，命中的直接锁定，未命中的走裁决优先级。

### 第二阶段：核心翻译

**核心翻译函数**与**残留诊断白名单**（`KEEP_ENGLISH`）完整可复用代码 → 见 `references/code-patterns.md`（按需查）。

**关键规则**:
- 公式保护：所有以 `=` 开头的单元格跳过（openpyxl 读取的公式值以 `=` 开头）
- 整词匹配：使用 `\b` 边界符避免子字符串误替换（如 "TNT Model" 中的 "T"）
- 长词优先：术语按字符串长度降序排列，避免短词抢占长词
- VBA 保护：`openpyxl.load_workbook(..., keep_vba=True)` 和后续 `wb.save()` 保留宏

**分批策略（防止内存溢出）**:
```python
BATCH_SIZE = 3  # 每批最多 3 个 Sheet
for i in range(0, len(SHEETS), BATCH_SIZE):
    batch = SHEETS[i:i + BATCH_SIZE]
    wb = openpyxl.load_workbook(out, keep_vba=True)
    for sname in batch:
        n = translate_sheet(ws, patterns)
    wb.save(out)
    time.sleep(0.5)  # 系统释放内存
```

**文件夹结构**:
- 首次运行：`shutil.copy2(src, out)` → 复制源文件（含 VBA）
- 逐批累加：每次 `load_workbook` 读入已翻译文件 → 翻译 → `save` 覆盖

### 第三阶段：多轮递进翻译

**典型轮次分配**：

| 轮次 | 术语规模 | 目标 | 策略 |
|------|---------|------|------|
| Pass 1-2 | 基础 100-200 | 表格字段、表头 | 快速覆盖高频可见文本 |
| Pass 3 | 500-800 | 全面覆盖（章节/术语/字段） | 全字典翻译，3 Sheet/批 |
| Pass 4 | 300-500 | 中英混合长句 + 化学名 | 针对长句片段和化合物名补充 |
| Pass 5 | 200-400 | 最后残留清理 | 逐 sheet 扫描残留，精确补充 |

**每轮策略**：
1. 先用 `check_remaining.py` 扫描残留英文
2. 根据残留调整术语字典，补充漏翻项
3. 运行下一轮脚本
4. 重复直到仅剩应保留的白名单项

### 第四阶段：残留验证与白名单

**残留扫描** (`check_remaining.py`):
```python
# 扫描 >=3 字母的英文单词，统计词频
```

## 工作流程 — 方向二：中→英（化工安全专业英文化）

> 2026-08-19 沉淀：95 页化工厂入厂安全培训 PPT 英文化项目。适用对象：安全培训课件 / 讲义 / 讲稿 / 技术文本，面向外籍化工工程师或国际项目。

### 核心原则：翻译的三个层次

| 层次 | 含义 | 常见失败 |
|------|------|---------|
| 字面准确 | 逐词对应 | ❌ 最容易被 AI 默认采用，产出 Chinglish |
| 术语精确 | 使用 NFPA/OSHA/API/ASME 等国际标准表达 | ❌ 术语错译导致安全语义歧义（最危险） |
| 行业地道 | 英语母语工程师读起来"像是英语写的" | ❌ 中文句式残留、全角序号、perk 类口语误用 |

**目标不是逐字对应，而是让英语母语的化工安全工程师读起来，感觉这份文件本来就是用英语写的。**

### 第一层：术语精确（安全语义无歧义）

1. **先建术语库，后翻译**——从 `data/termbase/safety.md`（原 EN-GLOSSARY 10 大类 + 过程安全新增，EN→ZH 可反查）起步，覆盖项目特有术语后开工
2. **高频错译黑名单**（termbase 拒用❌列已收录，此处强调）：

**最高危错译 Top5**（译错即安全语义歧义，交付前 `grep -i` 必查）：

| 中文 | 正确 | 错误（AI 常见） |
|------|------|----------------|
| 爆炸极限 | flammable range / explosive limits (LEL–UEL) | explosive range |
| 特别重大/重大/较大/一般事故 | Extraordinarily serious / Major / Relatively major / General | extra-large / serious（分级译反） |
| 双重预防机制 | Dual Prevention Mechanism（官方译名） | Dual Control |
| 隔绝式呼吸器 | SCBA (self-contained breathing apparatus) | self-contained respirator |
| 挂牌上锁 | LOTO (lockout/tagout) | stop, tag, lock |

完整错译黑名单（11 条：逃生面罩≠gas mask、高处安全带≠safety belt、受限空间≠limited space 等）→ 见 `data/termbase/safety.md` 各行"拒用❌"列。

3. **警示语语气规范**（法定条款强制语义）：

| 中文 | 英文 | 场景 |
|------|------|------|
| 应/必须 | shall / must | 法律强制、SOP 强制步骤 |
| 宜/建议 | should | 推荐做法 |
| 不得/严禁 | shall not / must not / is prohibited | 禁止性规定 |
| 严禁 | strictly prohibited | 最高级禁令 |

4. **不确定的术语优先查 NFPA/API/OSHA 标准用法**，不要自行发明

### 第二层：行业地道（去 Chinglish）

**句式检查清单**（翻译后逐条过）：
- [ ] 全角序号 `①②③` → ASCII `1. 2. 3.`（英文版里全角序号是明显的中文残留）
- [ ] 中文"进行/加以"式动词短语 → 英语惯用动词（make a calculation → calculate）
- [ ] 中文短句 → 按逻辑合并为英文主从结构或名词化
- [ ] 口语误用：perk（→optional）、bottom line（慎用）、make XX well（→maintain）
- [ ] 单位/阈值/连锁逻辑：数字安全关键信息**不得**在润色中被改掉

**英文比中文长 ~40%**：PPT 场景必须下调字号（标题 26→22pt、条目 15→14pt、描述 11.5→10.5pt）+ 放大行高，否则必溢出。

### 第三层：流程与验收

1. **术语库先行**：开工前建 `GLOSSARY.md`（分类表），对照翻译
2. **脚本化改造**（PPT 内容在脚本/数据文件里时）：改数据脚本（如 part1/2/3_en.py）→ 重建 → 重灌备注 → QA，比直接改 PPTX 高效
3. **讲稿/备注同步**：`## Page N` 格式按节解析重灌；**改完必须验证 `## Page` 数量 = 页数**（编辑误删行尾换行会把下一节标题吞进上一段落，95 节变 94 节）
4. **QA 双保险**：
   - 机械 QA：页数/图数/备注数/越界/中文残留/乱码（`\ufffd`）
   - **术语 QA：QA 无中文残留 ≠ 术语正确**——必须对照术语库人工/逐页审关键页（分级页、表格页、警示页）
5. **交付对比**：交付前跑 `grep -i` 扫描黑名单术语，确认 0 命中

### 方法 B：内容内嵌 PPT 的就地翻译（python-pptx，2026-08-20 沉淀）
> 适用：内容直接嵌在 PPTX（非脚本生成）的培训课件，需保留版式/图片/分组结构时，用 python-pptx 就地替换，比重建高效。

**四步法**：
1. **导出精确键**：脚本递归（group 感知）输出每段/每 cell 的 `repr(text)`（含 `\n`、`\xa0`、全角引号、箭头等不可见字符）→ **精确匹配键**。
2. **建 `T` 全量字典**：键=精确原文、值=英文；数字/位号/标准号/ACRONYM 不进字典。跑完扫残留，剩余项基本都是「键里差一个空格/换行的坑」——比对 repr 逐字修键而非猜。
3. **格式保留**：改首 run 的 text、删多余 run（保留 rPr 字体字号加粗）；单元格按 `\n` 分行、缺行 deepcopy 末段补行。⚠️ **分组 `shape_type==6` 必须递归进入**，否则漏 group 内文字。⚠️ **段落级写回铁律（v3.3.1，2026-09-08 事故回流）**：替换写入禁止"整框文本压进首 run"——含多段（编号列表/多行）的框会被压成单段+字面换行、丢段落结构（en2en 返工实证，已全量重建修复）。正确做法 = **逐 paragraph 替换**（每段独立判断，段内写首 run、清同段其余 run），段落结构天然保留；仅确认单段框可用首 run 直写。
4. **autofit 防溢出**：英文长 ~40%，按「估算每行字符宽 0.5×字号 → 折算行数 → 估算高度 > 框高则整体等比缩小字号(下限 0.55)」对文本框与表格 cell 统一收缩（用列宽/行高做框尺寸）。极端缩小就检查 map 键问题。

**验收**：中文残留=0 + `\ufffd`=0 + 页数不变 + 黑名单 0 命中；autofit report 里字号 40→26 这类属正常。

### 方法 B+：超大 PPT 的并行子代理翻译（v3.3.0，2026-09-08 沉淀）
> 适用：PPT >100 页 / >5 万中文字符时，单进程顺序翻译会超长且慢。用**并行子代理分章翻译 + 主进程统一替换**。2026-09-08 实测：148 页 / 10.7 万字符设备培训课件，2 子代理并行完成第 1 章（P5-22），产出 138 键字典，用户验收 OK。

**流程（主进程编排）**：
1. **全量导出**：脚本导出全部文本单元 → `units.json`（每项 {slide, shape_id, prefix, text, font_sizes, frame_w, frame_h}），统计单元数与字符量
2. **识别章节边界**：找目录页/章节标题页，把 148 页切成 N 章（每章 ~1 万字符最优），逐章切出 `chXX_units.json`
3. **建翻译规范**（主进程做，质量基线）：写 `translation_spec.md` = 通用栏目模板表（系统简介→System Overview 等跨页统一词）+ 本任务设备/术语锁定表 + 压缩规则。**栏目名/术语必须主进程定，子代理不得另译**——这是全书术语统一的唯一保障
4. **并行派子代理**：每章 1 子代理（或按字符量 1 代理 1-2 章），prompt 模板：①读 chXX_units.json ②读 translation_spec.md + 已完成章节 dict 作风格参照 ③产出 `chXX_dict.json`：`{"中文原文精确字符串": "英文译文"}`——**键逐字复制自输入**（含 \n），中度压缩 ④报告键数/未处理 slide。⚠️ **prompt 内嵌长度预期（v3.3.1，2026-09-08 二次全量实战）**：写明"EN/ZH 字符比 2.5~3.5x 属正常（CJK 双宽，视觉宽比约 1.3~1.8x），勿为压长度删技术/安全内容；溢出由 fix_overflow 兜底"——否则代理会误判"超长"并在报告里反复解释（ch02/05/07/09 多代理同症状）
5. **主进程合并**：各章 dict 合并 → 统一替换（子代理只产出字典，不碰 PPTX——避免并发写同一文件）
6. **就地替换**：`apply_dict.py` 模式——精确匹配 text_frame 全文→替换首 run 保留格式（多 run 清空其余）；表格 cell 同样处理；group 递归
7. **溢出缓解**：`fix_overflow.py`——英文/中文长度比 >1.4 的框按比例缩字号（下限 6pt / 0.55 比例）；原 PPT 常无 autofit 设置，此步必做
8. **QA 每批必跑**：中文残留（应逐批递减至 0）/ 乱码 / 页数不变 / 字号下限

**要点**：
- 子代理 prompt 必须自包含（看不到主会话）：输入文件路径 + 规范路径 + 风格参照 dict + 输出路径 + 键精确性要求
- 同 slide 重复文本（如导航角标）自动合并为单键（dict 天然去重）
- 已应用键匹配不到中文自然跳过 → **替换脚本可重复跑**（分批合入安全）
- 压缩度以验收样板为准——先做 1 章样板给用户确认风格，再批量（软目标先确认）

## 工作流程 — 方向三：英→中 PDF/法规/长文 → 中文（v3.2.0 新增）

> 2026-09-04 沉淀：马来西亚 OSHA Act 514 全文（81 页法条 + 5 附表 + 修订流水）+ HIRARC 指南 → 中文交付。适用：英文 PDF（法律/法规/标准指南/事故报告/技术手册）→ 中文（**默认同格式 PDF**，用户指定 Word 时出 DOCX），同目录交付培训/合规场景。本方向典型源格式为 PDF（含法规/长文），故 spec→create-docx→导出是标准链路；若源已是 DOCX 则跳过导出步直接交付。

**前置工具**：配合 `ray-doc-toolbox` 使用（PDF 提取 + create-docx 生成），本 skill 负责**翻译决策与内容质量**。

### 五步流程

1. **提取全文**：用 ray-doc-toolbox `read`/`pdf-text` 提取 PDF 文本到 txt（先 `inspect` 判断文本层/OCR 分支；扫描件用 `--pages` 关键页）。输出含分页标记时保留，用于定位。
2. **翻译并构建 spec**：
   - 先过 CAT 三段式（grep 术语库锁定命中项）
   - 全文翻译，译文按**文档结构**组织成 `*_zh_spec.json`（title + sections：heading/level/paras/table），供 create-docx 消费
   - **结构完整是硬要求**：法律全文的 PART/条/款/附表/修订清单必须全覆盖；删页决策（如广告页）须用户先确认
   - ⚠️ **spec 必须程序化构建（铁律，v3.2.3，09-06 实测）**：写 Python 脚本（dict + `json.dump(ensure_ascii=False)`）生成 spec，**禁止手写 JSON 文件**——手写必踩内容 ASCII 引号坑（如「所谓"技术服务请求"」的 `"` 提前截断 JSON 字符串报 `Expecting ',' delimiter`）；状态机自动修复会搞坏文件（曾 3 次失败）。中文内容引号一律用「」，Python 构建自动转义永不出错。构建脚本分批 append（每批落盘防上下文丢失），最后统一 `json.dump` 写盘
3. **中间生成 DOCX**：`ray-doc-toolbox create-docx --spec <spec.json> --out <同名_中文.docx>`——DOCX 是 spec 渲染的中间载体，**最终交付格式按输出默认规则还原**（见开工简报下方规则）
4. **QA 抽读验证（必做，静默失败最危险）**：生成后必须用 python-docx 抽读验证，不能只看 `ok:true`：
   - **条号/章节连续性**：正则提取标题行条号，校验 1→N 连续无重复无缺失（曾抓出 spec 残留 28 个旧草稿 section 导致条文乱序重复）
   - 表格存在性：抽查每个 section 的表格列数/行数（曾抓出表格字段名错致整表静默丢失）
   - 乱码扫描：`\ufffd` 必须 0
   - 首尾段落抽查
5. **交付格式还原（默认与原格式相同）**：
   - 源为 PDF → 用 Word COM 导出中文 PDF（`doc.ExportAsFixedFormat(out, 17)`，见 ray-doc-toolbox P-014）放入交付目录（**交付目录默认 = 源文件同一文件夹**，v3.3.2 规则；用户指定目录时以用户为准）；**中间 DOCX 留在临时工作目录，不放进交付目录**（除非用户明确要 DOCX）
   - 源为 DOCX → 直接交付中文 DOCX
   - 用户明确指定格式（如"转成 Word"）→ 按指定格式交付

### 法律/法规文书翻译纪律（方向三特有）

| 项 | 规则 |
|----|------|
| shall | 应/须（法律强制语气） |
| so far as is practicable | 在合理可行范围内 |
| 罚则金额/监禁/日期/机构缩写 | 原样保留（ringgit/林吉特、DOSH/PTW/PPE 等不译） |
| 修订脚注 `*NOTE—Previously "X"–see Act A1648` | 保留不删（标注历史沿革） |
| 已删除条文（Deleted by Act X） | 照译并标注"（已删除）"，不跳过 |
| 定义条款的引号词 | `"certificate of fitness"` → "合格证明书"（引号词+译文） |
| 附表引用 `〔第 X 条〕` | 保留结构引用 |
| 生效日期/版本说明 | 文首加"版本与法律地位说明"段（依据/免责/生效日） |

### 插图回插子流程（v3.3.3，2026-09-09 沉淀）

> 方向三延伸场景：译文以「图 X.Y（原图略）：图题」占位后，把原版插图插回交付 PDF。CHEF Manual 189 页 / 71 图全量实战（四步 + QA）。

1. **探针定界**：fitz **真题注块检测**（短文本块以 `Figure X.Y` 开头；勿用首次提及——正文交叉引用会误判页码）。区域上界 = max(同页上一题注底, 上一正文块底)+4；下界 = 题注上沿-1；**题注在页顶（y<110）→ 图在上一页底部**（跨页情形）。
2. **提取**：内容框 = 栅格+矢量+短文本块并集（含图内标签；排除宽>380 且长>100 的正文块）。单一栅格占内容框 ≥70% → `extract_image` 原生字节（无损）；否则 220dpi 区域渲染。
3. **插入**：python-docx 定位占位段，`insert_paragraph_before` 插图（居中）+ 题注去「原图略」（改写保首 run 格式）。**width 与 height 必须同时给**——fitz 写的 PNG pHYs=0，只给 width 会让 python-docx 读 DPI 除零崩溃。
4. **QA**：插图计数 + U+FFFD=0 + 5 张多模态对位抽查 + **译者说明页同步改写**（勿漏）。

**特殊情形裁决**（探查→方案→用户批准后动手）：原书重号图（两处各自插图+译者注）；正文复用同图（双插或「参见图 X.Y」）；无编号图（同源去重→「参见图 X.Y」）；源书仅文字提及无图（保留原状）；表格型图（渲染为图 or 人工转录真表格，用户定）。

**两坑**：①题注与横轴标签合并成一个文本块 → 下沿钉题注上沿会切标签（下沿=区域下沿即可）；②题注块压在栅格 bbox 上（含行距空白）→ 下沿外扩到栅格底+2 且不超过题注字形上沿。

- 输入 **Excel 工作簿** → 方向一；输入 **PPT/讲义中译英** → 方向二；输入 **PDF/法规/长文（英译中）** → 方向三

| 5 | 公式被替换成文本 | 公式单元格被当文本翻译 | `=` 开头单元格直接跳过 |
| 6 | 保存时 WinError 5 / 文件锁（高频，08-20 实测） | 输出文件被 Office/WPS/预览打开（`~$xxx` 锁文件） | 先存 `OUT+".new"` 再 `os.replace`；被锁则版本化文件名交付；提醒用户先关旧文件 |
| 7 | **生成类命令静默失败**（v3.2.0 补，09-04 实测） | spec 字段名错（如 `columns` 应为 `headers`）/ 残留旧草稿 → create-docx 输出 ok 但内容残缺（表格空/条文乱序）零报错 | **QA 抽读与生成成对**：生成后必抽读验证（条号连续性/表格存在/乱码/首尾段），不能只看 `ok:true`；spec 字段名先查 schema 文档勿凭印象 |
| 8 | **手写 spec JSON 引号截断**（v3.2.3 补，09-06 实测） | 内容混入 ASCII `"`（如「所谓"技术服务请求"」）提前截断 JSON 字符串 → `Expecting ',' delimiter` | **spec 一律 Python 程序化构建**（dict + json.dump 自动转义）；中文引号用「」；禁止手写 JSON、禁止状态机自动修复（会搞坏文件） |

## 提速与 Token 优化策略（五招速查）

| 招式 | 做法 | 效果 |
|------|------|------|
| 单脚本全量 | 全部术语（700-1500 条）写入单一脚本 RAW_TERMS 字典，每轮只改字典+参数 | 避免多轮 AI 交互 |
| 诊断驱动 | 先 `check_remaining.py` 扫残留 → 只生成补翻译典，用数据说话 | 不猜覆盖度 |
| 白名单过滤 | 单位/缩写/变量名预置白名单（50+ 高频项） | 免重复判断 |
| 渐进构建 | 首轮只提 100-200 条核心术语，按残留增量补 | 防 token 爆炸 |
| 模板复用 | translate_batch.py 框架只换 RAW_TERMS 和路径 | 零成本重建 |

## 遗留注意事项

- **正常保留项**：含英文的单元格多数属正常保留（单位符号、专业缩写、公式变量、场景保留词）——残留报告需人工判读，非数字越小越好
- **性能**: 3-5 轮翻译受文件大小和分批数影响，大工作簿预期 10-15 分钟量级
- **兼容性**: 翻译后文件直接在 Excel/WPS 中打开，中英文混排显示正常
- **边界**: 纯数值、空白、公式单元格不变——三类合计通常占文件 60-70%
- **中→英方向**: 面向外籍员工的培训材料，宁可"术语精确但句式简单"，不要"句式华丽但术语模糊"——安全文档语义优先
- **PPT 英文版**: 英文比中文长 ~40%，必须下调字号 + 放大行高；图片若无文字（灰度/写实风格）可零成本复用，语言中立
- **术语库纪律（v3.1.0）**: 库文件 grep-only 永不整读；命中即锁定不得另译；收尾必做术语审计入库+命中台账；热词表只收无歧义词（上限 80）；毕业=移 `_graduated.md` 永不删除；备查池数据集仅作候选永不直接采用（旧译名慎用）
