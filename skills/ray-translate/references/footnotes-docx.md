# 真 Word 脚注实现规程（v4.4.0 新增）

> 适用：译文需要**真脚注**（引用上标 + 注文落所在页底部 + 横线分隔）的场景。`ray-doc-toolbox create-docx` 的 spec 通道**没有脚注能力**——spec 里写 `<sup>N</sup>` 只会渲染成普通上标文字，注文会混进正文流。本规程是 spec 通道之外的补齐路线：直接操作 DOCX 的 `word/footnotes.xml`。
> 机制参考外部整本书翻译流水线的实战沉淀，脚本须按本规程自行实现，不直接搬运第三方代码。

> 🔗 **分工指针**：脚注的 **OOXML 外科实现细节与守恒断言**（refs==defs==range、zip 级后处理落盘、id 冲突）→ `ray-file-inplace/references/adapters-docx.md`「真脚注 OOXML 外科」节；本规程管语言侧（源文标记识别 / 编号对拍 / 已有 DOCX 改造）。

## 1. 实现骨架

python-docx 不原生支持脚注，须手工操作 OOXML：

1. **`word/footnotes.xml` 必含两个分隔符脚注**：`w:id="-1"`（continuation separator）与 `w:id="0"`（continuation notice）。**漏了这两个，Word 打开报「文件可能已损坏」**。
2. 每条真脚注 = `<w:footnote w:id="N">`（N ≥ 1，**全文唯一，禁止重复 id**——重复同样触发「文件可能已损坏」）。
3. 正文引用点 = 上标 run 内插 `<w:footnoteReference w:id="N"/>`。**标题、表格单元格里的引用也必须走 runs 注入通道**（不能只处理正文段落）。
4. 脚注定义行（行首 `<sup>N</sup> ` 形式）从正文流**摘出**，只进 footnotes.xml——不要留在正文里排版。

## 2. 三个致命坑（全是实测）

| # | 坑 | 后果 | 防法 |
|---|----|------|------|
| 1 | 重复 `w:footnoteReference w:id` 或漏 id=-1/0 | Word 报「文件可能已损坏」 | 每次引用唯一 id；footnotes.xml 必含 -1/0 |
| 2 | 引用写成 Unicode 上标字符 ¹²³⁴ 而非 `<sup>` 标签 | 两套口径并存时，**两处检查器结论打架**（一处认、一处不认→「有定义无引用」假阳性） | 全文统一标签形式；质检正则只认标签 |
| 3 | 引用只注入正文段，标题/表格内漏注入 | 该处引用丢失，闭合检查报「有定义无引用」 | add_runs 类函数统一处理所有 run 通道 |

## 3. 源文侧脚注对齐（交付前必做：双向闭合检查）

- **一次性把源文脚注定义全量抓出**（按源文页脚逐页抄全）——源文 37 条只抄 30 条这类漏抄，靠「源文脚注编号序列 vs 译文引用序列」对拍抓出。
- **源文脚注编号并非总是连续**：以源文页脚为准，勿假设 1..N 连续。
- **逗号合并写法必须拆**：源文 `¹˒²` / "1,2" 合并引用要拆成两个独立引用。
- **一个源编号被引用两次 = 多余**：删多余引用。
- **闭合判据**：引用集合 == 定义集合（两个方向的差集都为空）。任一方向非空 → 交付前必须归因清零。

## 4. 交付前 docx 侧自检

- 解包 DOCX：`word/footnotes.xml` 引用数 == 定义数；
- 抽 2-3 条用 Word 打开目视：注文落在**引用所在页**的页底（不是文末）；
- 脚注区有横线分隔（separator 生效的旁证）。

## 5. 已有 DOCX 无脚注时怎么改造

译文已成 DOCX 但脚注是普通段落时：读入 docx → 识别正文中的脚注标记段（上标数字/标记行）→ 从正文流摘出定义 → 注入 footnotes.xml + 在原位置插入引用 run → 重存后按 §4 自检。
